01 / The approach

An interface.
Not another model.

The research question: what can move below the model boundary? Keep semantic decisions with the model. Give bounded execution, observation, and verification a local home.

01 — REUSE

Ground. Then reuse.

Explore turning an initial visual understanding into reusable targets and methods, instead of describing the same interaction from scratch.

02 — REACT

Keep feedback local.

Use bounded observe–act–verify loops for steps the runtime can check. Return to the model when a fresh decision is needed.

03 — REVALIDATE

Check before continuing.

Revalidate the state an action depends on. Refuse stale targets and escalate ambiguity rather than treating an old plan as current evidence.

Design principles with scoped experimental evidence, not a claim of general GUI automation or guaranteed safety.

04 / Before you start

A preview.
With clear edges.

Start with the source and the documented scope. A research artifact is not the same thing as a production-ready product.

What is available today?

The public research repository, experiment code, and retained evidence. Start with the repository README for the current entry points. This page does not yet offer a packaged installer or playable demo.

Which environments are covered?

Current real-app evidence is Linux/X11. Broader operating-system support and general GUI reliability are not established by this preview. Check each experiment's documented environment before attempting reproduction.

Is this a model or a hosted service?

Neither. Agent Interface researches the execution layer between a model and computer I/O. Model access and local setup are separate; this website does not execute agents or collect API keys.

What is still experimental?

Generalization, installation, and real-time gameplay remain active work. Do not assume production safety, human-level operating speed, a MAP01 clear, or a general cost reduction. Consult the research record for the scope of individual results.
