# WSLc Calc: visible target effect after input-owner deadline

Two fresh WSLc allocations used LibreOffice Calc on private Xvfb, a known blank FODS, fixed reviewed A2 point [81,168], main-equivalent runtime 901e9bb5ab69393a4bece7d86e4fa7ea826cd1a6, pinned image, one CPU, 1 GiB, no network and a 45-second outer timeout. A research-specific supervised worker recorded custody, grabbed the X server, checked the Calc window chain, issued a button pair and synchronized it before an 800 ms deadline, then stalled. An existing prestarted supervisor retired the worker at the deadline and returned UNKNOWN. This worker directly used XTEST, bypassing the public guarded-dispatch path; no model call or production integration is claimed.

- A01 running-Calc control: by the time the supervisor returned UNKNOWN, the name-box crop had changed from the reviewed A1 digest to the A2 image; a later capture matched it. The predeclared constrained OCR read A2 for both later images, though it read only `A` for the initial A1 crop.
- A02 stopped-Calc case: the harness checked the window's `_NET_WM_PID`, executable and owned process group, SIGSTOPed that Calc process, and confirmed `/proc` state T. The X server synchronized the original button pair before the deadline. After owner retirement, while Calc was still stopped, the captured name-box crop exactly matched the initial A1 digest. The harness then SIGCONTed Calc; the next capture changed to the same A2 crop seen in A01 and constrained OCR read A2. The effect appeared after the supervisor returned; no second input request or replay caused it. The original document file remained unchanged.

An aggregate audit verifies image artifact/crop hashes, OCR crop association, window chain, process ID and stop/resume timing, server sync before deadline, owner UNKNOWN/retirement, before/mid/after capture ordering, neutral button state and observation beyond the worker's scheduled later marker. The marker did not appear. Both OCR inputs and raw outputs are retained; OCR's initial `A` misread is not hidden, and the A2 reading is supported by the earlier known-layout visual inspection, not a general classifier. Frozen inputs and 305 runtime hashes matched; both containers were absent and ZIP integrity passed.

This is one controlled schedule per arm. It demonstrates real Calc can visibly process already-delivered input after the input owner has timed out and retired. It does not establish when the X server queued the events internally, general task-effect reconciliation, arbitrary app behavior, a successful operation receipt, crash durability or MAP01 completion. UNKNOWN and no blind replay remain necessary.
