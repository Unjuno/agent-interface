# Atomic Job membership and owner death: R590

One Windows no-GUI/no-model trial used `PROC_THREAD_ATTRIBUTE_JOB_LIST` to create a suspended Python child already associated with a private kill-on-close Job. The owner confirmed membership and reported PID plus creation FILETIME. The auditor verified the retained child process HANDLE against that FILETIME, observed WAIT_TIMEOUT before termination, terminated only its own owner subprocess, and then observed the child HANDLE signaled without fallback termination. The auditor did not hold or duplicate the Job HANDLE. Conditions, exact source bytes, raw results, empty stdout/stderr and hashes are retained in raw.zip.

A separate reviewer matched source hashes, nonce and owner identity, the pre/post wait results, code order, process HANDLE close and absence of fallback. The total recorded host interval was 0.125 s. The Windows monotonic clock returned the same timestamp for owner termination and child observation, so no fine-grained termination latency can be inferred. The auditor recorded a boolean creation-time match but did not retain its own raw FILETIME as a separate field. Exit code 0 is not task success.

This is one direct child killed before resume, not a descendant, real model host, reader/pipe, all parent-death boundaries, nested Job compatibility, GUI, input release, WSLc cleanup or reliability proof. The prototype is single-thread only; it lacks pipe support and durable independent custody, and must not yet be used to launch the model. Failure paths, handle closure and late operation fences remain to be validated.
