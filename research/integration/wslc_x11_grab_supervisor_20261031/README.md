# Isolated WSLc Xvfb: prestarted supervisor and X server grab custody

Three fresh isolated WSLc allocations used main-equivalent runtime be326cf3305183fb15bbfcd5b18593489d3c1361, the pinned image, private synthetic Xvfb, one CPU, 1 GiB, no network and a 30-second outer timeout. A test-specific worker used an X server grab and a held button; existing `PrestartedCancellationSupervisor` instances were started before the worker action, one to supervise the worker and one running the existing `x11_cancel_worker`. The test worker wrote its session, PID, X resource base, binding revision and held-button custody before pressing. This is a research composition, not production integration.

- A01: the worker pressed and then stalled with a later scripted action at two seconds. The 800 ms operation deadline caused the owner supervisor to retire it, returning UNKNOWN / transaction_deadline. The independent cleanup worker observed the owner connection disconnected and returned a verified release readback; its overall `cleanup_status` remained UNKNOWN and `release_confirmed` remained false by contract. The isolated observer saw button down before cleanup, up after cleanup, and only one press/release pair after the scheduled late time passed. No late artifact appeared.
- A02: the owner generation supplied to cleanup intentionally had a wrong PID. Cleanup returned UNKNOWN / invalid_cleanup_request without release; the button remained down. The isolated harness then performed an explicit fallback release and verified neutral state. This fallback is a test cleanup, not the production worker.
- A03: with a four-second owner deadline, the worker's two-second delayed operation did run, and the target saw two press/release pairs. Its minimal test worker omitted receipt identity fields, so the supervisor correctly returned UNKNOWN / stale_or_mismatched_receipt despite the visible events; this does not establish a successful production receipt.

An independent aggregate audit checks prestarted process identities, deadline retirement, disconnect and release readbacks, mismatched-identity refusal, fallback, event order and observation beyond the scheduled late time. Thirteen existing cancellation-supervisor tests passed locally. Frozen trial inputs and 305 runtime hashes matched; containers were absent and ZIP integrity passed. The test verifies a bounded controlled schedule with a responsive private X server, not all late-event queues, an unresponsive X server, host crash, real Calc input, arbitrary held keys, or a general atomic grab implementation. `UNKNOWN` is deliberately preserved; readback is not promoted into a general task or release guarantee.
