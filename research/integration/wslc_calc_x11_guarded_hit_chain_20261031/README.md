# WSLc Calc: X11 child-chain check inside an input guard

Four fresh WSLc allocations used the known blank Calc fixture, fixed reviewed A1 coordinate, main-equivalent runtime 0e201cccadac2ffeb84b8f4275dce67b72664361, pinned Calc image, one CPU, 1 GiB, no network and a 60-second timeout. No model calls. The research caller placed the exploratory X11 child-chain check from #9860 in the existing synchronous `input_guard` callback for one frozen click. It checked before admission, focus, move and press. This is caller-side research code, not a runtime-integrated hit guard.

- A01, unobstructed: all four checks admitted, the click completed and the compiled graph reached TASK_SUCCEEDED. A separate FODS audit verified exact A1=731, A2=864 and the graph's saved-file hash c9f0081f4a9d8ed02d5005352f1e31e900a83d1337ab690cf6da314c03b48b56. Releases and neutral input were verified.
- A02: the test inserted an InputOnly overlay inside the callback at `before_press`, after the admission, focus and move checks had passed. The reported X11 child chain then excluded the target and the callback refused. The click returned execution_failed after one emission (pointer movement), with verified release; the runtime describes the failed operation's effect as unknown. Exit 1 was the expected stop.
- A03 repeated A02 in a fresh allocation with the injected overlay selecting button press/release events. It received none; the click again failed at operation 2 with one earlier emission and verified release. The close state had no keys or buttons down.
- A04 was a deliberately unsafe isolated positive control: the callback recorded the same target-excluding chain but returned True. The click completed and the test overlay received button-1 press and release, proving that this event observer could receive the events in that controlled setup. The runner then deliberately stopped without continuing the Calc task. Input release and neutral state were verified.

The independent aggregate audit checks stages, decisions, reported emissions, releases and the observed empty versus press/release event streams. All frozen inputs and 305 runtime hashes matched; the four containers were absent and ZIP integrity passed. The callback is synchronous and its X11 queries are not bounded here; the hierarchy check is not atomic with the subsequent press, so a window change after the callback remains a race. X11 shapes, other window managers, external clients, non-X11 platforms and general model-driven tasks remain unverified. The trial does not promote a production runtime guard, certify absence of every possible side effect, or claim generic computer-control completion.
