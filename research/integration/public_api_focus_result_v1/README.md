## H / T / D / C / U

**H.** The public Python path
`dispatch_golden_v3 -> api.dispatch -> selector -> X11RuntimeSession ->
core admission -> X11Backend` keeps native program completion distinct from
application task success, and stale source/binding/lease conditions fail before
input.

**T.** Six fixed conditions x two fresh Tk applications = 12 formal cases in two
fixed batches. Positive A-entry input, wrong-field B input, no Entry text effect,
stale observation, stale binding, and expired lease. Public read-only observation
was taken before and after every case. No formal reruns, replacement rows, or
post-freeze source changes.

**D.** Retained decision: `PASS_PUBLIC_API_EFFECT_SEPARATION_SCOPED`.
Native completed 6/12, but only 2/12 independently scored the requested A=`7`,
B-empty application state. The default golden-v3 view promoted zero unscored
completions to task success. Stale observation, stale binding, and expired lease
were refused with zero task input in all six negative cases. Raw-only audit has
zero errors and frozen corruption controls reject.

**C.** The application scorer is cooperative fixture evidence supplied after the
raw dispatch. It is not a generic runtime scorer. The public Python API was
exercised; CLI argument handling, MCP transport, a model/provider, and the
six-task matched efficiency allocation were not.

**U.** Finite directed Linux/X11/Tk evidence only. No natural failure probability,
token saving, latency benefit, broad GUI reliability, product readiness, or
integrated #57/#2789 acceptance claim.
