# WSLc Calc: exploratory X11 point-to-window child chain

Three fresh WSLc allocations used the known blank Calc fixture, a fixed reviewed A1 point, main-equivalent runtime 99d535acc6259c8bf096509937348aea7f2d61a6, the pinned Calc image, one CPU, 1 GiB, no network and a 60-second timeout. No model call. A research-only caller queried X11 TranslateCoords from the root down through mapped children at the point, bounded to 64 levels, and required the Calc target window to occur in that reported chain before mint or input. This follows the stationary obstruction counterexample #9859.

- A01, no overlay: the reported chain included the Calc target. The guarded click and graph completed, and an independent FODS audit matched the graph verifier's saved-file hash 91b1fcb215acdc943370ca1a83af0e42540f449662ac0e5b54924c4f2d8cae4b and exact A1=731, A2=864. Releases and neutral input were verified.
- A02, visible 8x8 InputOutput overlay: the reported chain ended in a different window and the caller stopped before mint or dispatch, exit 1. No owner input program was present; close found neutral keys/buttons and made no release attempt because there had been no input.
- A03, 8x8 InputOnly overlay: the reported chain again did not contain the Calc target and the caller stopped before mint or dispatch, exit 1. An independent image audit verified that the entire RGB capture before and after creating the overlay was identical, as well as no owner program or mint and neutral input. Therefore pixel equality alone could not reveal this particular input interception.

All frozen input hashes and 305 runtime hashes matched; the three containers were absent and ZIP integrity passed. The X11 chain was recorded by the research caller; it is not yet an integrated runtime guard. Its read is not atomic with later input: a stacking, geometry, shape or window-generation change after inspection remains a race. The test does not establish correctness for all X11 shapes, compositor behavior, transients, other platforms, untrusted clients, or model-driven tasks. Negative process exit is the expected refusal, not task completion.
