# Capture-bound OCR preview gate for a reviewed dialog

`research/live_control/reviewed_preview_gate_v1.py` composes the existing explicit-value OCR cue and `ReviewedModalGuard`. It checks a fresh, retained capture against caller-reviewed static regions, runs OCR on two caller-reviewed preview crops, revalidates the same capture and association after OCR, and arms a guard over the static and current preview regions only for a matching cue. Mismatch returns `wrong`; malformed, stale, replaced, expired or failed evidence returns `unknown`. The gate is single-use and neither discovers a dialog, reviews a template, mints an alias nor dispatches input.

The OCR runner receives a timeout bounded by the remaining capture age, gate deadline and one second per crop. The standard `subprocess.run` honors that timeout; a custom runner is trusted and could fail to do so. The gate returns hashes and call metadata rather than raw OCR; callers needing a full audit must retain raw output separately. A successful cue checks only the specified crops and expected decimal strings; it does not prove semantic identity outside those regions or a saved-workbook effect.

Two preregistered WSLc Calc runs used this exact module after the guarded paste had yielded with entry pending. In f17, deliberately expecting 330/517 while the preview read 329/517 returned `wrong`: no confirmation or Save occurred, the saved file stayed blank and release was neutral. In f18, matching expected values armed the guard; a separately owned guarded click completed, fresh cell OCR confirmed 329/517, and a separate guarded Save produced an independently parsed FODS with exactly those two values. The original paste was not replayed. No model was used.

The module's eight unit tests and 59 related cue/guard/compiled-bridge tests pass locally in normal and optimized Python. They cover low-confidence/malformed OCR, timeout, static mismatch, observation replacement and expiry during OCR, mismatch, single-use behavior and changed preview at the later guard. Run `python research/integration/wslc_reviewed_preview_gate_20261031/audit.py` with Pillow to verify the retained raw packet, capture and OCR hashes, guard/action/release receipts, independent saved FODS and cleanup. Candidate archive bytes are hash-checked exactly; comparison with checkout source normalizes CRLF. Source/image and external dependencies are not fully reproduced.

The live trials used one fixed layout, two known values, a previously reviewed static template and a fixed execution order. They do not establish general dialog recognition, arbitrary OCR reliability, external concurrency safety or product-wide completion. Target discovery, review, clipboard ownership and recovery orchestration remain experimental harness code. Issue 57 remains open.
