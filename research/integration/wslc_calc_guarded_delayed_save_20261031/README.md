# WSLc Calc: structured guarded save and delayed target effect

Two fresh WSLc allocations used LibreOffice Calc on private Xvfb, known blank FODS, main-equivalent runtime 2adcef200e28e1b586e7a40fea255d6614a7ae28, pinned image, one CPU, 1 GiB, no network and a 45-second outer timeout. The existing guarded keyboard path first entered 731 and 864, with verified release and a reviewed fixed-layout filled-cell cue; the disk file still matched the blank baseline. A separately prestarted, supervised research worker then used `GuardedSessionOwner.invoke_guarded` for observe, mint and keyboard Ctrl+S, recording the structured handler receipts. This directly exercises the guarded owner handler, not the MCP transport or a complete production orchestration. No model call was made.

In both arms the guarded input handler returned completed with verified input release and `task_success: null`; the test worker deliberately stalled after recording that local receipt. Its outer supervisor retired it at 800 ms and returned UNKNOWN / transaction_deadline. No second save was sent.

- A01 running-Calc control: the file snapshot at owner retirement already contained exactly A1=731 and A2=864.
- A02 stopped-Calc case: the harness verified the Calc process identity and owned process group, SIGSTOPed it, and confirmed state T before the guarded save. At owner retirement the file still matched the blank baseline. After SIGCONT the file changed; a separately written XML audit found exactly A1=731 and A2=864. Thus the effect of an already-completed guarded input became visible after the caller's outer result was UNKNOWN, without replay.

The aggregate audit checks guarded observe/mint association, exactly one worker input program, its completed/release receipt and null task success, outer UNKNOWN/retirement, entry release, focus ancestry, process stop/resume and timestamps, baseline/mid/after hashes and XML values, neutral Ctrl/S and mouse states, and observation beyond the worker's scheduled later marker. The marker did not appear. Frozen inputs and 305 runtime hashes matched; both containers were absent and ZIP integrity passed. Each arm is one controlled observation. File snapshots do not prove crash durability or target queue drainage. The experiment does not establish public MCP transport behavior, a general reconciliation protocol, model efficiency, arbitrary applications or MAP01 completion; UNKNOWN must not trigger blind replay.
