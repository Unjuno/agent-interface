Construction notes: The first new-case run exposed a test expectation error: raw_refs correctly included request bytes, late-usage receipt, and the independent score state (3), while the test initially expected only 2. The assertion was corrected to require all three custody references; behavior code did not change for this correction.

The first public-MCP suite import attempt failed because the sparse worktree did not include runtime dependencies. No test body ran. The worktree was expanded to include the suite's runtime modules, then the entire 17-test suite was rerun successfully in normal and optimized modes. These are setup failures, not product failures.

ASTORA read-only review found that a single-receipt implementation would lose a final value if a partial snapshot arrived first. The implementation was revised to retain chronological cumulative snapshots, reject regressing or disappearing counters, and aggregate only the latest snapshot on the original attempt. A follow-up review identified Python bool/float equality with integer indexes; exact integer validation and journal-mutation tests were added. All three affected suites were rerun on the revised source.
