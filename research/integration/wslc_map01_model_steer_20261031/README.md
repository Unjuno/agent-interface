# MAP01: model-proposed target and one bounded steering action

Two predeclared fixed-order WSLc allocations, seeded identically, run guarded movement, interrupted input, release, review, stale-alias rejection and one live full-screen `gpt-6.1-sol low` decision. Both independently proposed target `(655, 527)` in the 1280x1024 desktop image. The game window was `[320, 272, 640, 480]`; the target is 15 px right of its horizontal center. A fresh pixel gate revalidates the model's 8x8 target patch. The wait control emits no steering input. The steering arm maps a horizontal offset above 5 px to one guarded 50 ms right key pulse, with pixel checks before admission, focus, and key press. It does not fire. Game-internal labels and angle are only sampled by the scorer and never passed to the controller.

The three columns of scorer position are before, immediate, and after a 0.5 s coast. Both owner releases were verified, tested keys were up and both model hosts closed. Ammo stayed 50 and kills stayed 0; neither arm attempted a shot. Guard-stage target-patch differences in the steering arm were 21.48 on a threshold of 32, not exact matches. One independent model call took 3.474 s in control and 3.515 s in steering; each reported 12,450 input tokens, with 68 and 58 output tokens respectively. These are measured call durations and token usage, not a speed comparison with a baseline.

The result demonstrates one local reduction in scorer-reported horizontal offset under this setup. It is one fixed-order pair, with separate model calls and a single nearby, initially visible enemy. It does not establish general aiming accuracy, meaningful success rate, target identity under movement, model awareness of the effect, or MAP01 completion. The model does not see a post-turn image in this run; screenshots and game-state labels were retained for offline scoring only. An 8x8 patch guard and a center heuristic do not establish semantic target identity. The action ran after an earlier cancellation that could have produced partial effects.

The runtime snapshot, runner, host and adapter were frozen into a hash manifest before either allocation and mounted read-only; the manifest and source files are retained in `public.zip`. Image digest, image-to-response binding, target patch differences, admission checks, release, scorer records and host closure can be checked with `python audit.py` (Pillow required). Source immutability across these allocations was rechecked after the runs. The manifest does not pin the external model service, host OS, installed host Python dependencies or Codex executable version. The local source snapshot is not asserted to equal the recorded main reference. Private session/call artifacts remain local; their hashes are retained separately.

A useful next step is a preregistered multi-seed, randomized left/right/center and moving-target study with no-turn controls and fresh post-action visual decisions. If that succeeds, combine bounded re-observation with a separate task-effect comparison; avoid treating a reduced pixel error or released key as proof of a hit.
