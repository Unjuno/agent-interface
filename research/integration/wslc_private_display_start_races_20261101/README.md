# Private display draft: startup-close and expiry checks

The initial [#10088](https://github.com/Unjuno/agent-interface/pull/10088) draft permitted `close()` during an in-progress startup to return before the process was created; startup could subsequently publish a live display. A test that blocked the first authority setup reproduced this before the change. A second test blocked the final authority setup until after the startup deadline; the original draft still returned a display, and that test also failed before the fix. Those two pre-fix failures were observed in the local test output; this archive retains the post-fix runs, not their original console output.

The draft now tracks a closed/starting state under a lock, refuses a new spawn or publication after close, signals the owned process if close occurs after spawn, and checks the deadline again immediately before publication. Two new tests exercise close before spawn and after spawn; the latter confirms the worker ultimately reaps the child. Another test delays authority setup beyond the deadline and verifies no session is published and the child is retired. These are controlled pauses, not exhaustive scheduling proofs.

Five tests passed in each of two fresh WSLc containers, normal Python and `-O`, with pinned image `sha256:6150a4f3c779a51b3ac6a7d93bc1d0450803325efb7ab38ade8b1aaf79c33e25`, one CPU, 1 GiB memory limit, no network and no pull. WSLc reported swap was not limited. [raw.zip](raw.zip), SHA-256 `cdd508126201d6194abc4b12eb536cd5b6318a43a91ed495f2c44d3ed7dfe0a7`, retains exact candidate/test files, hashes and both test outputs.

The draft is not integrated with cancellation or MCP. In particular, `close()` during startup requests termination but may return before the startup worker finishes reaping; startup error cleanup itself can still wait without a hard bound. Concurrent retirement, failure injection at other process and fd boundaries, resource exhaustion, cookie lifecycle, same-user threats, and broader test suites remain unverified. The earlier held-key composition used the prior module revision and must not be silently attributed to this revision. No old physical release, end-to-end recovery, MAP01 completion or hard deadline is established.
