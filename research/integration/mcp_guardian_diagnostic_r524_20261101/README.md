# Diagnostic explicit guardian commit: r524

One preregistered fixed-order four-arm synthetic trial passed its scoped checks. Each arm used in-process MCP on a private Xvfb with real guarded owner and supervisor, an independent guardian ready before held input, target KeyPress(a) and keymap-down, and a cancellation deliberately stalled before the real owner cancellation method. The original action and cancellation remained pending. A test-specific prepared record included the call ID, gate token, operation ID, owner generation and pidfd PIDs, deadline, and a checksum-validated shared snapshot containing key `a`. Parent and guardian exchanged an explicit COMMIT only after the parent verified the prepared-record digest.

The valid arm recorded matching prepared bytes/digests and guardian plus independent pidfds observed owner and supervisor exit. A mismatched owner PID was rejected and the guardian reported no signal. A simulated pre-write stall caused parent timeout without COMMIT and no record or receipt at observation. In the late-ack arm, parent timed out without sending COMMIT, guardian subsequently sent the prepared acknowledgement while the socket was still open, and guardian's receipt recorded `connection_reset`, `uncommitted`, and `signal_sent=false`. Independent liveness was sampled after parent exit before fixture cleanup. Acquired pidfds were observed exited during cleanup. The no-signal claim comes from guardian's own receipt, not an independent signal trace.

The preceding r523 trial ended ERROR without a guardian receipt; r524's observed reset supports the diagnostic hypothesis for this new sample but does not establish r523's actual cause. Independent review found another unresolved ambiguity: the fixture marks `commit_sent` only after `sendall` returns. A timeout or exception during that call may leave the guardian having received COMMIT while the parent reports it unsent. From the moment sending is attempted, the outcome must be UNKNOWN until independently resolved. Timeout after COMMIT but before its final acknowledgement is likewise untested. The late-ack test does not explicitly assert the receipt token against the parent token, although this sample's values match. The prepared file was fsynced and directory-fsynced according to the fixture code, but neither power-loss durability nor authenticated peer identity is proven. The stall is a sleep before writing, not a real blocked filesystem syscall. Old input release, queued-request drainage and task outcome remain UNKNOWN; no replay is authorized.
