# R563: fake launch permission gate and positive control

Two preregistered independent forced-order trials on WSL Ubuntu Python 3.12.3, no GUI/input/network. In the death arm, the parent was killed and reaped before the supervisor spawned a child; the child waited on an authorization pipe, supervisor observed parent EOF, and the child observed EOF and exited without writing the fake-effect marker. In the control arm, the parent sent a grant and the same fake child wrote the marker. Both returned 0, with child and supervisor pidfd exit observed and no emergency cleanup events. Unique run IDs and exclusive directories were used. Conditions, script, raw output, IDs and event logs are archived; the second arm's event log is in `control-events.zip` because both source files have the same basename. Pre-run script SHA-256 `9b96757bf440d547398aca8e4f8440706b92580e60cb5eb4a5a6364f684608e7`.

This does not establish safety after a grant was queued or forwarded just before parent death: the child may act later. The event log is fixture-reported, PID-to-pidfd identity is not independently bound, and supervisor exit status was not independently collected. The child is a fake marker writer, not the existing owner; there is no public MCP path, real input, release/readback, WSLc, MAP01, finite-recovery guarantee or reliability claim. This is a research candidate, not a production patch.
