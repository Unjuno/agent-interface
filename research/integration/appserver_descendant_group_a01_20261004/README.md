# App-server descendant retirement: process-group A01

This construction-only experiment compares two teardown scopes around the exact `CodexAppServerClient.close(timeout)` implementation. Source is `research/live_control/codex_app_server_client_v2.py`, fetched at main `4d42238694c55aaa29bf47cb13a5b8d4c5d4074a`, Git blob `85f7f5129920e2fb3bceeefaabf99cc1cf1483b3`, SHA-256 `243d3c0b242a34317b5cc6234df2f323322271e670c7f38a3b25a35e0b13c768`.

The baseline used the current `Popen` launch and exact `close(timeout=.20)`: parent exit was `-15`, but its inherited-pipe grandchild remained in state `S`, the reader remained alive, and close raised `TimeoutError: app-server reader close timed out`. The runner then SIGTERM'd only its own recorded grandchild and confirmed reader termination. The comparison arm created an isolated new session and changed only the test process's `terminate()` primitive to `killpg(SIGTERM)`; the same exact `close()` method returned without error in about 1.1 ms, with the reader ended and the direct child and grandchild gone/reaped. Full timing and PIDs are in `RESULT.json`; raw output and cleanup are retained.

This CPU-local helper is deliberately very small (one direct child and one 30-second grandchild per arm). An independent saved-output audit passes. This result supports the process-group retirement mechanism in this WSL/Linux fixture. It does not implement the change in the repository or prove that production Codex launches always own a complete process group, that descendants do not escape it, or that cross-platform signal behavior, app-server protocol, GUI effects, task correctness, physical key release, or economic benefit are solved. Existing PR #7237 / successor #7254 retain source ownership; this packet is an additive mechanism experiment only.

Environment note: this Windows host has Ubuntu WSL with Python 3.12.3. `wslc.exe` is not available, and the Docker Desktop Linux engine was not running, so this two-process OS construction probe used the existing WSL distribution without downloading images, using GPU, or starting a service.
