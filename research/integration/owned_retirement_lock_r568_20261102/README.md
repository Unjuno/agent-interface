# R568: nonblocking retirement lock candidate rejected

A gated fake process on the base allowed two concurrent retirement callers to enter terminate; the first assertion expected one call and observed two. A draft nonblocking lock prevented double entry in the scoped test, but the test does not force the second caller to run before the first is released, so its pass alone is weak. An existing 49-test suite run on the candidate had three errors in tests constructing owners with `object.__new__`, because the new lock was not initialized; the same three errors and the fake test are retained in raw.zip together with exact candidate diff and conditions. This is an exploratory fake-process study, not a real input/release claim.

Independent Astra review identified stronger correctness failures: the pending result can be cached as a final failed cleanup by prestarted cancellation; an existing caller can overwrite a later confirmed retirement record with pending; the lock ends before disconnect/release cleanup and does not prevent duplicate release; exceptions and waiters lack a persistent shared transaction. Fixing the three fixture errors alone would not solve these issues. The candidate and insufficient test were discarded. A replacement must distinguish pending from final UNKNOWN, preserve a single cleanup transaction and receipt, and test forced overlap, exceptions and late completions. Parent-death and real X queue/release remain out of scope.
