# Stopped-display recovery: fixed-order two-arm trial

Two preregistered synthetic trials used the same private display fixture, source parent `1b3f3e4276e33da4ea5a2680109c7bb96d8ea362`, image `agent-interface-xvfb-mcp:late-input-r19` (`sha256:bd191d30ea94871a1d3ca717252cd07a276e8ef7d1bcb4a130b63935ce075425`) and seven-second cancellation deadline. The fixed-order first arm reserved no retirement time; the second reserved two seconds. Each had its own disposable, network-disabled container limited to one CPU and 1 GiB. No model or physical input was used.

In both arms the old target observed `a` down and an independent keymap check confirmed it before the owned Xvfb was stopped and `/proc` showed state T. The zero-reserve arm returned after 7011.134 ms with `deadline_after_cancel`, fresh display forbidden and no fresh target started; the fixture classified it INCONCLUSIVE and retired the old display during subsequent cleanup. The reserve arm returned after 5009.255 ms with old guarded owner and display retired, permitted a fresh display, and observed fresh target count 0→1, press and release, key-up and verified fresh close; the fixture classified it PASS. Both old release and task success remain UNKNOWN, and the old actions returned EOF. The `replay_allowed` receipt is not an independent observation of replay or queued requests.

Both arms' explicit cleanup checks passed: the old action thread stopped, old owner and display retired, old target exited, and no cleanup exceptions occurred; in the reserve arm the fresh display and target were also retired and fresh guard close verified. The old guard's cleanup receipt remains UNKNOWN: retirement of the display does not establish that the old input was released or its queued operations drained.

The raw archive includes conditions, hashes, fixture, output, logs and exit codes. This is one fixed-order pair, so it establishes neither a general success rate nor a causal or latency distribution. It is a manual failure injection on the direct Python path, not automatic expiry, MCP, a real application task, MAP01, a hard deadline guarantee, or a real-time performance benchmark. In particular, elapsed times in these two samples do not measure performance against a general baseline.
