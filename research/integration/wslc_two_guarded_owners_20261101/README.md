# Overlapping guarded X11 owners and cleanup

Three single-attempt private WSLc/Xvfb experiments use the exact local runtime candidate archived in the adjacent `wslc_retired_owner_recovery_generation_20261101/runtime-source.zip`. Frozen manifests, test scripts, conditions, raw receipts and target events are retained. `python -B verify.py` checks source and script hashes and principal results. Local absolute-path command records are omitted; each frozen runner documents its command template. These are direct owned-guarded-session API experiments, not two MCP transports or production desktops.

* r144 interposes a simulated new X client just before the normal cancellation release method. The old automatic release clears the newer same-key hold. That ordering is forced.
* r146 uses two real spawned guarded owners on the same private display: while owner one holds `a`, owner two observes, mints and completes `c`; its own verified release does not mean the first owner's `a` is up.
* r147 combines two real owners and the normal automatic cancellation path. A fixture clears old `a`, then the second guarded owner holds `a`; cancelling the first releases the second hold. Both old actions and closes remain UNKNOWN, with no replay.

The ordering and X sync delays are injected, target is synthetic and each condition ran once. These observations do not establish spontaneous frequency, a public MCP admission path, MAP01 behavior, physical input release or a general queue-drained fence. They do show that PID-qualified old-client disconnect and successful readback do not establish same-display cross-owner isolation. See each RESULTS.md for exact scope.

`verify.py` checks the frozen source and trial scripts against their manifests and selected receipt fields; it is not a checksum of every raw output or a fresh experiment. The original per-trial `audit.py` files are preserved as historical inputs, but assume the original local directory layout and cannot be run directly from this archive. The runners likewise expect an extracted `src/` beside each trial and the exact pinned local image; reconstruct that layout from the adjacent source zip and each conditions file before attempting a new allocation. The image digest identifies the tested image, but availability or provenance of an equivalent image is not established here. A later execution must use a new allocation and be reported separately.
