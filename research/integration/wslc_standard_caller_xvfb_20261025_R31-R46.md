# WSLc standard-caller R31–R45 — bounded-release transaction boundary

R31–R36 stopped before input while resolving the private-Xvfb/container setup. R37–R41 passed the unchanged public standard caller at 3,500–3,800 ms pauses, with supervisor release/readback margins from 377.305 down to 72.300 ms; each reached independent all-up checks, the late-event horizon, and both synthetic task oracles. R42 at 3,900 ms exceeded the 4 s transaction deadline by 4.988 ms and remained UNKNOWN. Near the edge, R43 passed at 3,850 ms with 27.552 ms margin, R44 failed at 3,875 ms by 0.466 ms, R45 passed at 3,860 ms with 20.877 ms margin, and an independent same-condition R46 passed with 18.848 ms margin. R45/R46 repeat the full scoped result with similar timing, but the near-deadline samples do not establish a safe timeout threshold or broad reliability.

R43–R46 used distinct pre-registered attempt IDs, the same pinned source commit `e4e34a163e1f288d8841d300ae719abcf9e58223`, digest-pinned Ubuntu, network-disabled containers, and isolated outputs. Each exact container and Xvfb process was removed. Raw outputs and per-attempt audits are retained beside each result. R46 replicated R45's 3,860 ms condition: release margin was 18.848 ms versus 20.877 ms, and independent parent readback arrived at +4,108.282 ms versus +4,104.230 ms. Supervisor release receipts are separate from runtime cancellation custody: for all passes runtime custody remains UNKNOWN, `release_confirmed=false`, replay denied, and `task_success=null`. Failure cases stop before independent release readback and task oracles; teardown is not evidence of input release. R46's initial 24/27 auditor result and additive predicate correction are preserved in its audit-correction record; the experiment was not repeated.

These are synthetic-Xvfb standard-caller results on the user-authorized PC only. They do not establish Win32 desktop or MAP01 behavior, real-application task transfer, model/provider use, matched efficiency, or broad reliability. The next discriminating work should move to an independently justified boundary condition or a real supported-app effect path; do not repeat a consumed allocation or claim a safe timeout threshold from these samples alone.
