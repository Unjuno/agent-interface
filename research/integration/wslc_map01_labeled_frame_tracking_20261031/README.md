# WSLc MAP01 labeled-frame tracking pilot

This pilot builds a small reproducible frame-and-label benchmark for the ambiguity exposed by the recovery experiments. It captures 20 RGB `GameState.screen_buffer` frames and their labels from the same ViZDoom state object after a development-selected MAP01 route. The game engine's object ID and bounding box are evaluation-only after initialization; these are not the X11 screenshots consumed by the live runtime. The initial point is the center of the largest initially visible `Zombieman` label, so the pilot assumes an oracle-provided initial target rather than testing model grounding.

Two frozen offline candidate functions receive only the first RGB frame, the current RGB frame and that one initial point. `fixed` keeps the original point only while the 8×8 RGB mean absolute difference is at most 32. `wide` searches a 48×96 source template over `dx ±48`, `dy ±32` in two-pixel steps using spatial stride three; it rejects a boundary result, score above 32 or distinct-runner-up margin below 4, and also requires the shifted 8×8 patch to differ by at most 32. These thresholds and the template are exploratory, not calibrated safety rules. The scorer then checks whether each returned point lies inside the same object ID's game-reported box, another enemy box, neither, or an ambiguous/unlabeled case; a refused candidate is `abstained`.

| Allocation | Condition | Outcome |
|---|---|---|
| aa01 | 20 frames without the additional turn | both candidates returned a point inside the same ID's box in 20/20 frames |
| aa02 | planned 80 ms view turn | alias contained a prohibited hyphen; stopped before the turn after five partial frames. Container exit was zero but the result records an error. |
| aa03 | corrected alias; one guarded 80 ms left turn between frames 4 and 5 | fixed: 5 inside / 15 abstained; wide: 20 inside |

In aa03, the selected ID 14 box moved from x=303 to x=333 after the turn; its width was 26 and then 25 pixels. The wide candidate moved from x=316 to x=346, inside the same game-reported box, while the fixed candidate abstained for the following 15 frames. The game engine reported health and kill deltas of zero. All recorded navigation and the additional turn had verified neutral input releases; successful runs also recorded empty final keymaps. The failed aa02 owner-close release was verified, but it has no final keymap readback.

This is a positive **controlled camera-shift** example and an initial benchmark, not 20 independent trials or proof of robust target identity, safe attack, task completion or lower latency. The target remained visible and no alternative enemy, disappearance, occlusion or adversarial lookalike was exercised. aa01 and aa03 have differing initial positions and were run sequentially; aa03 was designed after observing that aa01's target barely moved. The game engine provides both frames and scoring labels, so the oracle is not an independent physical sensor. The source image and labels are a privileged dataset collection path, not evidence that the X11/model interface sees or can act on the same state atomically. Earlier `wslc_map01_recovery_large_patch_probe_20261031` demonstrated that a wide match alone can be fooled by a small local occlusion; this pilot's extra local-patch check does not qualify the combined method against all such cases.

Each isolated WSLc attempt used network none, private Xvfb, one CPU and 1 GiB, a 30 s watchdog, Freedoom2 MAP01 skill 1 seed 991031 at 35 tics/s, and image `sha256:6150a4f3c779a51b3ac6a7d93bc1d0450803325efb7ab38ade8b1aaf79c33e25`. The read-only Python runtime subset matched the earlier fixed-patch probe; intervening main changes were research only. The specifically named containers exited and were removed. ZIPs retain frozen runners, scorer, conditions, frames, labels, input and release receipts, error and partial images. `python audit.py` (NumPy and Pillow, normal Python mode) verifies hashes and releases, reruns the scorer, reconstructs the box shift and counts, and mutates later-frame labels to confirm candidate points are unchanged while scores change. That mutation checks data separation, not semantic correctness. Further benchmarks need independently varied seeds, actual movement and other targets, disappearance/occlusion/lookalike controls, timing and live guarded-action validation.
