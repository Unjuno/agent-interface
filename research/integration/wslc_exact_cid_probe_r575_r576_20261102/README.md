# WSLc exact-CID probes R575/R576

Two distinct preregistered no-model/no-GUI/no-input trials used WSLc 3.0.3, a pinned local Calc image, network none, unique name/label and `--rm`. R575 observed the CID file while it was still empty, exited UNKNOWN, and killed the WSLc client after a bounded wait. The full CID appeared later; subsequent exact-ID listing was empty, but identity was never matched while the container was running and cleanup remains UNKNOWN. This failed attempt is preserved; it is not replaced by R576.

R576 changed CID handling to wait for 64 hex characters. Its inspect matched the full CID, unique run label and container name while running. The ID-filtered running list contained one matching 12-character CID prefix and label; the WSLc client later exited 0 and the same ID-filtered list returned empty with exit 0. The separate `r576/audit.py` in the archive checks these retained records and their order. This supports the observed single-run normal-exit behavior, not general cleanup: the probe itself checks list exit codes but does not validate list content, and a nonmatching-ID or decoy control was not run, so filter selectivity is unproven. An independent review reached the same limitations.

`raw-redacted.zip` retains conditions, scripts, events, raw WSLc stdout/stderr bytes, exit codes, and a redacted command for each attempt. Only the local CID-file path is replaced; each original command's SHA-256 is in its redacted JSON and the original remains local. `SHA256.json` hashes the archive entries. No model, application GUI, user input or task scoring occurred. WSLc's memory warning says swap is not limited. No bounded full-lifecycle guarantee, force-cleanup guarantee, release, speed, reliability, or MAP01 result follows. Future drivers must handle client exit with surviving containers, partial CID writes, label/identity mismatch, per-operation and overall deadlines, raw diagnostics, and exact-ID cleanup independently of client state.
