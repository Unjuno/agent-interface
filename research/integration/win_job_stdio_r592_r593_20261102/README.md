# Windows Job standard streams: R592 and R593

The experimental atomic Job process now supports stdin/stdout/stderr using both JOB_LIST and HANDLE_LIST, with only the three child pipe ends explicitly inheritable. It remains a single-thread research prototype, not a Popen-compatible production model host. Tests cover small roundtrip output, an invalid executable, a known injected failure before FD ownership transfer, and an injected failure before raw FD close; close uncertainty is retained rather than blindly retrying a numeric descriptor.

R592's EOF test was invalid: its reader marked completion even on an exception. The raw run is retained, but its passing status does not prove EOF and does not establish that the defect occurred. R593 corrected the test: the worker exits normally while its grandchild still holds stdout; the reader must still be running, then Job close must produce normal EOF with no reader exception, followed by reader join and stream closure. Five tests passed in both normal and optimized Python. Independent review matched source hashes and output.

This does not independently verify the grandchild process HANDLE, parent death while stdio is active, model or app-server communication, large-output backpressure, FD ownership transfer interrupted between Python operations, concurrent unrestricted handle inheritance, closing a stream while another thread is reading, WSLc, input release or general recovery. `run.py` timeout only stops the test process and is not independent custody for uncertain handles. No test timeout occurred in R593.
