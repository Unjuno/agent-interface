# R560: fake launch custody after parent death

One preregistered forced-order experiment ran in WSL Ubuntu Python 3.12.3, directly on the host distro, not WSLc. No GUI, input or network was used. Controller P spawned a separate supervisor S, S spawned a sleeping child C, and S was gated before checking the parent's liveness pipe. After P was killed, the controller observed C still alive while S was gated. Once released, S observed pipe EOF and terminated and reaped C; the controller observed C absent. Exit 0; timestamps, exact script, pre-run conditions and raw event log are in `raw.zip`. Script SHA-256 before invocation: `430739524f9c0e63ce9e32cf967e5479d269d1f4d2aed9461958f105cc063c7e`.

This is one synthetic ordering, not integration into agent-interface. It shows eventual cleanup only after the supervisor resumes, and explicitly demonstrates the live-child interval while the supervisor is paused. It does not prove recovery if S permanently stalls or dies, PID acquisition races, bounded operation admission, release/readback, real application effects, WSLc, MAP01, or reliability. The fixture used owned pidfds for emergency cleanup; controller cleanup of S was not separately audited as a recovery outcome. No safety property should be inferred from the PASS_SCOPED label beyond the events recorded.
