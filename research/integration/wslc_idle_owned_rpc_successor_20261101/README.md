The runner and preflighted separate X target are byte-identical to that trial; the runtime candidate changed. The private Xvfb ran with one CPU, 1 GiB, no container network, and no model.

The old spawned owner captured once, then the test stopped Xvfb and observed state `T` with the owner RPC lock held. The 500 ms idle capture returned unavailable about **0.115 ms after its deadline**. The parent reported failed/review-required, and closed the old child while the server was stopped with no automatic release and cleanup `UNKNOWN`. After server resume, a separate new owner performed a guarded `a` action. The independent target process recorded one `a` press/release and value `a`; the action and fresh owner reported verified release, and final keyboard/button readback was neutral. The target and Xvfb exited zero.

No cancellation was injected in this cell. It therefore checks the successor's stopped-observation and fresh-task path, **not** the newly changed in-flight cancellation ordering. The old operation was read-only; no key was held across the stop. One timing observation, with process and lock states recorded by the test itself, does not establish hard deadline guarantees, physical cleanup of prior held input, MAP01, or general reliability. The unmerged draft still needs cancellation/close concurrency and real-X qualification.
