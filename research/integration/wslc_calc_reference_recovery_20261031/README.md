# Calc: one bounded Save after reconciling an unknown entry effect

This research-only continuation composes the stale-reference `SAFE_YIELD` from PR #9982 with a **new**, separately guarded Save. It never replays the original entry. After the compiled method yields with `enter` pending, the caller takes a fresh observation, checks the same target association and compares both cell crops against a separately prepared, pre-reviewed known-answer reference. Only a `filled` match permits one newly minted Save reference and one guarded Ctrl+S. The original compiled receipt remains `SAFE_YIELD`, `task_success=null` and replay forbidden; it is not relabeled as a successful compiled method.

Two independently identified WSLc/Calc trials used the same frozen code, blank document, stale initial reference, fixed geometry, model and resource limits. Their only frozen input difference was the recovery reference. The order was stale-reference control first, matching-reference condition second:

| Trial | Fresh reference result | New Save | Independently read saved FODS | Result |
|---|---|---|---|---|
| d05: stale control | unknown | none | byte-identical original blank | correctly stopped; task incomplete |
| d06: known 329/517 reference | filled | one guarded Save | exactly A1=329, A2=517 | separate saved effect verified |

Both original methods executed only the entry transition, yielded `effect_unavailable`, denied replay and verified entry release. In d05 no recovery Save reference or Save record exists. In d06 a new observation followed the prior method observation, exactly one recovery Save reference was minted, the Save's recorded guards were VALID, and its release was verified. A separate XML audit found exactly the intended two populated direct cells in the saved file. Both owners closed with empty verified releases, independent key/button readback was neutral, both processes exited 0, and both named containers were absent. The independent audit recomputes the two pixel-crop comparisons from the retained fresh screenshots and checks their association to capture hashes.

This is one fixed-order positive/negative pair on a synthetic known-answer fixture. The matching reference had to be prepared in advance from a separate prepopulated Calc document, so this does not solve arbitrary value recognition, prove rollback of unsaved edits, establish general recovery or shared-display safety, or demonstrate MAP01. It is an **experimental caller in the retained runner**, not a new production runtime API. Each trial used one `gpt-6.1-sol` low call (12,194 input and 78 output tokens; cached input 0); no schema preflight was performed and reference-preparation/setup costs are outside those counts. Provider cost is unknown. Issue 57 remains open.

`public.zip` retains both frozen inputs and runners, original and recovery observations, screenshots, model call records, guarded execution and Save receipts, saved FODS, release and cleanup results. Private model protocol journals are hash-indexed in its manifest. `python audit.py` checks the packet and the two prior reference packets, verifies the single changed input, distinct call IDs, original yield/no replay, fresh pixel comparison, at most one recorded new Save, independent saved bytes and neutral release. The source snapshot and image bytes are omitted; their hashes and post-run verification summary are retained.
