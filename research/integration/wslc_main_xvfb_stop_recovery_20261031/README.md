# Current-main private Xvfb stop and fresh-target recovery

On Docker Desktop's WSL-backed engine, a CPU-limited, network-isolated container ran the current-main standard MCP caller's private-Xvfb server-stop integration (`runtime.cli_v1.test_mcp_xvfb_server_stop_integration`). This is a synthetic X11 application, not MAP01, a provider-driven run, or a performance benchmark. The container used two CPUs, a 2 GiB memory limit, a 256-process limit and no network; its source was mounted read-only. The fixed source commit, archive digest, image digest, runner and results are retained in `public.zip`; `python audit.py` verifies the packet and key observations.

The first attempt, b01, exited 127 before the test because the image had `python3` but not `python`. It is retained as a failed setup attempt. The separate b02 allocation changed the runner to `python3` after dependency preflight, with the same source snapshot and test; it ran once. The Docker process exited 0 and all five unittest cases passed. Passing these assertions does **not** mean the interrupted original task succeeded:

- While the owned X server was stopped, cancellation returned in 0.254 s (predeclared bound 3 s), reported release unconfirmed and prohibited replay. Its terminal cleanup remained `UNKNOWN`.
- After server resume, the independent observer still saw `a` held through the observation horizon. The original synthetic-task oracle therefore reported **FAIL**, even though the expected initial application effect appeared. The old task was not replayed.
- A separate fresh target and fresh operation recovered within the test's measured 0.661 s (bound 5 s). Its independent oracle observed the expected effect and both monitored keys up through the horizon: **PASS for that fresh-target task**. Final test cleanup also observed both keys up. This does not turn the original task into a success or demonstrate release was confirmed while the server was stopped.

The test includes an 8.5 s no-late-press horizon and uses an independent parent X client to read back effects and keys. It observes two named keys and a synthetic effect, with a controlled Xvfb stop; it does not prove arbitrary input release or application recovery. The source archive contains only runtime modules and required research helpers; the full commit SHA identifies the repository tree, while the source archive SHA identifies the actual mounted subset. Image and source bytes are not included in this compact packet. Other host dependencies and scheduling were not frozen. No statistical claim follows from one completed run.

`public.zip` contains both conditions and runners, launcher status, stdout/stderr, Xvfb log, the full b02 receipt, and a per-file SHA-256 manifest. Both uniquely named containers were observed exited; no running container with their prefix remained. No input was sent to the user's desktop.
