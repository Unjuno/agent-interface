# WSLc detached exact-CID and filter control, R577

One preregistered WSLc 3.0.3 trial started a uniquely named/labeled detached, no-network container from pinned image `sha256:6150a4f3c779a51b3ac6a7d93bc1d0450803325efb7ab38ade8b1aaf79c33e25`; the only container process slept, with no GUI, model, input or task. After the launch client exited 0, inspect reported the matching full CID, label and name with `Running=true`. While it ran, an exact-ID filter returned one matching full CID and label; changing one hex digit returned no rows. The script then stopped the identity-confirmed exact CID; stop returned 0 and the same CID, and an exact-ID post-list returned empty with exit 0. A separate auditor and independent Astra review checked the raw events and outputs. This is one normal detached-stop ordering.

The negative filter did not re-inspect the target at that exact instant; the interval and bounded 60-second sleep support only a scoped observation. `stop_confirmed` in the raw result means the stop command returned 0, not that absence was independently established; the post-list is separate. Startup timeout before identity, client crash, filtered-list transport errors, fallback cleanup, hard total deadlines, release of input, real application effect, efficiency, MAP01 and reliability remain untested. Raw inspect output can contain sensitive values in other runs and should not be published without review.

`raw-redacted.zip` retains preregistration, source, independent audit, timestamps and raw command output. Only the local CID-file path in the launch command was replaced; its original SHA-256 is recorded in that redacted command, with the original retained locally. `SHA256.json` hashes all archive entries. WSLc reported that the memory limit excludes swap.
