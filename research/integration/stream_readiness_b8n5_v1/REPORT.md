## 1. 観測結果

共通の開始点から読取処理が戻るまでの中央値、単位ms。各セル3回。
「期限内フレーム」は3回分の合計で、左がFD_THEN_BUFFERED、右がEXPLICIT_BUFFER。
分母は実行ケース数とは異なる。期限200 ms、candidate戻りの許容上限250 ms。
最初のbytesとreader初期化は時間原点より前に完了している。

| 条件 | select→buffered readline | 明示的buffer＋nonblocking read | 期限内フレーム数 |
|---|---:|---:|---:|
| 単一の完全通知 | 0.159 | 0.150 | 3 / 3 |
| 2通知を1回で送信 | 200.274 | 0.156 | 3 / 6 |
| 3通知を1回で送信 | 200.276 | 0.168 | 3 / 9 |
| 2通知を60 ms離して送信 | 60.239 | 60.229 | 6 / 6 |
| UTF-8途中で分割、60 msで完結 | 60.244 | 60.249 | 3 / 3 |
| UTF-8途中で分割、340 msで完結 | 340.257 | 200.271 | 0 / 0 |
| 改行なしで80 msにEOF | 80.190 | 80.202 | 0 / 0 |
| データなし、420 msまで開放 | 200.308 | 200.302 | 0 / 0 |

同時2通知の比較経路は200.272–200.293 ms、候補は0.154–0.158 msで戻った。
同時3通知は比較経路200.273–200.307 ms、候補0.148–0.216 ms。
これらの約200 ms差は、意図的な待機予算を無駄に消費した差であり、
自然なネットワーク分布や製品全体の速度改善を測ったものではない。

### 完全通知がbuffer内にあってもfdは読取可能とは限らない

6ケースで比較経路は最初の1通知のみ期限内に返し、残る計9通知を返さなかった。
単一のraw readが送信済み全bytesを読み込み済みであること、最後のselectは
readable=falseであることを別々に確認した。その後の診断readlineは新しい
raw readを行わず、writerのEOFより前に残る完全通知を取り出した。
したがって、この差はwriterが未送信だったことやパイプでのデータ喪失ではない。
期限内に返らなかった通知は、診断で回収した遅延通知として保持した。

### fdが読取可能でも、1行が完成しているとは限らない

部分通知の末尾が340 msで届く3ケースでは、比較経路のreadlineが
340.254–340.261 msまで戻らず、200 ms予算を約140 ms超えた。
候補は200.263–200.272 msで未完了として戻り、UTF-8文字途中のprefixを保持した。
後続の診断読取で残りを収集できたが、これは元の期限内成功には数えていない。
両経路は共通の検証後deadline判定を持ち、比較経路の遅い行もON_TIMEにはしていない。

### 保全された正例と不確実性

単一通知、別々に送信する2通知、期限内に完結する分割通知は両経路で正しい。
改行なしのEOFはEOF_INCOMPLETE、開いたままデータなしはBUDGET_EXHAUSTED。
EOF、不完全フレーム、今は読めない状態を混同しない。
全48ケースで、診断終了までの全受信bytesは送信bytesと完全一致した。
成功した読取や診断は、task成功、最新世界状態、ACK、input/retry authorityを意味しない。

## 6. 統合判断と未解決点

採用候補は、OSのfd可用性とフレーム可用性を分け、未消費bytesの所有者を
一つにすること。今回の候補実装はその一例であり、全I/Oを低水準化する提案ではない。
非blockingな読取、完全フレーム判定、deadline確認、後続読取の状態保存を
同じ契約で検証する必要がある。公開runtimeへの自動採用はしない。

関連3分野: OS I/Oのbuffer所有権、分散処理の通知とACKの分離、リアルタイム制御の
観測期限と判断期限の分離。これらの転用性能自体は今回実測していない。
