# Primary caller Calc partial-input recovery

One scripted, zero-model trial exercised the current Node primary caller through the real relay and MCP against LibreOffice Calc in a private Docker Xvfb. The task was to save numeric `731` in A1. A test-only owner factory injected an exception after the first key-down was submitted and caused the first automatic release to fail. The original receipt reports `execution_failed` and `recovery_required=true`; independent X keymap readback shows a held key. The same stopped primary explicitly requested release recovery and the receipt and X readback showed neutral input. It then closed.

A distinct primary and server observed the same Calc window. The owner checked the A1 name box and OCR of the original formula-bar image read `7`; it registered a fresh reference and entered only `31`, then Enter and Save. The saved FODS independently parses as numeric A1 `731`, with no formula. The second input receipt reports verified release and the final X keymap and button mask were neutral. No earlier text was replayed.

The first server used a test-only wrapper around the real relay/MCP implementation and the existing one-shot fault factory; the second used the ordinary source relay and server. `trial.zip` preserves registration, runner, wrappers, original responses and images, OCR crop, document, condition and result; SHA-256 `8bd49b8596f2708eb728bafd4d8072b19be26ad48137936ca020a6fa1b86f964`. `runtime-source.zip` retains the exact 394 registered runtime files; SHA-256 `41071cdd8ae599ec306b0eb73ff2febe66bc8f3f958ae648e99d2291d1d7250a`. The trial seal SHA-256 is `622048a6d130cd9c41ade0b108322ab0ef49d5798df058c5305456d3551c2423`.

`python audit.py` checks both archives, the seal and registration, runtime and host hashes, session identities, receipts, original image hashes, retained OCR record, continuation text and saved document. `audit_ocr.py` independently reproduces the crop from the retained original screenshot and reruns Tesseract; it requires Pillow and Tesseract. The six host modules were compared by Git blob with main `3cc8b8b2b005320476e733778502fd776c8c25d7`; 65 runtime source files were compared against earlier main `25424677be9ca1e0949bee1d1f56f74cc522f2c5`. The runtime source is a registered synthetic snapshot, not a release build or proof every file matches current main.

The container had no network, one CPU, 1 GiB memory, a read-only root and a private X server. This is one familiar task and one controlled failure point; OCR is fixture-specific. It does not show arbitrary process-crash recovery, model-driven behavior, WSLc/native Windows, statistical reliability or speedup. The earlier input's effect was determined by the subsequent observation, not by the release receipt.
