# r04 — atomic admission against action completion

r04 follows r03 and moves call-state validation, duplicate lookup and new
cancellation-operation admission into one `calls_lock` critical section. This
prevents an action from finishing between the active-call check and creation
of its cancellation record. It retains r03's controlled `KeyboardInterrupt`
case and receipt binding checks.

The focused MCP owned-process/guarded suites passed 77/77 in normal and
optimized Python. `SHA256SUMS` binds the exact current source, docs, conditions
and captured output. The real X11, physical-release, full transaction deadline,
prestarted-helper, task-effect, WSLc, MAP01, efficiency and reliability gaps
remain open.
