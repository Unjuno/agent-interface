# WSLc MAP01: model-guided reviewed recovery refused by aim gate

Two preregistered episodes used `gpt-6.1-sol` (requested low) for three calls in one session. A model-selected capped fire was cancelled on either natural or injected patch change; its partial effect remained unknown and its input release was independently verified. After the action and monitor ended, a read-only review of the same focused window established a new scope. A third model call received the review's fresh image. The candidate then re-observed and evaluated a recovery gate before any new action.

Both third calls chose fire, but the selected targets were 48 and 68 pixels horizontally from the 640-pixel window center, outside this experiment's 40-pixel aim gate. Other checked conditions passed: image difference was 15.536 and 21.458 against the 32 threshold, and the window binding matched. Both recovery actions were refused before dispatch. Terminal cleanup independently confirmed neutral keys and buttons. These are **not successful model-guided recovery actions**. The fixed aim gate exists because this fixture fires with a keyboard key and does not aim toward an off-center target; simply widening it would not establish an accurate shot. A follow-up needs a grounded turning or aiming action and fresh verification, or a reasoned alternate task.

The third calls used 15,867 and 15,866 input tokens (including 13,824 cached input each), and 31 and 30 output tokens respectively. This pair is not an efficiency comparison, general safety result, semantic detection result or MAP01 completion. The candidate snapshot is not asserted identical to main.
