A fresh WSLc allocation k01 tests a partial-task boundary on the fixed 731/864 Calc workflow. It retains the earlier temporary stale-target intervention and one fresh model re-grounding; after the compiled entry keyboard program returns completed with verified release, the harness places an X overlay over the reviewed context region before the next observation. The harness removes this overlay only after the compiled method returns. This is an injected test condition, not autonomous recovery.

The compiled receipt records one completed `enter` transition and yields `SAFE_YIELD / effect_unavailable`, with the entry effect still pending because the changed context prevents its predicate from being accepted. Exactly one entry execution and two total owner programs (initial click and entry) were retained; there is no Save chord and no replay. A post-yield screen matches the reviewed filled-cell pixel reference while the context crop differs. Independently parsed persisted FODS remains byte-identical to the blank fixture. Thus the screen cue and disk result are distinct evidence; the pixel match is not an independent read of application memory. The owner close release was verified and the final X key/button state was empty.

The two model calls requested gpt-6.1-sol low and used 25,779 input tokens (20,352 cached subset) and 140 output tokens. Cached tokens are included in input. The allocation used 1 CPU, 1 GiB, private Xvfb/Calc, no container network, and host-only model access. This is a correctness probe, not a performance comparison.

`public.zip` retains frozen conditions, candidate code, observations, model result accounting, programs, receipts and saved bytes. `audit.py` checks archive/source/candidate hashes, the context and filled-cell crops, one entry execution, absence of the Save chord, independent FODS parse and neutral input.
