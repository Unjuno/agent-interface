# WSLc Calc: stale target refusal after model grounding

This negative experiment follows PR #9853, using main-equivalent runtime at 798c4a10aec139d1dc05e786e8bcbb81f24a4a06, a fresh Calc document and the pinned WSLc Calc image. The container had one CPU, 1 GiB, no network and a 150-second timeout. One host gpt-6.1-sol low call saw the original screen and selected A1 [81,151] and Save [83,51]. After its response, the test placed a synthetic 8x8 black X overlay at the selected point, then captured again before mint or input.

The pointer binding was unchanged, while all 64 target pixels changed. The caller's fresh-image comparison rejected the stale target and exited 1 with `target changed after model call`. This nonzero exit is the expected negative result, not task completion. An independent audit recomputed both retained image hashes and pixel hashes, checked the association with the model image, found no owner program or minted handle, and verified no click result. Owner close reported no release attempt because no dispatch had occurred; X reported no keys or buttons down. The container was removed.

The model used 12,192 input / 78 output tokens and 4.842 seconds. Frozen inputs and 305 runtime / 2033 host-source hashes matched after execution. The archive includes the attempt, screenshots, logs and audit; its protocol journal stays local because it includes local paths, with its hash recorded here. ZIP integrity passed. The injected overlay tests the caller's pre-dispatch comparison on one fixed layout; it does not establish native input-guard behavior during a dispatch, arbitrary changes outside the inspected patch, recovery after partial input, or task success.
