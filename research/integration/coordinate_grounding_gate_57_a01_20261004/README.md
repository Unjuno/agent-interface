# A01 — model-coordinate grounding through pinned target handles

## Question and boundary

**H:** A model-proposed coordinate can be converted into an observational target handle from the exact image/binding that produced the coordinate, then revalidated against a fresh observation before any ordinary action-admission step. Missing, changed, ambiguous, stale, or out-of-scope targets must stop without input.

**T:** Exercise the current `runtime.guarded_x11_v1.TargetHandleStore` and its real pixel/focus/geometry checks with deterministic synthetic RGB images. Convert one fixed model-coordinate proposal into a bounded region, mint a session alias against source sequence 1, and resolve only against sequence 2. Exercise exact match, geometry translation, changed pixels, duplicate regions, local movement, stale capture, focus change, missing alias, flat source, and out-of-bounds coordinates.

**D:** The target-coordinate path is mechanically supported only when the exact source patch is uniquely resolved in a fresh, correctly bound observation. All refusal cases must be ineligible. Even a valid handle is observational only and still requires ordinary admission. The probe must dispatch zero input.

**C:** This construction uses synthetic pixels, one deterministic model-coordinate value, and no model, application, GUI, OS input, or independent task-effect scorer. It does not establish visual grounding accuracy, action correctness, recovery efficacy, or end-to-end benefit.

**U:** The live desktop lane, screenshots, and action authority are not used. This is a model-free construction under Issue #57 / the next-work note in #6957, not a live allocation.

## Result

Against the frozen source in `FREEZE.json`, the exact current handle registry passes 8/8 construction tests. Fresh unchanged pixels resolve the proposed point as `VALID`; an explicit window translation resolves as `REVALIDATED`. Changed pixels, duplicate exact regions, local movement, stale observation, focus change, missing alias, flat source, and an out-of-bounds point refuse. `PROBE.json` records zero input dispatches and the limited claim scope. `audit.py` independently checks source commit blobs/SHA-256 plus the result predicates.

The construction answers the specific mechanics question left open by A14: new coordinates can be used to mint a bounded observational alias and then joined through fresh pixel revalidation. A model-produced coordinate remains an unverified proposal; the registry does not grant action authority. This does not replace the missing fresh application-level target/effect test in #57.
