# Guardian commit-send ambiguity: r525

One preregistered fixed-order three-arm synthetic trial passed its scoped checks on Docker Desktop Linux. Each arm used in-process MCP, an owned guarded X11 owner and prestarted supervisor, a separate guardian ready before a held `a` input, and a cancellation deliberately stalled before the real owner method. The parent verified the prepared-record digest and marked COMMIT attempted before the send boundary.

The valid arm sent COMMIT, received acknowledgement, and guardian plus independent pidfds observed owner and supervisor exit. In the `error_before` arm the fixture injected an OSError after marking attempted but before sending; the parent reported `commit_unknown`, and guardian reported an uncommitted no-signal result. In `error_after`, the fixture successfully sent COMMIT then injected OSError before setting its local sent flag or receiving the final ack. The parent again reported `commit_unknown`; guardian reported COMMIT received and signalled both processes, whose exits independent pidfds observed. Thus the same parent classification corresponded to two distinct observed fixture outcomes. A separate sentinel and Xvfb remained alive at observation and every acquired pidfd was observed exited in cleanup.

The archive includes preregistration, scripts and hashes, MCP metadata, prepared records, guardian receipts/stderr, observer and cleanup results, stdout and exit. The read-only source was owned-display draft `7a131be784b6c135c78cf63e48e21ece783c5b30`; the image was `agent-interface-xvfb-mcp:late-input-r19` (`sha256:bd191d30ea94871a1d3ca717252cd07a276e8ef7d1bcb4a130b63935ce075425`), network disabled, one CPU, 1 GiB, no pull. The raw field named `durable_record_matches` means bytes and digests matched after fixture fsync calls, not proof of persistence across power failure. Observation images and X authority cookies were not retained.

The injected errors immediately before and after a successful send do not reproduce a genuine partial kernel send; they test the conservative classification boundary. Independent review identified a remaining failure: guardian sends its final acknowledgement before it waits for parent exit and retires the processes. If that send fails after COMMIT was received, the prototype can exit without carrying out its accepted custody. An acknowledgement-send failure must not discard accepted custody, and that boundary is untested here. Parent's UNKNOWN decision is reported to the observer before abrupt parent exit and is not a demonstrated durable product custody record. Guardian receipts are not independently authenticated signal traces; trusted fixture PIDs were opened without an independent pre-open incarnation proof. One arm each in fixed order does not establish reliability or hard deadlines. The actual cancellation body, external/graceful MCP transport, old input release, queued requests, real filesystem stalls, guardian crash, real application task and MAP01 remain unverified. PR #10131 remains blocked and its failing shutdown test is unchanged.
