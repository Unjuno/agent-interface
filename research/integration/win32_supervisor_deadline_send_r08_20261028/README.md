# Candidate Win32 supervisor deadline-send R08

A fresh R08 repeats the R06 extreme, contract-valid obligation construction against the candidate production supervisor with deadline-aware Windows overlapped send. The program validator and obligation derivation produced 63,488 Unicode obligations in a 952,830-byte protocol-shaped request; this does not establish full runtime admission. A gated owned worker and non-reading peer ran inside a Job Object. The exchange returned `TimeoutError` after the 200 ms deadline instead of remaining blocked at the observation point, marked the helper unavailable, and the peer and worker exited. Process inspection found neither PID remaining. The trace reported exchange completion 4 ms after the recorded deadline in this run; this is not a hard timing guarantee.

Separate synthetic unit tests cover normal small requests reaching a fake recovery helper and a delayed fake release not running after timeout. These do not demonstrate physical input release or an independently observed application effect. The native experiment uses a fake identity reader, zero grace, and a deliberately non-reading peer; it does not establish exact production helper retirement, absence of bytes delivered before cancellation, or safe replay. Serialization, write/cancel system calls, receive and process retirement are not proven bounded. No GUI, game, model, native keyboard/mouse input, WSLc or Docker was used.

The candidate source snapshots, source conditions, exact probe, traces, outcome, empty streams and hashes are retained. The probe imports the runtime package under test via `PYTHONPATH`; rerunning requires matching its recorded source hashes and a fresh output directory.

Two retained local unittest runs cover the deadline-send tests and the existing process-cancellation suite: 29 tests pass in normal and optimized Python. The new tests include normal fake release, delayed fake release after timeout, late completion, partial write, cancellation failure and pending-write reuse. Baseline test and owner snapshots preserve Windows line endings and match current main after newline normalization. These tests do not exercise real keyboard/mouse input or app delivery.
