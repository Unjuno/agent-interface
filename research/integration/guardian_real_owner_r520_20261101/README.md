# Guardian against a real guarded owner and supervisor: r520

One preregistered synthetic trial on isolated Docker Desktop Linux passed its scoped checks. A disposable parent started a private Xvfb, the repository's `OwnedGuardedSessionOwner` and its prestarted cancellation supervisor. It observed/minted a patterned target and began a guarded input; the parent recorded both a target KeyPress and independent keymap-down while the action thread was still alive. A separate guardian accepted pidfds for the owner and supervisor and acknowledged commit. An external observer independently pinned those processes, the guardian and Xvfb before allowing the parent to exit via `os._exit(0)`.

The guardian receipt reported signals to both supplied pidfds and exit observations; independent pinned pidfds also showed owner and supervisor exit. Xvfb and an unrelated sentinel remained alive at observation. A subsequent fresh X connection observed `a` up on that still-running Xvfb. This is a point-in-time keymap observation: it does not establish why the state changed, delivery of the old release, old task success or absence of queued requests. The receipt explicitly leaves old release unconfirmed, task success unknown and replay disallowed. The observer then signalled and observed exit for all acquired pidfds; pidfd readability does not prove orphan reaping.

The archive includes preregistration, fixture scripts and hashes, initial observe/mint JSON, parent log, guardian receipt, observer result and cleanup, stdout and exit. Capture image files referred to by observation paths were temporary and are not retained; no X authority cookie is archived. The source was draft commit `830b75480c14044739e0442313d99ba08d0391a4`; image `agent-interface-xvfb-mcp:late-input-r19` was pinned to `sha256:bd191d30ea94871a1d3ca717252cd07a276e8ef7d1bcb4a130b63935ce075425`, with no network, one CPU, 1 GiB and no pull.

This is one manually committed synthetic crash experiment, not MCP cancellation or normal transport shutdown. The guardian does not yet receive verified operation/input custody, protect against an adversarial peer, survive its own crash, or isolate a blocked receipt writer. It issues no input release and does not establish general reliability or hard deadlines. Early fixture failure before pidfd registration relies on the container as final containment, and an initial partial output line could wait until the outer timeout. This does not resolve the failing shutdown regression in PR #10131.

Independent fixture review found further limitations: the owner used inherited DISPLAY/XAUTHORITY rather than the experimental owned-display Xlib fence; pidfds were opened from trusted fixture PIDs without independently proving the pre-open process incarnation. The PASS predicate required exit but did not require `signal_sent=true`, although both receipt fields are true in this sample. Guardian signal provenance was not independently established. The post-retirement Xlib query also relied on the outer timeout rather than a separate bound.
