# WSLc Calc: explicit expected-value OCR cue

`research/live_control/calc_ocr_pair_cue_v1.py` extracts the earlier fixed-value OCR classification into a reusable pure function. The caller supplies two explicit nonempty ASCII decimal strings. It returns `filled` only when both single-word OCR results match at confidence 90–100; valid mismatches are `wrong`, and missing, malformed, ambiguous or low-confidence OCR is `unknown`. Invalid expected values raise `ValueError`. This cue does not establish saved-workbook success or grant input authority; the caller must own geometry, freshness, OCR resource limits and guarded action.

A frozen WSLc Calc run e16 exercised the new module through an experimental adapter reading expected values from a read-only input. With 641/283 and an intentionally stale reference, the compiled method returned `SAFE_YIELD`, did not replay entry, then used two Tesseract crops and a new guarded Save. An independent parser found exactly 641 and 283 in the saved FODS and input release was verified. The host/container launcher took 10.579 s; the task interval was 7.465 s; one model call used 12,194 input and 78 output tokens. This is one fixed-geometry known-value case, not a general performance or reliability result. Issue 57 remains open.

Run `python -m unittest research.live_control.test_calc_ocr_pair_cue_v1` and `python -O -m unittest research.live_control.test_calc_ocr_pair_cue_v1`.
