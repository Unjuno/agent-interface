# R565: parent-liveness recheck race

Three separately preregistered unique-directory forced-order fake-process cells on WSL Ubuntu Python 3.12.3, without GUI/input/network. The supervisor received a grant and checked its parent pipe immediately before a gated forward. When parent death preceded the check, the child saw EOF and produced no fake effect. In the live-parent control, the fake effect occurred. When parent death followed a no-EOF check but preceded forwarding, the fake effect occurred after parent death. All three scripts returned 0 because each expected observation, including the counterexample, occurred; this is not a safety PASS. Child and supervisor pidfd exit were observed and no emergency-kill events were recorded. Conditions, code, raw output and per-arm event logs are archived; pre-run script SHA-256 `10e249456d640a0922d80a8cc8c70ed6cc78aa28272d16165fb940e0f614d7da`.

One check cannot atomically prevent a later parent death before forwarding. These are fixture-generated events, with unverified PID-file-to-pidfd identity and no independently collected supervisor exit status. No actual agent-interface owner, public MCP, real input release, WSLc, MAP01, bounded recovery or reliability was tested. The candidate is not adopted.
