# WSLc private Xvfb: cooperative target barrier and asynchronous effect

Three fresh WSLc allocations used main-equivalent runtime 9ce6751e69feb658a6e156b67955433899f0a355, a synthetic cooperative target on private Xvfb, pinned image, one CPU, 1 GiB, no network and a 30-second outer timeout. A research-specific worker sent and X-synchronized a button pair, then stalled; the existing prestarted supervisor retired it at a 600 ms deadline and returned UNKNOWN. After return, the harness sent the target a nonce-bearing X ClientMessage. The target explicitly handled that message in its event loop and recorded an acknowledgment with its PID, window, nonce, whether the release event had been handled, and whether a test effect file existed. This is a deliberately cooperative fixture, not a generic X11 barrier or public dispatch integration.

- A01 running target, synchronous effect: the target handled the pair and wrote its effect before the acknowledgment; acknowledgment arrived within the 300 ms observation.
- A02 target SIGSTOPed through the owner deadline: no acknowledgment arrived during the 300 ms observation. After SIGCONT, the target handled the original pair, wrote the effect and then acknowledged. No input replay occurred.
- A03 running target, asynchronous effect: on button release the target scheduled an effect file write on another thread after 1.8 seconds. It then acknowledged the marker, recording that the release was seen but the effect did not yet exist. The effect appeared later. Thus, even a matching cooperative event-loop acknowledgment does not by itself prove completion of work delegated asynchronously.

The aggregate audit checks nonce/window/PID association, input event and deadline ordering, target stop/resume, effect and acknowledgment timestamps, worker retirement, neutral buttons and absence of the scripted extra-action marker during bounded observation. Frozen inputs and 305 runtime hashes matched; all containers were absent and ZIP integrity passed. Each arm is one controlled observation. A target-specific acknowledgment must define its completion semantics and be paired with effect evidence; this experiment does not establish an authenticated or generic barrier, arbitrary application queue drainage, real Calc behavior, durable completion, or MAP01 completion. UNKNOWN must not be upgraded solely from an event-loop marker.
