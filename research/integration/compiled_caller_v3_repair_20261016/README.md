## Counterexamples and adopted connection

The [prior characterization](../compiled_caller_handoff_20261016/README.md)
retains eight information-preservation failures per mode in the legacy helper
and import-only caller control. That FAIL remains unchanged. The new explicit
`integrated_efficiency_compiled_execution_v2.py` composes the actual v3 caller;
legacy v1 still imports v2 and is unchanged.

The new entry requires `interface_for_target`, called with the detached final
selected target/check after revalidation. Target promotion reaches the actual
core's symbolic admission requests instead of silently using a pre-model
interface. This is a trusted domain construction callback: actual mapping to
real windows/handles, generations and per-action authority remain the domain
adapter's validation responsibility.

The actual returned core receipt is detached before the sink runs and retained
in the returned result. Failed release maps to typed incomplete execution with
the known completed prefix and current input uncertainty. An explicit no-input
refusal differs from unknown delivery. A sink's ordinary failure becomes the
caller's typed `ExecutionReceiptError` with validated detached progress and the
original exception as cause. The caller captures that progress before auxiliary
clock/journal failures, remains CALLER_FAILED and skips outer effect verification.
Original sink diagnostics remain in the result; no retry or recovery is added.

## Limits and next integration

[COMPILED_CALLER_V3.md](../../live_control/COMPILED_CALLER_V3.md) describes the
explicit API and result fields. A returned in-memory receipt does not establish
durability or restart recovery. If the core never returns a receipt, prefix and
delivery remain unknown; non-Exception stops propagate. No generic compensation,
fresh input authority or automatic replay follows from failure metadata.

Qualify the actual domain builder, fresh observations/generations, backend
admission/release and independent effect/collateral predicate through this
connection. Then freeze and run a permitted matched cold/warm/invalidation/
repair comparison with actual provider/all-stage accounting. Physical release
bounds, bounded semantic recovery, live task success and second-domain economics
remain unmet under #17/#59/#57. Local passing tests do not close those goals.
