# WSLc shared-file PermissionError: bounded retry successor

The prior `wslc_three_arm_lifecycle_first_newseed_20261031` block stopped its ephemeral arm after five exact submissions when the host reported `PermissionError`; the retained exception did not identify the file operation. The successor research host wraps three idempotent shared-file operations—request read, image read and atomic response publication—in a 2 s permission-retry window with 20 ms maximum delay. It validates the request and image digest before invoking the model. The model call itself is **not retried** by this wrapper. Response bytes are produced once; if a response path already exists, identical bytes are accepted and conflicting bytes fail closed.

A separately frozen WSLc allocation au01 used a new fixture seed and intentionally raised one transient `PermissionError` before each of those three operations for request 002. The retry log records each injected failure; the arm then completed six exact fixture submissions, with six distinct retained task call IDs and all 48 recorded terminal releases neutral. One schema preflight also completed. Host and container returned successfully and the uniquely named container was absent in the subsequent WSLc listing. The measured preflight-through-process-exit interval was 42.962 s; this isolated, injected-fault run is not a controlled speed comparison.

`test_exchange_io.py` exercises transient permission failures, persistent denial until deadline, non-permission error propagation and publication retry without re-invoking a simulated model call, under normal Python and `python -O`. `audit.py` (normal Python with `jsonschema`) checks frozen inputs, preflight, image/response and call-ID association, retry events, exact submission history and neutral release records. `public.zip` retains the successor host/runner/launcher, schemas, retry events, timing, fixture records and source hash manifests; private model protocol/workspace files remain local and hash-indexed. The previous failed allocation was not rerun.

The injected errors happened **before** the operations; this does not reproduce the original sharing race or prove which original file failed. The timeout bounds retry scheduling after a `PermissionError`, not an indefinitely blocked filesystem call or log write. If publication still fails after a model call, provider use may already have occurred; no replay is authorized and accounting must retain any known use as well as uncertainty. A host failure can still leave the container waiting for its separate request deadline. This research bridge is not a production IPC guarantee, and one successful fault-injection trial does not establish general reliability, MAP01 completion, or broad efficiency.
