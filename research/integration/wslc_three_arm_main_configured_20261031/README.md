# Current-main WSLc Chromium integrated comparison

This prospectively fixed three-arm block uses main `3dfd373cd839061cf4112e8646918dcaa8a12167`, seed 991036, and the explicit `/usr/bin/chromium` configuration introduced by PR #9977. Three separate WSLc containers and fresh model sessions ran in fixed order: persistent, ephemeral, plain. Each had one schema preflight and the same six synthetic form tasks, including the persistent cold/reuse/invalidation/repair sequence. The host used `gpt-6.1-sol` at low effort. The retained task histories and original input-release events were independently audited; all 18 expected submissions matched exactly, and all 123 recorded terminal events had verified empty key/button state.

In this **single** block, persistent used 64.54% fewer recorded input tokens and had a 7.85% shorter measured lifecycle than plain. Cached tokens are included in input, not added to it; output is listed separately, and provider billing is unknown. The lifecycle starts just before model-host startup and ends when both host and container have exited. It includes schema preflight, validation, container/app startup, tasks, scoring, cleanup and polling; it excludes source preparation, launcher initialization, image build/pull and postrun audit. It is not the total cost of all research attempts.

These measurements do not establish a general speedup or reliability rate: arm order is fixed, there is one run per arm, load/cache/provider timing and arm toolsets are not fully controlled, and the task is one synthetic Chromium fixture. The earlier current-main attempt in PR #9977 consumed a separate 10,936-input/126-output-token preflight before failing at Chromium startup; those tokens are not included in the table. That failure is retained and was not replayed. The separate startup smoke and this new block have new allocation IDs. Second-domain matched evaluation, actual provider pricing, MAP01 and broad real-world performance remain unverified. Issue 57 remains open.

`public.zip` contains frozen runner/broker/configuration, model usage and typed call records, screenshots, exact submission history, runtime events, conditions, timers, cleanup, source hash manifest and schema records. The six host protocol journals remain private and are hash-indexed in `private-hashes.json`. Each of 2,092 mounted files was checked against the main Git blob after CRLF normalization before execution and against its exact mounted SHA-256 afterward; full source and image bytes are not included here, so those byte comparisons cannot be independently rerun from the packet alone. The host dependencies/provider are not fully frozen. `python audit.py` checks the retained archive, schema, unique call/ledger identities, all task/receipt/release records, source-verification summary, lifecycle ordering and no remaining named container. No permission-retry or host-failure marker occurred in this block.
