# Caller aggregate representability repair (I16)

An available cost for each attempt does not ensure Python can represent their sum. Two finite floats can produce infinity; a huge integer plus a float can raise OverflowError after execute and verification callbacks have completed, preventing the full result from being returned.

Preserve the original all-attempt coverage repair. Return null for an incomplete, overflowing, or nonfinite aggregate, preserving the result and every attempt. Individual numeric acceptance remains unchanged. This does not qualify arbitrary per-call values for strict JSON, currencies, provider prices, or end-to-end savings. Huge integer-only sums retain their original semantics and serializer limits.

First seven inert directed conditions produced three failures and four passes. Repaired seven passed normally and with -O. The final portable seven plus nine coverage and twelve existing caller checks passed 28 normally and 28 with -O without ROWS or TRACE_OUTPUT. Saved-data auditing compared all 21 complete rows, all six available original noncost receipts and all seven ordered callback sequences. Four full copied contradictions were rejected. Exact Fraction reference applies only to the declared seven cases. Nonfinite raw values retain explicit $numeric tags; strict JSON errors remain separately recorded.

All first failures, full process receipts, full streams, definitions and complete copied controls are retained. Public profile projections differ from private originals and carry separate pins. Historical Python files are inert .py.txt; only the portable aggregate module is added to normal discovery and registered once. The full native protocol suite, physical GUI, models, providers and formal allocations were not rerun.
