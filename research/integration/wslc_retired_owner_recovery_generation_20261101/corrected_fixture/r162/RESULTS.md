# Idempotent delayed-XTEST fixture and live positive control

A focused test against the r157 fixture calls its actual factory's `get` four times with a stable fake backend, then emits one key press. The unmodified fixture failed: the underlying fake XTEST function saw five calls (the intended a plus four delayed b injections), rather than two. The local fix installs its XTEST/sync wrappers only once per backend and refuses a changed backend rather than silently layering them. The same test passed in normal and `-O` WSLc runs; the optimized test also passed after the injection-count logging was added. The related owned-process test file ran 50 tests without failures. This is a local fixture prototype; no production runtime behavior was changed and no full suite is claimed.

In new private-Xvfb live control r162 with an append-only injection log, exactly one delayed b was recorded. The old target observed one b press about 8004 ms after the marker; the actual X sync returned about 7999 ms after the marker. At the 8.5-second check `a` was up and injected `b` was down. The fixture explicitly released the injected input; the real guarded action then returned completed and the owner close confirmed release. The private display was retired. This is a single non-cancellation control, not a MAP01 or general timing guarantee.

Two intermediate live diagnostic attempts r160/r161 failed to reach their expected marker. Review found the newly added logging code incorrectly used `root` inside a function where that name denotes the XTEST root argument, instead of the output directory; the old target nonetheless recorded a and b. The action's direct exception was not captured, so the precise runtime path is not independently established. r162 fixes the logging expression using the already-bound marker directory. These failed attempts are retained separately and not counted as passes. Earlier r156/r157 long sync observations used the repeatedly wrapped fixture and cannot be interpreted as a single-delay benchmark.
