# Corrected delayed-XTEST fixture: control and private recovery

The four allocations here use selected runtime files from draft #10088 at `cc94bf0166938bfdf518a11bda0ced0601c614c4`, not current main. `runtime-source.zip` preserves the exact r162/r163 runtime subset including the idempotent test fixture and injection logging. r160/r161 used a broken version of that logging file, retained separately, and failed. The underlying fixture idempotence repair was merged in #10103; the injection log is trial instrumentation, not part of that merge.

* `red_green` preserves the regression-test sources, hashes and logs: uncorrected fixture produced five low-level calls for one press after four `get` calls; corrected fixture produced two. Both normal and optimized focused tests passed; the related owned-process suite had 50 passing tests.
* r160/r161 are failed attempts: a newly added logging expression shadowed its directory variable with the XTEST root argument. They did not produce the expected sync marker. The action's underlying exception was not independently captured. Their raw outcomes are retained and are not counted as passes.
* r162 is one corrected-fixture non-retired positive control. The injection log recorded one delayed `b`; the target saw it around eight seconds, the original X sync and guarded action completed, and the test fixture cleared injected input before a confirmed owner close.
* r163 is one separate recovery allocation: the actual experimental private-display wrapper retired the old guarded owner and Xvfb with old operation UNKNOWN/no replay, created a replacement display and target, and executed a fresh `a`. The new target and keymap showed no `b` at 8.5 seconds from old request flush. Old authority failed to connect and new authority connected; error text was not retained, so the precise rejection reason is unknown.

These two successful allocations are fixed-order single observations and differ in retirement, display replacement and target; r162 does not prove r163's old X server accepted its flushed request. The wrapper is invoked directly, not through MCP; destroying the old Xvfb destroys its application. No general queue-drain fence, old-task success, physical-desktop release, MAP01, latency bound or reliability claim follows. Read each `RESULTS.md` and conditions for scope. Ephemeral Xauthority files lived only in container `/tmp`; local-absolute-path command records are omitted and the runner template is retained.

`python -B verify.py` checks the exact archived runtime subset, per-arm trial scripts against frozen manifests, conditions' manifest hashes, red/green input hashes and selected raw outcomes. It is not a checksum of all raw data or an experiment rerun. The original per-arm audits assume the old local directory layout and are historical, not directly runnable here. The runners require reconstructing `src/`, access to the exact pinned image, and fresh allocations; image provenance/availability is not established by this archive.
