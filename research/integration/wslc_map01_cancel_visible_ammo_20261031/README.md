# Visible HUD following X11 cancellation

This WSLc test extends #9892 with the game's HUD enabled so the operator-visible display can be compared with evaluator-only engine ammunition. Four fresh isolated Xvfb / Freedoom2 MAP01 instances used ASYNC_SPECTATOR at 35 tics/s, seed 991031, skill 1, one CPU, 1 GiB, no container network, and image sha256:6150a4f3c779a51b3ac6a7d93bc1d0450803325efb7ab38ade8b1aaf79c33e25. The same script and fixed order withhold/cancel/cancel/withhold were used. In cancel runs an independent X11 client observed `f` held and requested cancellation 50 ms later; the interrupted guarded operation returned verified empty release with partial effect unknown. No model or subsequent attack was used. The mounted runtime matches main 6a9c787d2caf9740612de65bd2539846dd87cad4 as recorded in #9891; later main commits through 8f079bd6c1ffa7372dbb3f0d98be48703cdafce9 add research records only.

For each sample the script advances the game, captures the actual 640x480 X11 window, saves its image and capture interval, then reads engine telemetry. The two sources are not atomic; the image precedes the telemetry reading, and the game continues throughout. In both cancellation runs, the first post-release sample showed 50 in the HUD and 50 in telemetry. The next captured HUD image still showed 50, while the subsequent engine read reported 49. In the next sampled image the HUD showed 49 and telemetry remained 49. Both no-input controls retained 50 in telemetry and an unchanged HUD crop throughout. The raw screenshots support the visible digits; the audit checks SHA-256 hashes of the full images and changes in crop (32,408)-(90,450), not OCR correctness.

This shows that successive screen and engine reads can disagree in this real-time measurement sequence. It cannot distinguish render lag from update timing between the capture and engine read, prove a simultaneously stale display, establish a safe waiting period, infer a hit, or justify treating the old action's effect as fully resolved. Capture and PNG encoding add latency and alter timing, and this small fixed-seed sample is not a general reliability or performance estimate. Observing a changed digit here provides an effect cue, not an autonomous recovery policy or MAP01 completion.

All raw images, receipts, telemetry, scripts, conditions and container output are retained in four ZIP files. `python audit.py` checks cancellation and release order, controls, capture hashes and sample ordering. The game telemetry is used only in this audit; no engine state was provided to a model or policy.
