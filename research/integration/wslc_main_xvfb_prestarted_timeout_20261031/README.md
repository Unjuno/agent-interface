# Prestarted supervisor: stopped-Xvfb deadline failure

This is a retained **failed** follow-up to the immediately preceding non-supervisor run in `wslc_main_xvfb_stop_recovery_20261031` (PR #9971). The predeclared question was whether enabling the existing prestarted cancellation supervisor changes the old task's observed key release while preserving UNKNOWN/no replay and fresh-target task success. Both use the same mounted source subset, image and stopped-private-Xvfb synthetic application; runs are sequential, not randomized, with uncontrolled host timing. The source subset is byte-identical across referenced commits `1ad8684` and current-main `577f1b13`; its archive digest, image digest, limits, runner and conditions are in `public.zip`.

The b03 test exited **1**: while the private server was stopped, the supervisor exhausted its transaction deadline and reported `owner_release_attempt.status=unknown`, `reason=transaction_deadline`, and a retired worker. Cleanup stayed `UNKNOWN`, `release_confirmed=false`, and replay remained prohibited. The existing test expected `not_attempted` at that point, failed, and its `finally` resumed the server and observed both monitored keys up during isolated cleanup. Neither the old task oracle nor the fresh-target recovery oracle was reached. Consequently there is no matched key-release or task-success comparison, and cleanup in the test harness is not evidence that the original task succeeded.

The mismatch is not evidence that changing the assertion alone is safe: the supervisor deadline prevents an acknowledged release while the server is stopped, and the observed worker retirement does not establish that a later release occurred or that it would not affect another client. Preserve the old failure; investigate the intended stopped-server contract, actual worker and queued-X-request behavior, and a fenced recovery design before changing success criteria. The prior non-supervisor run independently observed the original `a` still held and failed its task oracle, then passed a distinct fresh-target task; its raw data remain separate in PR #9971. One run per setting cannot establish reliability or generalize to MAP01.

`public.zip` includes the predeclared conditions, runner, launcher result, full receipt, stdout/stderr and Xvfb log. `python audit.py` checks the archive and the failed, unconfirmed outcome. The container was observed exited, and no private display input targeted the user's desktop.
