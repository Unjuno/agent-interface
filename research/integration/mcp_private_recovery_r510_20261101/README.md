One preregistered synthetic test on Docker Desktop Linux passed. A private MCP server observed and minted an alias, began guarded input, and the test observed both a KeyPress(a) event and keymap-down before stopping its owned Xvfb; `/proc` confirmed state T. `interface_guarded_cancel` returned pending, and `interface_results` later returned the same cancellation operation ID with terminal cancellation custody in approximately 5033.87 ms. The nested recovery result remained `unknown`: the old guarded owner and display had retired, fresh display was allowed, but old release and task success remained UNKNOWN and replay was disallowed. The test verified that the archived cancellation result matched the retrieved result and that its teardown completed; the dedicated container exited and was removed.

The MCP interface was invoked in-process through `server.call_tool`, not over a network transport.

This result is one manually triggered fault-injection test. It does not demonstrate a new-display task, automatic expiry, old key-up, old queue drainage, MAP01, hard deadlines, comparative speed or general reliability. `fresh_display_allowed` is a scoped result of the retirement checks, not proof of task success or authorization to replay the old action.
