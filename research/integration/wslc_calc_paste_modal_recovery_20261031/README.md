# Real Calc: bounded recovery from paste import dialog

Two preregistered private-WSLc Calc runs follow `wslc_calc_ocr_graph_paste_modal_20261031`. Each issues one guarded clipboard paste, then the original compiled graph yields `effect_unavailable` with entry pending. Recovery never replays the paste. It closes the original owner with verified input release, identifies a unique visible `Text Import` window, starts a separate modal owner, and compares fixed title, options, preview and OK-button pixels against the visually reviewed f09 screenshot. This fixed reference is specific to the known 641/283 fixture, screen geometry and Calc appearance; it is not a general dialog recognizer.

* f10 deliberately corrupts one reference-preview pixel. The modal is rejected before any confirmation or Save, neutral release is verified, and the saved file is byte-identical to the blank fixture.
* f11 uses the unmodified reference. One newly minted guarded click confirms the matching dialog. After a fresh Calc observation, actual bounded Tesseract identifies 641 and 283 in the reviewed crops. A separately minted guarded Ctrl+S completes, and an independent FODS parser finds exactly those two numeric cells. Original, modal and fresh owners each verify neutral release; no keys or buttons remain down.

Both host/container runs exited cleanly and the private WSLc container list was empty afterward. The original graph itself remained `SAFE_YIELD`; the confirmed dialog and Save were separately authorized recovery actions. Clipboard transfer, visual matching and recovery are experimental harness code, not a production dialog adapter. They rely on the fixed expected preview and one reviewed coordinate, and do not prove safety for other dialogs, arbitrary visual changes, concurrent interference, shared clipboard use or real-world reliability. No model was called. Issue 57 remains open.

`python audit.py` with Pillow independently verifies pinned inputs/manifest, the prior screenshot hash and exact dialog regions at each recorded guarded-click capture, the deliberate mismatch, original entry and release receipts, distinct owners, OCR crop/transcript hashes and confidence, Save guard/release and independent saved FODS. The test harness does not record a separate application-level acknowledgement of the click; the dialog disappearing, fresh OCR and saved file are the observed effects. The two controls are one fixed-order pair; source/image bytes and external dependencies are not fully reproduced. An offline two-test modal-image equality check was run before the trials and its source is retained in the archive.
