# Private stopped-display held-input recovery: r506

One preregistered synthetic trial passed its scoped checks on Docker Desktop Linux. A private Xvfb was confirmed stopped while a target had observed `a` down. A manual cancellation with a 7-second outer deadline and a 2-second retirement reserve returned in 5008.877 ms; the old guarded process and display had retired. A separate fresh target changed its counter from 0 to 1 and observed the new press and release, with key-up and verified fresh-session close. The old action returned EOF; old release and task success remain UNKNOWN. The old guard's cleanup receipt is `cleanup_failed`/UNKNOWN and includes a possible late server request. `replay_allowed: false` is a receipt field, not an independent observation of queue drainage or replay.

The tested image is `agent-interface-xvfb-mcp:late-input-r19`, image ID `sha256:bd191d30ea94871a1d3ca717252cd07a276e8ef7d1bcb4a130b63935ce075425`; it differs from r504's image, so this is not a controlled comparison. The image ran with no network, one CPU, 1 GiB and no pull. The source was the r505 worktree based on parent commit `557e96de32442cbfb970b28e3ccddb203d4e14b1`; the exact tested recovery source hash is in the raw archive. A subsequent docstring-only edit clarifies the reserve's limitations.

The archive retains preregistration, fixture, raw output, process cleanup, exit code, source/fixture hashes and stdout. The fresh target was stopped during fixture cleanup, and the old target exited after its server was retired; no dedicated container remained. Two fixture risks identified in r504 were addressed before this trial: the target is tracked before `pidfd_open`, and the old display is retired before closing clients during cleanup.

This is one manually triggered direct Python-path trial, not a hard deadline guarantee, automatic expiry, a naturally occurring failure, MCP, MAP01, a benchmark or evidence of general reliability. The display-retirement reservation is optional and defaults to zero. Cancellation may overrun; the existing outer deadline check then prevents fresh-display authorization.

Scoped local tests on the same image: 53 tests passed normally and 53 with `python3 -O`; the expected negative peer-mismatch case prints a child-process traceback even though the suite passes. Independent static review found no obvious new safety issue and explicitly noted that a reserve is not a hard real-time bound.
