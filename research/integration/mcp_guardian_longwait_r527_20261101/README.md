# Guardian wait beyond the prior six-second limit: r527

One preregistered fixed-order synthetic pair compared the r526 six-second parent-pidfd wait with a repeated-poll prototype. Both used in-process MCP on private Xvfb, real guarded owner and supervisor, guardian ready before input, held-key observation, and a cancellation stalled by a fixture before the real cancellation method. The MCP action and cancellation were recorded pending before the subsequent wait; the trial does not assert the key stayed held throughout it.

In the baseline arm, the parent remained alive for 7.2 seconds after accepting guardian acknowledgement. The observer then saw parent, owner and supervisor alive but guardian exited; guardian stderr reported its six-second parent-exit timeout and no guardian receipt existed. This reproduces a custody gap, not successful recovery. In the repeated-poll arm, the observer saw all four processes alive after approximately 7.203 seconds from guardian acknowledgement. After the observer allowed parent `os._exit(0)`, the guardian reported parent-pidfd exit and owner/supervisor retirement, and independent pidfds also showed both exited. Xvfb and an unrelated sentinel were alive at observation. All acquired pidfds were observed exited during cleanup.

The archive contains preregistration, scripts and hashes, MCP metadata, prepared records, guardian stderr/receipts, observer liveness, cleanup, stdout and exit. Source was owned-display draft `7a131be784b6c135c78cf63e48e21ece783c5b30`; image `agent-interface-xvfb-mcp:late-input-r19` was pinned to `sha256:bd191d30ea94871a1d3ca717252cd07a276e8ef7d1bcb4a130b63935ce075425`, network disabled, one CPU, 1 GiB and no pull. Observation images and X authority cookies were not retained. The raw `durable_record_matches` field compares bytes/digests after fsync calls and does not prove power-loss durability.

Repeated polling removes the particular six-second expiry in this prototype but can retain a guardian indefinitely if its parent never exits. Independent review identified another essential boundary: the guardian checks the cancellation deadline when preparing, then still signals the same processes after that deadline has passed. The old action could already have completed. A viable long-lived custody contract must define whether that signal authority continues for the entire exact process generation, prohibit incompatible new work after commit, and provide safe revoke/disarm semantics; this trial proves none of those. No resource-lifetime bound, guardian crash/restart, adversarial identity, true filesystem stall, hard deadline, normal cancellation, graceful/external MCP transport, old input release, queue drainage, real task success, MAP01 or general reliability is established. Old task/release remain UNKNOWN and no replay is authorized. These single fixed-order samples do not fix the shutdown regression in PR #10131.
