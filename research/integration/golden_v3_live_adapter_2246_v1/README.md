# Golden v3 live-adapter preflight (#2246)

This is an additive current-main successor for the remaining runtime/live-task
boundary in #2246. It does not modify the retained golden report or replay any
historical GUI/model/input allocation.

## H — hypothesis

The emitted golden-v3 report, validated CLI adapter, ordinary admission path, and
independent effect-scoring boundary can be composed for a disposable desktop task
only when all source identities and live authority prerequisites are explicit.

## T — preflight before any allocation

Run `preflight.py` in the pinned `python:3.12-slim` workflow after checkout.
It verifies the required source paths and Git blob identities, then checks for a
declared live provider/model authority. No pseudo-model or synthetic PASS is used.

A missing source identity is `STOP_SOURCE_IDENTITY_GAP`. Missing live authority is
`HOLD_NO_MODEL_AUTHORITY`. Only a later successor with real provider authority,
disposable GUI fixture, independent effect scorer, and held-out cases may cross
into model/GUI/input execution.

## D — promotion gate

A future live run must preserve: model attempts and unavailable usage, observation
identity, target/binding revision, ordinary guarded dispatch, exact release,
independent effect (success/partial/collateral/no-effect), stale repair,
ambiguous-delivery safe stop, and cleanup status. Process exit is not task success.

## C

The retained six-task golden report is one live allocation, not a baseline,
repeatability, token-efficiency, latency, or generality claim. The preflight
checks source readiness only and grants no authority.

## U / result boundary

This branch records only the preflight result. The first result must remain
machine-readable and fail closed. No model, GUI, input, or network task is
authorized by this preflight.
