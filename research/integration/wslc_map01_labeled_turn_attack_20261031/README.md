# MAP01 labeled view-turn and attack pilot (2026-10-31)

One fresh WSLc allocation combines the view turn from the [camera-shift pilot](../wslc_map01_labeled_frame_tracking_20261031/) with the later attack in the [attack-transition pilot](../wslc_map01_labeled_attack_transition_20261031/). The protocol was fixed before execution: after five recorded frames, one guarded 80 ms left turn; after five more, one guarded 1,000 ms F-key attack without automatic re-aim; then ten more frames. Freedoom2 MAP01 uses skill 1 and seed 991031. No model runs.

The same-state engine label for target ID 14 moves from x=303 to x=323 after the turn. The unchanged wide candidate moves its point from x=316 to x=336 and falls inside the target box on all ten pre-attack frames. The fixed candidate is inside on the first five and abstains on the next five. The game counter changes from 0 to 1 over the attack, the label changes from `Zombieman` to `DeadZombieman`, and both candidates abstain on the ten post-attack frames. All four guarded actions and final owner closure report neutral verified releases; the final keymap records no tested key down.

The candidate is **offline only** and did not drive the turn or the attack. The initial point is label-oracle supplied, and the screen and evaluation labels come from the same game engine, not the live X11 screenshot path. These are correlated frames in one trajectory, not independent trials; the change in counter is not independent evidence from another observer. This case does not establish safe identity tracking, action authorization, post-recovery control, relative speed, model behavior, or MAP01 completion. It also does not show that tracking improved the attack: the prerecorded attack was issued regardless of either score.

`aa05.zip` retains the predeclared conditions, runner, scorer, raw frames/labels, input receipts and result. With Python, Pillow and NumPy, `python audit.py` checks hashes and release receipts and recomputes the candidate outcomes. The WSLc image was pinned, networking was disabled, and execution used one CPU and 1 GiB with a 30 s watchdog.
