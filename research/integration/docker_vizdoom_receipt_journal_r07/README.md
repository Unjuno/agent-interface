# Docker/Xvfb receipt persistence profiling

**R07 persistent-writer receipt journal (2026-10-28):** The Linux-only, unintegrated persistent locked writer prototype passed 12 tests normally and 12 under `python -O`. Using the same 19 actual R04 pair-19 receipts for ten alternating repetitions, file-per-receipt pretty JSON measured 54.224 ms median combined append plus verified readback; persistent hash-linked JSONL measured 14.998 ms (3.62x faster, 72.3% lower), with every lookup matching and 21.1% more bytes. It flushes each event without `fsync`; durability, cross-host locking, caller compatibility and production interruption semantics remain unverified. Current `compiled.py` retains execution/effect artifacts as separate files; this prototype does not implement that on-disk API. The accepted result uses the pinned image digest; initial failed test logs and excluded setup attempts remain preserved. This storage-only result is not an integrated control speed score: current Docker/Xvfb compiled control remains about 5–6% slower than direct in integrated samples.
