# Docker/Xvfb receipt persistence profiling

**R07 persistent-writer receipt journal (2026-10-28):** The Linux-only, unintegrated persistent locked writer prototype passed 12 tests normally and 12 under `python -O`. Two independent 10-repetition comparisons used the same 19 actual R04 pair-19 receipts. Combined median append plus verified readback was 54.224 and 68.739 ms for pretty JSON files, versus 14.998 and 16.145 ms for persistent hash-linked JSONL (3.36–3.62x faster; 70.9–72.3% lower), with every lookup matching and 21.1% more bytes. It flushes each event without `fsync`; durability, cross-host locking, caller compatibility and production interruption semantics remain unverified. Current `compiled.py` retains execution/effect artifacts as separate files; this prototype does not implement that on-disk API. The two runs use a pinned Docker image digest. Initial failed test logs, an excluded no-overwrite collision, and setup attempts remain preserved. This storage-only result is not an integrated control speed score: current Docker/Xvfb compiled control remains about 5–6% slower than direct in integrated samples.
