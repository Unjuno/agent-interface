# Windows Job host drain: R595–R598

The experimental outer `JobHost` owns a host process, closes unused stdin, starts independent stdout and stderr readers before resume, drains binary output to separate files, and distinguishes host exit from Job/reader/stream closure. It accepts an explicit cwd and Unicode environment without changing the launcher environment. Observed process exit and cleanup after their time budgets remain UNKNOWN, with observed exit code retained. This is not yet the real model host.

Each numbered ZIP preserves source, conditions and test output from one normal and one optimized suite. R595's late-close test was insufficient because readers were absent, so its passing result does not establish deadline handling. R596 corrected it using two successful EOF readers and a timely control. R597 rejected a `None` read but accidentally also treated empty bytearray/memoryview as EOF. R598 checks type first and rejects all three; its 16 tests passed in both modes. A reviewer matched R598's source hashes and controls.

The suite includes exact 512 KiB stdout and stderr concurrently, partial JSON on timeout, reader errors, short file writes, direct host exit with a grandchild retaining stdout, a reader-start failure, non-ASCII cwd/environment, and known injected FD errors. It preserves test transcripts, not per-test child HANDLE traces or temporary log files. The 45-second suite timeout only stops the test process and does not provide independent custody. Real model/app-server, live model-provider accounting, asynchronous FD ownership transfer, ambiguous Thread.start failures, concurrent unrestricted spawn, blocking stream close, full descendant HANDLE verification, absolute time bounds and WSLc parent-death recovery remain unverified.
