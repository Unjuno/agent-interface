# Guardian prepared custody record prototype: r522

One preregistered synthetic three-arm trial used in-process MCP with an experimental owned-display guarded owner and prestarted supervisor. In all arms the target observed `a` press and keymap-down, the original action and an injected cancellation were pending, and the gate token and operation ID matched the MCP call and cancellation. The guardian was ready before input. The real owner cancellation body was held before entry and did not execute.

In the valid arm, a test-specific record included the call ID, gate token, operation ID, transaction deadline, owner generation, process IDs and a checksum-validated shared snapshot containing key `a`. The guardian compared the record with transferred pidfds, wrote a canonical prepared file using file and directory fsync calls, then returned its SHA-256. The saved record, parent acknowledgement and guardian receipt hashes matched; after parent `os._exit(0)`, guardian and independent pidfds recorded owner and supervisor exit. In the mismatch arm, a deliberately altered owner PID was rejected and the guardian reported no signal. In the injected writer-stall arm, parent timed out and no prepared file or receipt existed at observation; that arm's handoff and old outcome remain UNKNOWN. Sentinel and private Xvfb were observed alive, and acquired pidfds were observed exited during cleanup.

**A significant protocol race remains.** Independent review found that a prepared-file acknowledgement sent after the parent times out can still be buffered while the parent has not yet closed the socket. The guardian then treats later EOF as authority to signal, although the parent did not accept the acknowledgement. The 30-second injected stall did not test this boundary because the fixture killed guardian before it resumed. The prototype must not be used as an implementation; a separate explicit commit after digest verification and late-ack tests are needed, with ambiguity after any lost final acknowledgement still treated as UNKNOWN.

The archive contains preregistration, fixture scripts, source hashes, MCP metadata, prepared file, receipts, observations, cleanup, stdout and exit. Image `agent-interface-xvfb-mcp:late-input-r19` was pinned to `sha256:bd191d30ea94871a1d3ca717252cd07a276e8ef7d1bcb4a130b63935ce075425`, network disabled, 1 CPU, 1 GiB, no pull; source was draft `7a131be784b6c135c78cf63e48e21ece783c5b30`. A field named `durable_record_matches` in raw checks compares bytes and hashes after the code's fsync calls; it does not prove power-loss durability. Observation image artifacts and X authority cookies were not retained.

This is one fixed-order synthetic trial, not actual cancellation completion, graceful MCP shutdown, real filesystem stall, adversarial authentication, old release, queue drainage, general reliability, hard deadlines or MAP01. The mismatch no-signal result is the guardian's own receipt; owner/supervisor liveness after parent exit was not independently checked before cleanup. Pidfd provenance before opening from trusted PIDs and pre-registration cleanup remain unproven. The trial does not fix PR #10131.
