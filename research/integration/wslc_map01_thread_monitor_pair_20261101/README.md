# MAP01 separate-connection monitor during model wait

This pair follows the [synchronous natural-pixel monitor](../wslc_map01_natural_monitor_pair_20261101/README.md), where the monitor delayed the caller's normal game-sampling loop. The research runner moves that monitor into a bounded worker using its own X11 connection, while the main thread continues sampling the game during the second model call. The monitor samples the selected 8x8 patch approximately every 25 ms only while it observes F down; a MAD above 32 requests cooperative cancellation. No overlay is injected. The fixed test cap is 500 ms, regardless of the model's requested fire duration. The model and guard receive images, not evaluator-only ViZDoom counters.

In de01 at least one normal pending-game sample was timestamped between the first and last monitor crops. The cancel request returned without asserting release; the action's separate release receipt verified no keys/buttons down approximately 4.95 ms after the request. The incomplete wait explicitly retains `failed_op_effect` as unknown because input had already begun. The monitor worker finished and joined, both owner closes verified neutral release, final tested keys were up, and both host sessions closed. The simulator recorded one hit and 15 damage in each episode; the monitored episode also recorded one hit and one damage taken by the final sample. These are evaluator counters from the same simulator, not independent physical or causal proof.

The separate-connection run's first sample gap was close to this pair's no-monitor observation and shorter than the previous synchronous monitor's 944 ms observation. These are separate single episodes with different order, model/target/timing and trajectories; they are not a controlled estimate or guarantee of overhead. The changed patch may represent animation, impact, target movement or something else: this experiment does not establish semantic identity or that cancellation was strategically correct. Ten sampled crops cannot rule out changes between samples. File start/done markers are caller observations, not synchronized provider-side timestamps. The action occurred between those observed markers, not under a proven provider-level deadline.

Both original model policies requested fire; de01 requested 500 ms and de02 requested 1000 ms, capped to 500 ms by the experiment. Model call times were 3.614 / 3.658 s and 3.372 / 1.978 s respectively. Input tokens were 26,586 and 26,587; both included 20,224 cached input tokens. Output tokens were 60 and 62. Costs are unknown; this is not a general model-efficiency comparison.

Private protocol and workspace files remain local with hashes and sizes and are not independently audited. Run `audit.py` without Python optimization and with Pillow to verify hashes, model-image binding, gate stages, each monitor crop, the sampling overlap, cancel/unknown-effect/release ordering and raw game counters. WSLc used private Xvfb, network none, one CPU / 1 GiB and a pinned image; host OS, executable and model-service versions are not pinned.

This is a test-specific Python worker, not a production runtime monitor. One seed and one pair cannot establish sustained observation cadence, cancellation deadlines, broad recovery, v39 policy safety or MAP01 completion. Issues 57 and 59 remain open.
