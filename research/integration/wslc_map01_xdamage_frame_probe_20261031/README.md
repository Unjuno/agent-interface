# WSLc MAP01 root XDamage frame probe

This exploratory probe tests the spatial XDamage latch's raw input against a real, progressing Freedoom2 MAP01 window. After the existing development-selected navigation route, it subscribes to raw-rectangle DAMAGE on the Xvfb root, samples the fixed 8x8 screen-center patch and drains notifications at ten checkpoints separated by a planned 100 ms sleep plus game advancement and capture work. No model or attack is used; game telemetry is evaluation only. The window and source point are not a semantic hostile label.

| Allocation | Outcome |
|---|---|
| w01, w02 | DAMAGE creation/sync failed with `AttributeError` involving `BadRRCrtcError`; no checkpoint completed. Python recorded the error but the container process exited zero. Navigation and final releases were recorded. |
| w03 | Separately frozen follow-up explicitly queries DAMAGE version before creation; ten checkpoints completed. Version 1.1 was reported. |

In w03 each checkpoint drained one root DAMAGE rectangle equal to the entire 640x480 game-window geometry, so all ten intersected the small center patch. The recorded source-to-current patch RGB mean absolute differences were 36.542, 29.807, 0.573, 11.677, 30.094, 0.630, 0.458, 29.807, 30.094 and 0.630; nine were at or below the previously explored threshold of 32. Thus a rule that latches **every** intersecting root damage event would latch at every observed checkpoint in this one run, even where the sampled pixels differ little from the source. A damage rectangle is a redraw signal, not a claim that every pixel changed. Without a semantic oracle, this does not prove any particular notification was irrelevant or that a different policy would have been safe.

The first two attempts omit explicit version negotiation; adding it in w03 is consistent with the prior working synthetic probe and the follow-up completed, but this sequence does not independently establish the exact underlying server/library error. All three attempts are retained. Their 20 s watchdog and 5,000-event cap were fixed before execution. `status` and traceback, not container exit alone, distinguish failure from success.

This is one successful, development-selected same-seed trajectory, not a rate estimate, a comparison with a second game, a model-speed test or MAP01 completion. The planned sleeps do not define the actual frame rate: game calls, screenshots, event drains and encoding add time. Event loss, compositor and other backend behavior remain untested. The experiment supplies a practical counterexample to blindly using all intersecting root-damage notifications as semantic invalidation in this setting; a future design needs to distinguish redraws, compare current pixels where useful, and explicitly handle transient changes that occur between observations.

The isolated WSLc runs used private Xvfb, network none, one CPU, 1 GiB, Freedoom2 MAP01 skill 1 seed 991031 and 35 tics/s, and image `sha256:6150a4f3c779a51b3ac6a7d93bc1d0450803325efb7ab38ade8b1aaf79c33e25`. The read-only Python runtime subset matched the earlier fixed-patch probe; intervening main changes were research only. All specifically named containers were verified exited and removed. Action and final-close receipts report neutral releases; in w03 the keymap check was also empty. ZIPs retain freeze conditions, runner, errors, images, samples, event records and receipts. `python audit.py` (Pillow required, normal Python mode) reconstructs image hashes and pixel differences, root-rectangle intersections and recorded releases.
