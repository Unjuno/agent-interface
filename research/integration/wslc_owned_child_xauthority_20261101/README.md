# Draft: per-child X authority for owned guarded sessions

The private-display composition previously relied on changing the parent process's `XAUTHORITY` before starting an owned guarded session. That ambient setting is unsafe for concurrent sessions. This draft adds an optional explicit authority-file path to `OwnedGuardedSessionOwner`, applies it inside the spawned owner process before the bridge is created, and passes it to the prestarted cancellation-supervisor process before it reports ready. It does not change the parent environment. The explicit option currently requires the prestarted supervisor: the older cleanup path spawns helpers from the parent and has not been adapted to a per-session authority. The default, with no explicit option, preserves existing behavior.

One WSLc targeted test verified that a spawned Fake X owner and its supervisor see the specified file while the parent keeps a different sentinel. A second test created a real authenticated private Xvfb and independent target, then connected both the spawned guarded owner and a supervisor probe while the parent retained a deliberately invalid authority. This probe establishes connectivity of those processes, not successful cancellation or release. The initial test was observed failing before implementation because the constructor lacked the option; that console output is not archived.

A combined normal-mode run passed **75 tests** across the new test, existing owned-process and cancellation-supervisor suites, and the private-display tests. After that run one negative test was added to require the prestarted supervisor for explicit authority; the final targeted test file passed **three tests under `-O`**, and also passed normally in a separate local run. The two retained runs use the same production files; their test-file versions differ, and both exact versions and hashes are archived. The combined suite was not rerun after the test-only addition.

The isolated source used main `e5925b6bd99fd4ff3f8e0bda5ed4d7cc02d92c4d` and the private-display module from draft [#10088](https://github.com/Unjuno/agent-interface/pull/10088) `93ef7f4321b94ef83cdbea472cba7e85f51cfb78`, plus this candidate patch. It ran on pinned WSLc image `sha256:6150a4f3c779a51b3ac6a7d93bc1d0450803325efb7ab38ade8b1aaf79c33e25`, one CPU, 1 GiB memory limit, no network and no pull; WSLc reported swap was not limited. [raw.zip](raw.zip), SHA-256 `97b44166754f7fc323fba839f339a34a1c127b4ae8bea5859d67d644316d9377`, retains candidate sources, both test versions, frozen conditions, logs and hashes. Ephemeral X authority files are not included.

This is a draft Python-only connection mechanism, not a public MCP option or an automatic recovery system. It does not establish display ownership for every client, secure handling against other same-user processes, real input cancellation and cleanup with this authority, timeout bounds, old physical release, preserved task state, MAP01 completion or general reliability. Do not use it to retire a shared or user display.
