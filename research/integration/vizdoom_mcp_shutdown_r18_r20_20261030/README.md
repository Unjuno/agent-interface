## Effect-oracle integration boundary

The preserved R45 matched attack/coast fixture used `DoomGame` to read independent kill/death/episode fields and typed HUD ammo, but its configured game variables did not include position. R28 launches the ViZDoom binary directly through `OwnedTargetProcess`; it records only X11 device events and screen captures and has no `DoomGame` handle or independent position scorer. The earlier `vizdoom-owner-r02` diagnostic recorded the XRes window PID as the Doom child, distinct from its Python `DoomGame` launcher PID; an ancestor relationship alone is not authority to signal the child. Consequently neither R45 nor R28 proves the recovery action moved the player, and their results cannot be composed as a matched effect measurement. A valid next composition needs a pre-owned exact game process or equivalent fenced ownership, a scorer-only position channel kept out of controller inputs, and a matched neutral control with retained raw. Do not adopt a discovered PID solely from ancestry or infer movement from pixels.
