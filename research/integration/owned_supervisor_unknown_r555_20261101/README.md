# Synthetic UNKNOWN plus supervisor characterization

At commit 3a0984aef13, a pinned isolated Linux container (network none, 1 CPU, 1 GiB, source read-only) ran the named unittest; output and exit status are retained here. The test installs a mock supervisor and a synthetic unregistered-process marker, then calls close. The UNKNOWN / unverified result is returned without invoking the existing supervisor close; the asserted cleanup call fails. This establishes control flow under an injected state, not that this exact combination naturally occurs, that a real supervisor survived, or that closing it is the correct recovery ordering. Resolve the custody and cancellation dependencies before modifying the order. See the previous r554 artifact for the independently reproduced late-child bug.

## Follow-up: reachability and ordering

The mock characterization forced an unregistered process marker and an already-created supervisor together. In the normal startup sequence the owner process is registered before the supervisor is constructed, and the unregistered marker arises in the exception handler when identity cannot be established or the registered Process differs. The source alone does not establish that the injected combination occurs without an exceptional identity failure or external state mutation. The supervisor is also used for release after owner retirement (`_cleanup_after_owner_retirement`), and its `close()` acquires its own lock; simply moving that call ahead of UNKNOWN could discard needed recovery capacity or block. The characterization's expectation that close must immediately be called is therefore not an established invariant. Its red test was removed; this raw result is retained. A valid fix needs a reachable fault, explicit custody and ordering, and tests for actual supervisor and child outcomes.
