# WSLc Calc: a new value pair with an explicitly prepared pixel reference

This exploratory two-route comparison changes the earlier fixed Calc task from 731/864 to **329/517**. Before either comparison arm, a separate no-model, no-input allocation opened a prepopulated FODS, independently verified its two source values, and captured a reviewed 1280×800 reference image. That known-answer reference is a substantial setup dependency: the cue uses exact pixels, not general recognition of arbitrary values. Its source file and captured image are retained.

The two arms then started from the same blank FODS and used the same inputs, image, source subset and model (`gpt-6.1-sol`, low) in fixed order: fresh → compiled. Fresh grounded twice in one model session; compiled grounded once and ran the local two-transition method. The fresh Save point is checked, but Save itself is a scripted Ctrl+S in both routes. Each had a separate private-Xvfb Calc instance and model session.

An independent XML audit checks one sheet and **all** populated direct cells, rejecting extra or repeated populated cells and formulas; both saved documents contained exactly A1=329 and A2=517. Initial click, entry and save releases were verified; compiled's two transitions reported verified release, each session closed with a verified empty release, and independent key/button readback was neutral. The compiled runtime method receipt says `TASK_SUCCEEDED`, while its `task_success` field remains null; the saved-byte scorer supplies the separate effect evidence. Both host/container processes exited 0 and the named containers were absent afterward.

In this single fixed-order pair, compiled's measured interval was 22.10% shorter and its recorded input count 52.69% lower than fresh. The timer begins before the first model request **after** application startup and initial capture, and ends after session close and saved-file scoring; it excludes application/container startup, preparation of the known-answer reference, and final cleanup. There was no schema/model preflight in these runs. Cached input is part of input, not additional; monetary cost and provider billing are unknown. One sample per route, different route/tool behavior, fixed geometry and a known-answer reference cannot establish general speed, failure equivalence, arbitrary Calc tasks or MAP01 completion. It is not the three-arm cold/warm/invalidation/repair comparison requested by issue 57, which remains open.
