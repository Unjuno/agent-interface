# MAP01 natural-pixel monitor during a model-wait interval

This pair extends the earlier [injected mid-hold cancellation](../wslc_map01_midhold_policy_cancel_20261031/README.md) without adding an overlay. Each WSLc arm follows the same development-selected route, obtains a model-authored fire/idle policy on a full X11 image, checks its 8x8 target patch and binding, then starts a second model call. If fire is eligible, the local caller caps the proposed duration at a predeclared 500 ms and issues one guarded F-key hold while the second call's start/done markers are outstanding. The original model proposals requested 1000 ms; 500 ms is the test's cap. Evaluator-only ViZDoom counters are never supplied to the model or guard.

| Allocation | Local handling | While F was down | Ammo before / after model wait | Hits / damage before → after | Result |
|---|---|---|---|---|---|
| dd01 normal | no mid-hold monitor | no monitor captures | 50 / 48 | 0 / 0 → 1 / 15 | action completed, neutral release |
| dd02 monitor | sample selected 8x8 patch approximately every 25 ms while F is observed down; request cooperative cancel if MAD >32 | 18 retained crops; all observed MAD 0; no cancel requested | 50 / 48 | 0 / 0 → 1 / 15 | action completed, neutral release |

Both policies were fire, both initial and input-stage patch/binding gates accepted, and both actions finished and released before the caller observed the second model-done marker. These markers are host-file observations, not synchronized provider-side timestamps. Both host sessions closed and final tested X keys were up. The simulator hit and damage counters are not independent physical evidence. There was no wait-only arm, so this pair does not isolate whether the attack caused the counter changes. No monitor cancellation happened: the result does not test cancellation latency or prove that natural changes are always detected. Exact equality of 18 sampled patches cannot rule out changes between samples, changes elsewhere, or a change in the target's meaning.

The monitor runs synchronously in this research caller before its normal model-wait sampling loop. The interval from the recorded `second-pending-start` game sample to the first `pending-2` sample was 230 ms without the monitor and 944 ms with it. These are two single observed intervals in different episodes; they are not a statistically isolated overhead estimate. They do reveal a concrete integration concern: this monitor structure delays that caller's normal sampling while it polls. Monitor sampling and model/scene observation should be decoupled and then measured under the same effect and release gates.

The first and second model call times were 4.125 / 2.101 s in dd01 and 3.796 / 2.243 s in dd02. Input tokens were 26,623 and 26,613; cached input was 12,032 and 20,608 respectively and is included in input. Output tokens were 98 and 88; reasoning output is a subset. Cost is unknown. This is one fixed-order, one-seed pair with differing model-selected target points, independent sessions and cache/trajectory differences, not a general speed or accuracy comparison.

`public.zip` retains the frozen 315-file candidate, conditions, model images/responses, all 18 monitor crops/timestamps, evaluator samples and action/release receipts. Private model protocol and workspace files remain local with hashes and sizes and are not independently audited. Run `audit.py` without Python optimization and with Pillow to verify hashes, model-image binding, gate stages, crop differences, action/marker/release ordering and raw sample counters. WSLc used private Xvfb, network none, one CPU / 1 GiB and a pinned image; host OS, executable and external model service versions are not pinned. This test does not establish semantic target identity, continuous monitoring, v39 policy safety, MAP01 completion or overall project completion. Issues 57 and 59 remain open.
