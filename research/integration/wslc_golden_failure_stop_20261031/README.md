# WSLc integrated caller incomplete-task stop

The persistent caller previously attempted the next scheduled reuse task even when the prior cold task failed without a reusable target. It navigated the next task and raised `reuse route requires cached target`, without finishing the independent effect evaluation. An incomplete operation can have an uncertain external effect, so the runner now stops the arm before any next task, completes the independent evaluation, and retains reconciled task details. The three-arm entry point saves an incomplete report and stops before later arms if the arm is incomplete or the independent evaluator fails. It does not automatically retry an uncertain operation.

The first regression failed before the change; three targeted unit tests passed in normal and optimized Python. One fresh WSLc Chromium trial intentionally supplied the previous wrong fixed point: task 1 failed, its release receipt was verified empty, no task 2 was attempted, the independent evaluator recorded zero submissions and failure, and reconciled task details were retained. All 2030 frozen source hashes matched and the exact container ID was absent. The raw archive was ZIP-verified.

This proves one controlled stop case, not successful task recovery, cancellation fencing, model/provider efficiency, or general safety. The injected point and usage are synthetic. The tested copy of the caller client additionally names the installed Chromium path; the change itself is in the integrated runner. The final main-entry check was strengthened after the live run to reject a failed sixth task even if the independent evaluator reports success; this later change has unit coverage.
