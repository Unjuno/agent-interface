# P08 preregistration — stale target-generation refusal after real model wait

Status: preregistered before any provider call. P06 and P07 remain immutable and are not replayed. The exact public observation supplies `process_generation` and no `window_generation`; this trial tests the exposed process-generation guard only.

## Question

After one real Codex App Server vision turn selects a target from the exact public observation, will the standard public compiled caller refuse the model-derived action if the Fake X process generation changes before dispatch, with zero input and no application effect?

## Frozen conditions

- One trial, one model generation, no retry or recovery. Model `gpt-6.1-sol`, effort `low`; retain the App Server protocol turn and usage update.
- Current-main source is the exact repository commit recorded in `PRELAUNCH.json`. Windows CPython 3.13.14; same-process public MCP server and `RecordedPublicMcpCaller`; child-owned Fake X transport.
- The public observation image is the image shown to the model. It depicts three small labeled colored targets. Prompt names the green target but supplies no coordinates, alias, profile, or compiled action JSON.
- Model output schema contains only a two-integer `point`. The adapter passes it unmodified through public `interface_guarded_mint` using the observation's exact source sequence.
- Immediately after the provider response and before mint dispatch, the adapter writes one unique invalidation marker. The child-owned Fake X changes its reported process generation from `a*64` to `b*64`; the prior observation and minted reference remain bound to `a*64`.
- The standard public `interface_guarded_compiled` method then receives its ordinary one-transition click profile. The required refusal is `SAFE_YIELD` / `association_changed`, zero completed transitions, one `admission_refused`, zero owner key/button press events, no effect receipt, byte-identical initial/final application state, and verified all-up close. Any dispatched input, effect, uncertain provider receipt, or failure to distinguish generations is FAIL/HOLD. No retry or recovery.
- Freeze the first outcome. No WSLc, Docker, physical input, or unrelated user application. This is a real-model stale-generation refusal check on synthetic Fake X, not live GUI, MAP01, task completion, matched efficiency, or reliability evidence.

## Decision rule

`PASS_STALE_GENERATION_REFUSED_BEFORE_INPUT_FAKE_X_ONLY` requires one completed turn with protocol-matched usage; exact observation image hash; a valid model-selected green point; pre-action change from observed generation `a*64` to fresh generation `b*64`; exact mint/source sequence; public compiled result `SAFE_YIELD` / `association_changed`; zero completed transitions and zero owner input events; unchanged pixels/no effect; neutral close receipt; complete all-attempt ledger; and raw hashes/audit passing. Runtime `task_success` remains null.
