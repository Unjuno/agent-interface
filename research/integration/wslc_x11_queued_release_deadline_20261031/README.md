# WSLc Xvfb: flushed release request across cleanup deadline

Three fresh WSLc allocations used main-equivalent runtime 6e7a5d6860f0f4f5ccdd631e8fd528507a3a5119, private synthetic Xvfb, the pinned image, one CPU, 1 GiB, no network and a 30-second outer timeout. As in #9866, a test worker pressed button 1 while holding the server and was retired by an existing prestarted supervisor at its deadline; the parent observed the button down. A second prestarted supervisor ran a **test-specific**, already-connected X11 cleanup worker, not the production `x11_cancel_worker`. A pauser process SIGSTOPed the private Xvfb and verified `/proc` state T; the worker then issued and flushed a ButtonRelease request and blocked in sync. The pauser resumed Xvfb after one second.

- A01, 2.5-second cleanup deadline: the server resumed while the worker was alive; it synced, read button up, and the target observed press then release. No fallback was needed.
- A02, 0.5-second cleanup deadline: the supervisor returned UNKNOWN / transaction_deadline and retired the worker. After server resume the button was still down and the target had observed only the initial press during the bounded observation. The harness explicitly released afterward. This trial did not record a precise supervisor-return timestamp before waiting for server resume.
- A03 repeated A02 with that timestamp. Recorded order was server stopped, client flush returned, supervisor returned UNKNOWN with worker retired, then server resumed. During the bounded post-resume observation the button remained down and the target saw no release; the isolated fallback then released and verified neutral input. The original worker's scheduled late-action artifact was absent after its scheduled time.

An independent aggregate audit verifies the recorded ordering, control, event/readback states, owner and cleanup retirement, and fallback. A client-side flush is not proof that the X server processed or durably accepted the request; this is one controlled timing and cannot establish that queued events can never arrive late. The test-specific cleanup worker omits the production worker's XRes ownership checks and is not a replacement for it. Frozen inputs and 305 runtime hashes matched; all containers were absent and ZIP integrity passed. No real app, model, product-level release guarantee or MAP01 completion is claimed.
