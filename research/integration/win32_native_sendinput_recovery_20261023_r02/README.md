# Native Win32 SendInput recovery discriminator R02

This one-shot experiment uses only a user-owned local Windows PC, two disposable `fixture_app` windows, a single CTRL key, and one fresh fixture for a public-MCP task effect. It does not use WSLc, Docker, or any other application window as a target. Conditions and source SHA are frozen in `conditions.json`.

The experiment exercises the existing `OperationOwner` and `OperationCancellationSupervisor` with production Win32 `SendInput` and `GetAsyncKeyState` calls. In the first schedule the producer pauses before calling the real send. In the second, it pauses after the real send accepted CTRL-down but before returning to `key_state`, leaving the producer's in-memory held-key ledger uncommitted. The supervisor must close admission, retire that exact producer, and only then run one recovery-UP helper. A separate helper observes the state through the frozen 1500 ms horizon. The public stdio-MCP task then uses a newly created fixture generation and an independent fixture file/journal oracle.

The stall is deliberately outside the Windows API call. This isolates accepted-before-return and retirement/recovery ordering with real desktop input, but does not reproduce an OS thread blocked inside the kernel's `SendInput` implementation. It cannot establish hard real-time behavior or general safety. A missed identity, foreground, input-state witness, deadline, helper receipt, or task effect remains UNKNOWN/FAIL; the runner does not retry or replay and only closes/kills processes it created. If a terminal UNKNOWN remains after the supervisor thread and exact producer have stopped and the same fixture still independently reports CTRL down, a separately recorded parent safety-UP may restore the fixture desktop. That cleanup never promotes the experiment outcome.

The runner, auditor, conditions, and this protocol are committed before the one-shot. Raw reports and independent audit are committed separately with a SHA-256 manifest.

R01 stopped before either fault schedule because the spawn child re-imported a module-level output guard and exited before helper readiness. R02 moves the guard into `main()` and runs a frozen two-helper spawn readiness preflight before any target input. R01 raw is preserved as an earlier `FAIL_OR_UNKNOWN`; R02 is a distinct attempt and output directory.
