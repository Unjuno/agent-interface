# Guardian parent-pidfd observation after final-ack failure: r526

One preregistered fixed-order synthetic pair passed its scoped checks. Each arm used in-process MCP with an experimental owned-display guarded owner and prestarted supervisor, a separate guardian ready before a held `a` input, and cancellation deliberately stalled before the actual owner cancellation method. Parent transferred pidfds for itself, the owner and supervisor; guardian checked the parent pidfd's PID against its observed parent and the prepared custody record. The record also bound MCP call ID, gate token, operation ID, owner generation, deadline and a shared key-obligations snapshot.

In the valid arm the parent verified the prepared digest, sent COMMIT and received final acknowledgement. In the ack-failure arm the parent sent COMMIT, deliberately shut down the socket while remaining alive, and classified the result `commit_unknown`. Guardian waited for the fixture-induced socket EOF before attempting its final acknowledgement; its send failed with `BrokenPipeError` before the parent's recorded pre-exit timestamp. Guardian nevertheless retained the transferred descriptors, waited for the parent pidfd to become readable, and then reported signalling and observing the owner and supervisor exit. The outside observer independently saw the owner and supervisor pidfds readable while Xvfb and a separate sentinel were alive. All acquired pidfds were subsequently observed exited in cleanup.

The archive contains preregistration, fixture scripts and source hashes, MCP metadata, prepared files, guardian stderr and receipts, observer and cleanup results, stdout and exit. Source was owned-display draft `7a131be784b6c135c78cf63e48e21ece783c5b30`; the Docker image was `agent-interface-xvfb-mcp:late-input-r19` (`sha256:bd191d30ea94871a1d3ca717252cd07a276e8ef7d1bcb4a130b63935ce075425`), network disabled, one CPU, 1 GiB and no pull. The raw check named `durable_record_matches` compares prepared bytes and hashes after fsync calls; it does not prove power-loss durability. Observation images and X authority cookies were not retained.

The socket shutdown was fixture-controlled; this is not a spontaneous communication failure or production guardian integration. Independent review identified a major custody limit: after COMMIT the prototype waits at most six seconds for parent exit, then raises and exits without retaining the obligation. A parent that survives longer can therefore lose guardian custody; neither arm tests that case. Guardian's signal/ordering is supported by its receipt and process exit by independent pidfds, not an independent signal trace. The real owner cancellation body was stalled; old release, task success and queue drainage remain UNKNOWN, and no replay is authorized. This pair does not establish adversarial authentication, guardian-crash recovery, a true blocked filesystem, hard deadlines, graceful/external MCP transport, real application success, MAP01 or general reliability. The parent UNKNOWN is not demonstrated to be a durable product custody record. PR #10131 remains blocked.
