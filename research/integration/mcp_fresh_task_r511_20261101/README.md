# MCP stopped-display recovery with a fresh target: r511

One preregistered synthetic trial on Docker Desktop Linux passed. The in-process MCP caller started a key hold on an exclusively owned private Xvfb; a target KeyPress and keymap-down were confirmed before pidfd-stopping that server and observing `/proc` state T. MCP cancellation first returned pending; the same operation ID later had a retained terminal result that authorized a fresh display after old guarded owner and display retirement. The polling observation took approximately 5048.07 ms. Old release and old task success remained UNKNOWN, and the cancellation receipt prohibited replay.

Only after that result, the fixture started a separate private display, independent target process and fresh MCP server. The synthetic target's state changed from `count: 0` to `count: 1`; its event log recorded `a` press followed by release. Independent keymap readback showed `a` up, the fresh MCP action completed, and fresh MCP close reported verified. This describes the observed interval only: it does not independently prove that no later event or old replay could occur. The raw JSON is written before final assertions and teardown; the archived test log and exit code also show the test passed. There is no separate teardown receipt.

The raw archive contains preregistration, candidate diff, exact tested fixture sources, pretrial hashes, public MCP responses, target events and state, log and exit. The trial used image `agent-interface-xvfb-mcp:late-input-r19` (`sha256:bd191d30ea94871a1d3ca717252cd07a276e8ef7d1bcb4a130b63935ce075425`) with no network, one CPU, 1 GiB and no pull. After the trial, independent review identified an abnormal fresh-display cleanup hang risk; the checked-in test was changed to use retained-pidfd retirement and avoid closing X clients while a server is alive. The archived source and hashes preserve the exact trial fixture; normal and `-O` local test suites also passed with the subsequent cleanup fix.

This is a single synthetic in-process MCP trial, after an exploratory pass, not an external MCP transport test, automatic expiry, old key-up or queue-drain proof, MAP01, hard-deadline guarantee, benchmark or general reliability claim. The target count is a synthetic effect, not proof of an arbitrary application task.
