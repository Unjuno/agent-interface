# Win32 Freedoom MAP01 — standard supervised public caller R07–R12

Six separately preregistered native Windows attempts exercised the current-main `supervised-win32` MCP stdio surface against fresh Freedoom MAP01 processes. The user's authorization covered this PC. No WSLc allocation, Docker, model, or provider was used. Each target-generation hash returned by public `interface_observe` matched the pretrial generation and was copied unchanged into the one public dispatch. These trials are not pooled as a reliability estimate.

| Attempt | Result | Disposition |
|---|---|---|
| R07 | Async server bootstrap was incorrect; MCP initialization closed before tools or observation. No dispatch or input. | Retain as pre-input setup failure. |
| R08 | Public observation and generation binding succeeded. The client saw `pending`; after it exited, the persisted action report resolved to completed with a verified release receipt and separate neutral readback. | Normal release/readback supported. Task oracle was not called; public task success remains null. A separate later capture showed 90.34% world-pixel change but is not an oracle certificate. |
| R09 | An 8 s authority lease expired at the first result reconciliation. Recovery record reported verified release and 31 ms cleanup latency, but the action row remained `running`; `interface_cancel` returned `not_cancellable`, while session close reported no unresolved call IDs. | Preserve the status mismatch and recovery receipt. No task oracle or task-success claim. |
| R10 | Normal action completion, release and neutral readback verified. Independent visual capture measured 91.32% world-pixel change and returned success, but the one-use receipt was rejected because `oracle_id` did not meet the required 32-character lowercase hexadecimal schema. | Positive effect measurement; public task success remains null. No retry. |
| R11 | Normal release/readback and independent visual task-effect receipt verified; public `task_success=true`. | Accepted receipt path names R10, while its digest matches the R11 raw artifact. The pointer mismatch is recorded and not rewritten. |
| R12 | Normal release/readback and generation-bound independent effect receipt verified; 90.3051% world-pixel change exceeded the strict 5% threshold; public `task_success=true`. | Scoped pass with evidence path and digest both matching the R12 raw artifact. |

The independent oracle waits one second after action completion, captures the same target through a fresh `Win32Backend`, and scores RGB changes in `x=0..639, y=0..399` against the pre-dispatch baseline. The verified task means only “visible forward response above the preregistered 5% pixel-change threshold”; it does not mean the level was completed. R11 and R12 are separate single samples and do not establish reliability.

## Scope and remaining work

R12 advances live standard-caller generation binding, normal release/readback custody, and an independently checked task effect. These attempts do not establish a physical release deadline, release under blocked platform I/O, recovery bounds for a blocked native producer, continuous-time stop behavior, matched efficiency, model/provider economics, or broader reliability. Continue by investigating R09's cancellation/action status mismatch and the observed producer-startup delay, then run a preregistered blocked-I/O recovery experiment under the authorized resource boundary.

Private raw packets `win32_freedoom_supervised_public_mcp_20261026_r07` through `..._r12` retain preregistrations, public MCP requests/replies, producer/session receipts, PNG/BGRA captures, cleanup records, and SHA-256 manifests. The manifests for 8, 28, 110, 36, 37, and 36 files respectively were rechecked with zero mismatches. R11's evidence-reference mismatch is detailed in its packet's `EVIDENCE_REFERENCE_RECONCILIATION.md`; R12's receipt points to its own hash-matching raw result.
