# WSLc broker: explicit host-failure signal

In the retained `wslc_three_arm_lifecycle_first_newseed_20261031` failure, the host exited after a `PermissionError` while the container continued waiting for response 006. Its model-attempt wait ended after 120.039 s with `TimeoutError`; the precise original file operation and provider outcome were not identified.

This research successor adds an atomically published `host-error.json` marker when the broker's outer loop fails. The container checks for a response first and then for that marker while waiting; a marker stops the current attempt without emitting another input or retrying a model call. The marker carries only a bounded error type and completed-call count. A malformed marker also fails closed. If the marker itself cannot be published or read, the existing separate 120 s deadline remains; neither marker nor deadline preempts an indefinitely blocked filesystem operation. The marker is not proof of input neutrality or of a provider-side outcome.

One fresh WSLc allocation, av01, deliberately injected persistent `PermissionError` **before** host reading request 006. After the host's 2 s bounded retry window, it published the failure marker. The sixth caller attempt returned `HostFailure` after 2.056 s, with no sixth response or retained model-call result and usage unavailable. The first five fixture submissions were exact, task 6 was missing, and all 42 recorded terminal releases were neutral. Both processes returned and the uniquely named container was absent in the subsequent listing. The block is intentionally incomplete; no allocation or model call was retried.

The two wait durations are observations from separate allocations, different seeds and different fault conditions. The successor injected a known pre-read failure, while the earlier `PermissionError` was uncontrolled and its exact operation was unknown. They do not establish a general speedup, actual recovery from the earlier race, or behavior when IPC itself cannot publish the signal. The 2.056 s is the caller's failed model-attempt interval, not a successful task or full lifecycle measurement. Known usage remains separately recorded; unknown usage is not zero.

`test_exchange_wait.py` checks marker handling, response precedence, malformed marker failure and the fallback deadline under normal and optimized Python. `audit.py` (normal Python with `jsonschema`) verifies the frozen source manifests, injected retries, marker, known model calls, incomplete fixture history, neutral terminal events and cleanup observation. `compare_prior.py` also audits the sibling prior packet and reconstructs both wait intervals. `public.zip` retains inputs, images, retry log, marker, outputs, task histories and timing; private model journals and workspaces are hash-indexed. Host service and omitted source trees cannot be independently re-read from the public packet. This is a research bridge test, not production IPC or MAP01 completion.
