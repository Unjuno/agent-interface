This additive protocol follows the v1 allocation, which stopped at `C01` because the raw event auditor incorrectly treated the Shift modifier KeyPress with an empty character as a payload character. The complete v1 allocation record and STOP audit remain immutable at `../caps_text_check_to_xtest_successor_v1/formal_runs/run_20261008_a01/`. No guard-arm case ran in v1.

## Current status

`FREEZE.json` is deliberately marked `PROTOCOL_DRAFT_NOT_ALLOCATED`. The revised event contract checks payload characters from nonempty `KeyPress.char` fields, requires monotonic timestamps in journal order, checks the progressive Entry value after each character KeyPress and before its KeyRelease, requires the exit row to follow input, and checks both keycode-multiset balance and valid per-key press/release chronology, including modifiers. Regression tests use the actual stopped v1 C01 record and reject a missing modifier release, terminal value/exit rows moved before input, a final value row moved ahead of its character KeyPress, and a release moved before its matching press.

## Additional auditor correction — 2026-10-08

Construction review found three false-accept paths in the draft auditor: it accepted matching `value` and `exit` rows before all key input, a final value row before its matching character KeyPress, and a key release before its matching press when keycode totals still balanced. Each was reproduced against the actual stopped v1 C01 journal; the original v2 auditor returned no errors. The auditor now requires every journal row to have an exact integer monotonic timestamp in recorded order, checks one progressive value prefix after each payload KeyPress and before its matching release, requires the single exit row last, and enforces per-key down/up chronology in addition to the existing multiset check. These corruptions are named mutation controls and regression tests. The v1 record remains unchanged. These are static/raw-record audit results only; no public dispatch or formal v2 case ran, and v2 remains unallocated pending independent review and fresh source readback.

A follow-up mutation review also found that JSON booleans could pass numeric equality checks as integer `0`/`1` for LockMask/keymap evidence, completed-operation indices, and the independent actor's state/ACK timestamp. The auditor now checks exact integer types for those fields, and four additional frozen corruption controls reject the substitutions. The v1 raw record is unchanged.

The fixture emits only `KeyPress`, `KeyRelease`, `value`, and `exit` Entry journal rows. A synthetic unknown event such as `MapNotify` was previously ignored; the auditor now rejects event types outside that set, with a frozen mutation control and regression test.
