# MAP01 hidden-HUD transfer replay

A post-hoc replay tests the exact fixed 50/49 ammunition crop templates from the earlier [HUD template probe](../wslc_map01_hud_template_review_20261031) on retained before/end images from the four [new-seed watch controls](../wslc_map01_scripted_newseeds_20261101). Both source ZIPs are pinned by SHA-256 at commit f2bd781bfb88f5d24b43cb016ad90183b2156e05. No new game, model, allocation or input is used.

The retained template-probe frames reproduce their original exact 50 and 49 matches. All eight new before/end crops match neither template and therefore return unknown. Visual inspection of the new captures shows the game view without the old status-bar HUD, unlike the template-probe frame. The adjacent simulator samples report ammo 50 before and 48 or 49 at the end, but those samples are not simultaneous with the screenshots and were not inputs to the matching rule. Mean absolute RGB differences and crop hashes are recorded; no threshold is inferred from this post-hoc inspection.

This is a useful transfer counterexample: an exact HUD-dependent recovery cue cannot report ammunition on these captures, and must remain unknown rather than claiming a value. It does not establish a general hidden-HUD detector, a false-positive rate, causal action attribution, live recovery or MAP01 completion. The two positive frames come from the template source, not independent held-out samples. Run `python research/integration/wslc_map01_hud_hidden_replay_20261101/replay.py` from a Git checkout containing the pinned commit, with Pillow and without -O; compare its JSON with result.json. The source images remain in their original archives.
