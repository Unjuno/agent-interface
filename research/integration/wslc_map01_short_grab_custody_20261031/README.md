# Prestarted cleanup after a short-grab MAP01 owner times out

This isolated WSLc composition extends #9902. A prestarted owner worker records and fsyncs its X11 resource identity, physical keycode and intended `f` release before input. It grabs the private Xvfb server, captures and compares a HUD crop on the same connection, sends key down, and ungrabs while the key remains held. A separate cleanup supervisor is already running. In `crash` mode the owner sleeps for two seconds with a deliberately scripted later release and extra attack; its supervisor's 800 ms transaction deadline retires it. The parent observes key state, then the prestarted cleanup worker checks owner disconnection and issues the recorded key release. In `normal` mode the owner releases after 85 ms and completes. This uses the existing experimental supervisor, not an integrated product recovery path; `crash` is deadline-driven process retirement, not a tested host crash.

| Runs | Mode | Owner result | Key after owner → after cleanup → after later observation | Ammo: before → after cleanup → later |
| --- | --- | --- | --- | --- |
| ac01, ac04 | normal | completed | up → up → up | 50 → 50 → 49 |
| ac02, ac03 | deadline retirement | unknown, worker retired | down → up → up | 50 → 48 → 47 |

In both retired-owner cases, the cleanup worker returned an observed key-release readback with empty tracked keys, and a separate parent keymap query also saw the key up. The receipt deliberately retains `cleanup_status: UNKNOWN`, `release_confirmed: false`, `task_success: null`, and `replay_allowed: false`: the readback does not establish complete queue drainage or owner-exclusive physical state. The worker was retired before its scripted late time and no late artifact was present after that time. This does not independently prove absence of every possible late input. Ammo was 48 in the first post-cleanup game sample and 47 at the later sample; because samples are not atomic with game updates, the exact consumption times and the original action's full effect remain unknown. An 800 ms held attack may have emitted multiple game shots; cleanup is not undo.
