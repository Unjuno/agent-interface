# Draft private-display owner: scoped WSLc checks

The accompanying experimental `PrivateDisplayOwner` launches a new Xvfb with a per-instance MIT-MAGIC-COOKIE file and retains a pidfd for its direct child. It does not accept an existing display to retire. Its retirement uses the retained pidfd and waits for the owned child; it reports `unknown` on a wait timeout. The caller must ensure the display and all applications on it are disposable. Killing the display destroys their context and does not establish a physical release on that old server.

Two WSLc checks ran both normally and under Python `-O`: the authorized client connected, a client without the authority file was refused, the retired server no longer accepted the authorized connection, repeated retirement was idempotent, and killing a stopped owned display left a separately launched display reachable. Each run reported two passing tests. The first test was observed failing before implementation because the module was absent. These tests do not establish resistance to an adversary running as the same user, or security against a leaked cookie.

The checks used pinned image `sha256:6150a4f3c779a51b3ac6a7d93bc1d0450803325efb7ab38ade8b1aaf79c33e25`, one CPU, 1 GiB memory limit, no network and no pull. WSLc reported that swap was not limited. [raw.zip](raw.zip), SHA-256 `13bd0f958bc9857e076c2dc421ade5ad5e0f6a48e6974e0c4bc8095302d5c02b`, contains the exact candidate files, source hashes and test output. Both launcher return codes were zero.

This is not connected to the guarded owner, cancellation, MCP, a target lifecycle, or recovery policy; no held-key task was run through it. Thread safety, startup-failure and timeout cleanup, cookie lifecycle and revocation, safe use under resource exhaustion, shutdown races, and ownership proof for all display clients remain unverified. Startup error handling can wait for process termination and is not a hard deadline. The broader project test suite and Windows paths were not run. Do not use this draft to terminate a shared or user display, and do not claim finite recovery, task completion or MAP01 completion from it.
