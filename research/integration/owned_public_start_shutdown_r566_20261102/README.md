# R566: public MCP observe after shutdown

On draft base `0e0aa3e5ca2`, one exploratory test used the pinned Linux Docker image `sha256:bd191d30ea94871a1d3ca717252cd07a276e8ef7d1bcb4a130b63935ce075425`, no network, 1 CPU/1 GiB and read-only source. A public `interface_guarded_observe` call entered the fake-owner spawn and was gated after child creation but before parent registration. Lifespan shutdown waited its existing worker-drain periods and returned with the gate closed. After opening the gate, the public call returned `observed`, so the regression assertion failed (exit 1, 7.254 s). The fixture killed and joined its child afterward; that is not shutdown recovery. Conditions, base, pre-run diff and output are in raw.zip.

A preceding attempt on WSL system Python failed import with `ModuleNotFoundError: mcp`; its test body did not run. The forced public-tool ordering is stronger than the prior private direct-call counterexample, but remains a read-only fake owner: it does not show late real input, GUI/task effects, release, WSLc, MAP01, frequency or reliability. The running worker was accepted before shutdown, so completion after shutdown also raises a result-publication/drain question separate from admission after closure. The test expresses a desired lifecycle contract for this draft, not an already-established guarantee.
