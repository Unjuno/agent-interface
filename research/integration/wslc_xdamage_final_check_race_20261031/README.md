# WSLc XDamage final-check race probe

This controlled private-Xvfb probe extends the research-only spatial XDamage latch. It asks whether a root-window notification drain and screenshot inside the existing `before_key_press` callback fence a later input. Both cases use the same textured synthetic target, private X11 server, source patch and scripted 100 ms F hold. The callback drains relevant root damage at each guard stage and checks the already captured patch. In q02 only, the test deliberately maps an 8x8 magenta overlay **inside the trusted final callback after its event drain and screenshot, before it returns**. This is deliberate test scheduling, not an assertion that ordinary callback code behaves this way. A direct X11 witness records the overlay; the pending event is not drained again until after the action.

| Run | Change after final drain | Guard result | Target events | Root damage read after action |
|---|---|---|---|---|
| q01 | none | admitted | F press, F release | 0 |
| q02 | overlay on checked patch | admitted | F press, F release | 1 intersecting rectangle |

In q02 the final guard screenshot was captured before the final drain, the overlay witness after the drain and before the callback returned, and the action's recorded key-hold wait began after the witness. The target queue recorded press then release. The root notification was read after that wait ended. Both action and owner-close receipts recorded neutral release and F keymap readback was up. The clean control also completed and released. These observations demonstrate a concrete check-to-input gap in this **test composition**; the current production runtime does not contain this XDamage latch. The test does not establish the exact instant the X server queued the notification, nor that the synthetic F action was unsafe.

The spatial latch helped earlier between-sample cases, but a drain before input is not an atomic fence. This experiment deliberately schedules a change within the callback and has one case per arm, in fixed order; actual concurrency, event loss, server failure, alternate backends, application semantics, resource cost, MAP01 behavior and speedup remain untested. The witness, notification reader, target and event queue share the same X server and test process; they are different observation paths, not external sensors. A future design must specify how to fence relevant environment changes through emission, or explicitly preserve uncertainty and limit the admitted operation, rather than infer continuous stability from the last drain.

Both frozen WSLc cases used the pinned image `sha256:6150a4f3c779a51b3ac6a7d93bc1d0450803325efb7ab38ade8b1aaf79c33e25`, private Xvfb, network none, one CPU and 1 GiB, and the same read-only Python runtime subset checked in the earlier MAP01 fixed-patch probe; intervening main changes were research only. Named containers were verified exited and removed. The archives retain conditions, runners, images, observation and action receipts, event records and logs. `python audit.py` (Pillow required, normal Python mode) verifies runner/image hashes, screenshot/drain/witness/callback/wait ordering, target events, later damage rectangle and neutral releases.
