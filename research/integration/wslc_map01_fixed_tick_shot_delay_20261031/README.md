# Fixed-tick MAP01 attack effect after input ends

This is a synchronous ViZDoom PLAYER-mode control experiment, not a live GUI, model, cancellation, or agent-interface benchmark. It follows the issue raised by PR #9889: an already emitted short attack can have effects after input stops. WSLc used image sha256:6150a4f3c779a51b3ac6a7d93bc1d0450803325efb7ab38ade8b1aaf79c33e25, no network, one CPU, 1 GiB memory; Freedoom2 MAP01, skill 1, seed 991031. Full scripts and raw host logs are retained. p01 failed before game launch because the default image entrypoint ran Node; p02 failed before game launch because python was not on PATH. Both failures are retained. p03 and p04 used /usr/bin/python3 and exited zero. The game engine telemetry and screen hashes are evaluator observations, not controller input.

p04 uses four fresh game episodes in fixed order idle, attack, attack, idle, each with the same scripted forward/settle/turn prefix. Prefix screen hashes and observed state match. In attack episodes, ATTACK was held for ticks 132–134 and then no button was held; ammo remained 50 through tick 134 and first fell to 49 at tick 136, the second no-input tick. Both idle controls remained 50 through tick 154. This demonstrates delayed game-side ammo consumption for this particular three-tick input, not a delayed key event or proof of an enemy hit.

p03 separately used four fresh episodes in withhold/fire/fire/withhold order. The same observable snapshots through a 3-tick attack and 70-tick no-input period matched across episodes; ammo went 50 to 49 before the final branch. A subsequent 12-tick attack led to 48 ammo, while withholding stayed at 49. All ended at 0 kills and 94 health. This is a deterministic fixed-seed reproduction, not four independent random trials, and matching recorded observations and pixels does not prove all hidden game state identical. It does not isolate causes in the prior real-time experiment, prove a hit, validate release through X11, or establish general reliability.

Run `python audit.py` to recheck the retained logs. The raw host output includes the WSLc memory/swap warning; no extra network or model calls occurred.
