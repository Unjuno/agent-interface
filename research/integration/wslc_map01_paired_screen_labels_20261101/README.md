# WSLc MAP01: paired simulator screens and label rectangles

Two preregistered model-guided recovery episodes extend the evaluator-only label study. At the fourth-frame sampling point, the evaluator saves both the ViZDoom `GameState` screen buffer and the labels from that same state. Neither is supplied to the model or action gate. The corresponding model image is captured separately via X11. In these two cases the entire 640x480 game-window crop of the model image is byte-for-byte equal in RGB pixels to the saved evaluator screen. The evaluator sample timestamp precedes the model-image request by 82.222 and 88.471 ms; equality shows identical displayed pixels in these observations, not simultaneous capture or guaranteed future state.

- ds01: the paired state showed Zombieman rectangle `(300,215,69,116)` in game coordinates. Both nominal center `(320,240)` and the converted model target `(333,274)` lay inside it. The later target-patch difference was 62.667 (>32), so recovery fire was refused.
- ds02: the paired rectangle was `(357,220,61,100)`. The converted model target `(390,269)` lay inside it while nominal center was outside. The aim-center condition and later patch-difference condition both failed; recovery fire was refused. Its earlier proposed turn also failed its own gate, so no turn was dispatched.

The original interrupted shots retain unknown partial effects and were not replayed; terminal input release was verified. These samples strengthen image/label alignment for the recorded frames, but do not validate the label generator, prove future aim or safety, establish a recovery hit, compare performance, or complete MAP01. This snapshot is not asserted identical to main; neither case is a synchronized production perception mechanism.
