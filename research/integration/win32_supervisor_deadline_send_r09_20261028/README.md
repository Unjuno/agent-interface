# Candidate Win32 supervisor deadline-send R09

R09 is a fresh run after the candidate also applied deadline-aware sends during helper shutdown; earlier R08 evidence remains unchanged. The pinned contract validator and obligation derivation produced 63,488 Unicode obligations from a six-operation synthetic program; the protocol-shaped request was 952,830 bytes. This is contract validation and derivation, not full runtime admission.

Against a real Windows pipe and a separate non-reading owned peer, the candidate supervisor returned `TimeoutError` after its 200 ms deadline rather than remaining blocked at the observation point, marked the helper unavailable, and the worker and peer exited. Exact source snapshots, environment, stage traces, output streams and hashes are retained. Process inspection found neither worker nor peer PID remaining. The trace recorded exchange completion 3 ms after the deadline on this run; it does not establish a hard bound. Identity was a fake constant and cleanup grace was zero.

The retained 30-test normal and optimized local runs include an actual pipe to fake recovery helpers: a small request reaches a fake release helper, and an extreme timed-out request remains UNKNOWN without the delayed fake release. They do not prove real keyboard/mouse release, application effect, or absence of a message accepted before cancellation. Serialization, OS calls, receive, and process retirement are not proven bounded. No GUI, game, model, native keyboard/mouse input, WSLc or Docker was used.

The probe imports the candidate runtime from `PYTHONPATH`; reproducibility requires matching its recorded candidate hashes and using a fresh output directory. Baseline test and owner snapshots preserve Windows line endings and match main after newline normalization.
