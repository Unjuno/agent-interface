# Calc model-grounding pilot with aligned guard and task clock

This follows PR #9879's fixed-task pilot. Two fresh WSLc allocations were prepared together and run sequentially: c06 compiled continuation, c07 a scripted second fresh-image model grounding before save. Both use the exact same runner and host bytes, blank fixture, reference image, pinned container, one CPU, network isolation, model `gpt-6.1-sol` low and main runtime at `ee9eb06a41312e17414e7e450790e96fc1fb942f`. The host model process has network access; the container does not.

The earlier scripted route did not register direct input with its session owner and used a different pixel guard. In both new runs the caller records its input dispatch with the owner; the close receipt confirms a separate release attempt and neutral state. The new scripted Save path additionally arms the same `SemanticSaveGuard` class and checks the saved cell regions and context at the guarded input boundary. The compiled graph retains its own composition and cue association. Using the same guard class is not proof that the implementations or fault coverage are equivalent.

| compiled c06 | 1 / 1 | 12,201 | 78 | 12,279 | 7,559.409 ms | 1,021.321 ms |
| fresh c07 | 2 / 2 | 24,402 | 140 | 24,542 | 12,774.574 ms | 7,410.780 ms |

The task interval uses a single container monotonic clock, from immediately before the first model request to after owner close and saved-file read/score. It excludes container/app startup, initial capture, final process cleanup and archive writing. Each extra fresh grounding starts its own model session. The post-first-grounding phase excludes the common first call and A1 click; it includes the extra model call in c07. The input-plus-output calculation does not add cached input or reasoning output a second time (both were zero here). In this single pair the compiled arm used 49.97% fewer such tokens and the measured interval was 40.82% shorter. Fixed order and variable provider timing make these descriptive, not a population estimate or full operating-cost comparison.

Both snapshots independently contain A1=731 and A2=864. Each operation's receipt confirms release; close also attempts and verifies release. The compiled graph's saved-file verifier reports success; the fresh script's saved effect is independently checked after close. Both validate the model-proposed Save location against reviewed bounds but send Ctrl+S via a fixed stable anchor. This remains a known fixture with hard-coded actions, not a general agent baseline. No stale-target, model ambiguity, missing data, warm reuse, adversarial guard, MAP01 or safety-equivalence test is established. One observation per arm is not enough to assert a general speedup, reliability or price savings.

`python audit.py` checks input/source hashes, model response and usage/image association, matching scripts and fixture, release records, timing order, the armed semantic guard, and saved FODS values. Raw top-level inputs, images, receipts and outputs are archived; private nested journals remain local and are represented by SHA-256 and size. Runtime and host-source hash manifests for the identical source set are retained in the preceding pilot. No experiment was discarded or repeated within this pair.
