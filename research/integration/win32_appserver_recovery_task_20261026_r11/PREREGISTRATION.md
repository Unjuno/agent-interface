# R11 preregistration: AppServer-grounded continuation after bounded recovery

R11 is a new, one-shot extension of R09. It must not modify or replay R05–R10. It pins the host runtime to Python 3.13.14 because the bounded AppServer pipe client refuses Windows Python versions below 3.12. Freeze `conditions.json`, `run.py`, `audit.py` and this preregistration in `PRETRIAL_SHA256SUMS` before launching either fixture.

## Question

Can the standard compiled Win32 caller complete one harmless task after bounded input recovery, when its click coordinate comes from one real AppServer model decision grounded in a fresh observation of the new target generation?

## Fixed protocol

1. Create one owned fixture, observe a real SHIFT-down, then block the fixture producer at the preregistered Python callable before native `SendInput` for SHIFT-up. Cancel exactly once through public MCP. Require retained `recovered / release_confirmed=true`, same-generation native SHIFT-up, and cleanup latency below 3 seconds. Stop before phase 2 on any failure.
2. Close the recovery session and retire its exact fixture. Create a new fixture with distinct process ID and target generation. Require the stale-generation public probe to return `TARGET_GENERATION_CHANGED` with `input_dispatched=false` before task input.
3. Capture exactly one 400×180 public observation on the fresh generation. Give its image to one `gpt-6.1-sol` AppServer turn at low effort with a strict integer `{x,y}` schema and fixed bounds 24–300 by 24–150. No input is allowed if provider execution fails, the schema is invalid, or the point falls outside those bounds.
4. Run exactly one `run_public_compiled` action on that generation using the returned point, type only `office`, save only within the disposable fixture, and release all input. Require the first compiled caller observation after the model turn to preserve the grounded target generation.
5. Require retained action release, independent native readback of SHIFT/CTRL/S/left button all-up, one exact click/six character/save event sequence, a fresh post-dispatch observation after response return, exact fixture effect, and `interface_verify_task` success bound to the exact call, operation, oracle and generation. Retire the fixture and restore the original foreground window.

## Evidence and disposition

Preserve all attempt artifacts and first outcomes. Hash the raw runner output, AppServer protocol journal, provider request/response, image, public observation/action/oracle records, fixture events/effect, cleanup receipts and pretrial files. Report AppServer token usage and latency, but state that the app-server journal is not independent upstream billing evidence and image token use may be unavailable. One sample is not an efficiency or reliability estimate.

The block is injected before native `SendInput`; do not claim an OS/kernel hang or arbitrary-I/O guarantee. This run uses only the owned Windows fixture. Do not query or operate Docker, global WSL, or WSLc. Do not rerun R11 after its first attempt, regardless of outcome.
