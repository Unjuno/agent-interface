# WSLc fixed-image template-score microbenchmark

Allocation dy01 compares the shadow matcher's scalar Pillow loop with a NumPy vectorized calculation on the *same* archived dx01 source and checked X11 images. The checked frame contains a synthetic gray intervention. Both calculate the absolute RGB differences for every 16x16 template position on the same 61×81 grid. The original archived model and action run is not repeated; no model or input is dispatched here.

After one warmup per method, 12 trials alternate method order on one CPU. The scalar median was **160.590 ms** and the vector median **3.890 ms**, a 41.29× ratio for these measured calculations. All 4,941 integer score sums were identical in every trial, including best candidate `(672,586)` and the spatially distinct runner-up. The vectorized 16-bit window tensor alone represents 7,589,376 bytes, excluding other arrays and runtime overhead. Python 3.11.2, NumPy 1.26.4 and Pillow 10.2.0 were recorded.

This is one warm, fixed-image microbenchmark, not an end-to-end control speedup. Image capture, input conversion to the prepared NumPy region, model calls, process startup, safety gates, release and recovery are excluded. The visual matcher remains shadow-only: identical scores do not establish target identity or make its provisional acceptance rule safe. Different image sizes, boundaries, load and memory pressure remain untested. No MAP01 completion or production-readiness claim follows.

`public.zip` retains input images, preregistered conditions, benchmark source, all raw timings and score sums. SHA-256: `4dea8c60801c250acc988159ed75c1ea6a5c8d2180226eb132e333d4a77d23f4`. Run `python audit.py` without `-O` (Pillow required) to verify the archive, pinned prior dx01 image provenance, independently recompute every scalar score, and check recorded summaries and timings. Timing is a recorded measurement, not independently reproduced by the audit. WSLc reported no active allocation after the command exited.
