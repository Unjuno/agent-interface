# WSLc Chromium: preflight-through-process-exit lifecycle comparison

Three prospectively frozen allocations run the existing six-task Chromium fixture with `gpt-6.1-sol` low, in fixed order plain → persistent → ephemeral. Each gets its own model session, WSLc container, Xvfb, application and 1 CPU / 1 GiB; containers have no network and the host supplies model calls. Each performs a separate schema preflight, whose response is independently JSON Schema-validated before the GUI container starts. The persistent route includes cold, reuse, invalidation and repair; the old reference was rejected with no pointer admission before repair.

A single Windows host `perf_counter_ns` measures from immediately before launching the preflight/model-host process until **both** the WSLc container and model-host processes exit. It includes preflight, local schema validation, container/Xvfb/app startup, six tasks, fixture scoring, process cleanup, and orchestration polling and timing-file writes. It excludes Python launcher startup/imports, prior source hashing and preparation, image build/pull, post-run archive/audit and any unrelated wait before the timer. The model-host exit is not a separately observed proof that every remote provider resource is reclaimed. This is a defined lifecycle interval, not a universal end-to-end product benchmark.

| Arm | Lifecycle | Model calls: preflight + tasks | Input tokens (cached subset) | Output tokens | Exact tasks | Verified terminal events |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| plain | 42.731 s | 1 + 6 | 104,105 (74,112) | 491 | 6/6 | 18 |
| persistent | 34.672 s | 1 + 2 | 36,859 (12,288) | 395 | 6/6 | 57 |
| ephemeral | 43.408 s | 1 + 6 | 105,575 (75,392) | 873 | 6/6 | 48 |

For this single fixed-order run, persistent's measured lifecycle was 18.86% shorter and its input-token count was 64.59% lower than plain. Cached input is already included in input; provider billing/cost is unknown. The persistent path also generated more locally recorded terminal events. All recorded terminal events reported neutral release, and all three fixture histories contained each exact submission once. Post-run WSLc listing returned successfully and found none of the three uniquely named `--rm` containers; the retained summary is an observation of that listing, not an independent container-runtime proof.

Each arm is one sample, with different phases, provider timing, cache state and sequential order. The plain and persistent pathways do not establish equal behavior under all faults. The existing fixture and experimental shared-volume bridge are narrow; no general speed, cost, reliability, human-tempo or MAP01-completion claim follows. The schema preflight is the direct-executable successor used in the prior WSLc study, not the older preflight gate. The source snapshot is the previously frozen a04 snapshot; the main SHA in conditions is an integration reference, not a claim that the snapshot matches every current-main byte.

The first allocation, aq01, failed during preflight setup because the old WSL-only path converter was called on Windows; the client initialized but no model turn or GUI container began. It is hash-indexed and summarized as a failure. Successor allocations ar01–ar03 used an explicitly Windows-native path converter and new frozen conditions; no failed allocation was rerun. The input source/host-source hash manifests were checked before and after the block; the source trees themselves and model protocol/workspaces remain local, with private-file hashes retained. The hosted model service and all host dependencies are not frozen.

`public.zip` retains conditions, executable harness, source hash manifests, timing events, preflight outputs, model call results and image hashes, GUI artifacts, independent submission histories, runtime terminal events and cleanup summary. Run `python audit.py` without optimization and with `jsonschema` installed. It revalidates schemas and image/response usage, task histories, timing order, neutral terminal events and source-manifest relationships. The auditor checks the recorded source-tree verification but cannot re-read the omitted source trees or excluded private protocol logs; it does not establish provider billing or independent pixel interpretation.
