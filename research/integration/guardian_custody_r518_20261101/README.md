# Independent guardian custody prototype: r518

One preregistered fixed-order pair in an isolated Docker Desktop Linux container passed its scoped checks. A disposable parent transferred a child pidfd to a separate guardian and received a readiness acknowledgement. In the committed arm the guardian acknowledged the handoff; the observer independently pinned the child before allowing the parent to exit via `os._exit(0)`. After socket EOF, the guardian signalled the transferred pidfd and observed that pidfd readable; its token/PID receipt matched the parent's. In the uncommitted control, guardian reported no signal and the pinned child remained alive until fixture cleanup. An unrelated pinned sentinel remained alive in both arms. Parent startup-through-exit observations were approximately 58 ms and 51 ms, respectively; these are individual fixture measurements, not a performance benchmark.

The raw archive contains preregistration, scripts, pretrial hashes, parent output, guardian receipts, observer results, test log and exit code. Image `agent-interface-xvfb-mcp:late-input-r19` was pinned to `sha256:bd191d30ea94871a1d3ca717252cd07a276e8ef7d1bcb4a130b63935ce075425`, network disabled, 1 CPU and 1 GiB. Cleanup used pinned pidfds for remaining test processes; no test container remained.

Independent fixture review found limits in the PASS predicate and cleanup. The committed-arm predicate did not explicitly require `signal_sent=true`; the raw receipt does record it for this sample. The observer's initial parent-output read relied on the outer timeout, and an early failure before pidfd acquisition could leave test children untracked until container removal. Cleanup signalled remaining acquired pidfds but did not wait for all such exits, and did not independently verify guardian termination. Therefore the archived result does not prove complete process cleanup.

This prototype handles only a disposable sleeping child, not the repository's owner or cancellation supervisor. It does not issue or verify input release, prove X request drainage, preserve a real MCP cancellation record, test a stalled writer, authenticate an adversarial peer, cover crash boundaries, or establish hard deadlines or general reliability. Receipt creation occurs after retirement in this fixture but is not isolated from a stalled filesystem. The uncommitted control only demonstrates that this particular guardian omitted its signal before observer cleanup. A successful `poll` on the pidfd indicates process exit, not application task completion. This is evidence for a possible custody seam, not a production implementation or a resolution of PR #10131.
