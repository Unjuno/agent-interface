# Direct Calc integration with fixture grounding: R585

One fresh isolated WSLc container ran the archived direct Calc runner on current staged runtime through the experimental ContainerDriver. A host thread supplied fixed, reviewed coordinates for two image-hash-bound requests; it was not a model and produced no usage or token measurements. The runner detected an overlay pixel change before creating mint/program artifacts, reobserved the target, entered 472 and 615 and saved the FODS. Independent host XML parsing of the saved file found exactly those populated cells. Each of click, entry and Save had a nonempty verified release with empty key/button lists; owner close had verified neutral release and a later X readback had no keys and no buttons 1–3 pressed. Exit 0, input/source hash stability and identity-verified container removal were recorded.

Conditions, exact driver/runner source hashes, host scripts, independently checked results and the saved FODS are retained. Full journals, screenshots and action receipts remain private locally because they include host paths and environment; their hashes are recorded but do not make them independently accessible here. A separate reviewer matched 168 source/input hashes, all 37 running/final inspect identities, two cleanup inspect identities and the journals.

This is one fixed-fixture direct-route engineering trial, not a model call, three-route comparison, efficiency score, parent-death test, full recovery proof, or MAP01 result. The overlay gate detected a pixel difference before mint; it did not pass a stale capability into the runtime to observe rejection. The independent FODS audit is separately executed XML parsing; it does not independently prove the GUI effect caused the file contents. Host elapsed time and container task/method timings are different intervals and use separate monotonic clocks. Synchronous teardown is not proven bounded.
