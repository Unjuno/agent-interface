# Public stdio MCP live Win32 effect R02

This is a new, one-shot public `runtime.cli_v1.mcp_server` experiment after the Win32 capture-artifact repair at source commit `a8117c3f7ff1d3e5c4bf2055b9f8ad58c7ec268b`. It creates one owned, visible fixture window, uses the public `interface_observe`, `interface_validate`, and at most one `interface_dispatch` call, then independently reads the fixture effect JSON and event journal. Exact conditions and frozen auditor are included here before execution.

The experiment is scoped to basic live effect and final input release. It does not prove target-generation admission fencing, blocked-I/O release bounds, supervisor recovery, provider/model efficiency, MAP01, or reliability. A timeout or uncertain outcome is never replayed. The probe closes only its owned fixture process/window and retains the raw report.
## R02 outcome and harness defect

The public `interface_observe` call returned a successful 300x140 observation and wrote a PNG whose source raw-pixel SHA-256 matches the observation receipt. This confirms that the capture-artifact repair is reached through the standard stdio MCP observer. The attempt then stopped before validation or dispatch because the probe serialized MCP `ImageContent.data` as though it were bytes; this SDK supplies a base64 string, so the recorder raised while building the response record. No input was dispatched, no task effect was attempted, and no release result exists. The owned fixture was closed and exited with code 0. The raw receipt is immutable and records `UNKNOWN`; do not replay R02.

The receipt also records `source_commit: UNSET` because the invocation did not set the optional environment variable. Conditions still pin the source to `a8117c3f7ff1d3e5c4bf2055b9f8ad58c7ec268b`, so the auditor correctly fails this provenance check. The frozen auditor has a weak `exact_event_count` predicate (`None == None` can pass when no event oracle exists); its R02 output is therefore a conservative failure summary, not sufficient evidence of event correctness. The R03 harness will store the SDK-provided base64 string directly, default source provenance to the frozen condition, and use a stricter auditor that requires an actual integer event count and successful observation before any pass.
