## Why this experiment, not another parser/retention experiment

A14 has a method-valid actual counterexample: requested hdv/actual TARGET dv
was returned as observed TARGET hdv + NO_REPAIR. The original source, answer,
H_FAIL and all72 files remain immutable. A12 separately established a finite

Neither result establishes the joined live model/guard/result/recovery flow.

The integration decision is whether the existing image review boundary can
stand alone before Save/task completion, or whether a later current local

This directly addresses #5260's review assumption and #57/#2789's guarded

## Proposed comparison (not yet allocated)

Hold requested model/effort, task, frozen image, desired result and scorer fixed.
Compare the image-only downstream route with current-local-guard plus one
bounded conditional recovery route. Preserve rich-model semantic intent:
local code may validate/invalidate; it must not silently replace an invalid
model answer with its own repair plan.

For each fresh task pair, two independent private Tk apps receive identical
stimuli and produce pixel-identical model-visible frames. Use one first actual
model answer per pair, bound to those identical images, explicitly shared
across downstream arms. Do not report it as two independent calls/answers.
Each arm has distinct app PID/token, output, input trace and exclusive task file.
Reject unequal initial pixels as METHOD_STOP; do not pool historical A14 rows.

Image-only control:
- A completed NO_REPAIR can proceed to its private Save endpoint without typed
  text reconciliation; score the resulting file independently, even if wrong.
- INSERT_PREFIX can execute only that proposed prefix and then private Save.
- REFUSE emits no task input/Save. Transport/tool/schema failure stops the pair.
This deliberate private control is not a production route or public desktop input.

Guarded route:
- After observing model completion, request a new nonce/sequence-bound actual
  app snapshot and fresh target-focus evidence; never treat the old screenshot
  or model answer as current admission.
- Compare the answer's literal field observations/decision to the current
  task state. A wrong NO_REPAIR cannot finish the task or Save incorrect text.
- Inconsistent semantic observations YIELD. If prospectively configured, allow
  at most one NEW recovery decision using later original pixels plus the actual
  typed discrepancy. Preserve the first wrong response; this is a changed-evidence
  semantic recovery, not transport retry, answer replacement or row exclusion.
- A focus-only change may use one explicitly configured A12-style recovery click
  plus a NEW bound ACK, never reuse old admission. No unconditional full-text replay.
- Every recovered proposal needs another current local admission before input,
  and exact independent task-file reconciliation before task completion.

Candidate residual set: intact, missing-first-prefix, wrong-recipient and
post-model focus drift; exact payloads/layout/order/allocation must be newly
chosen and frozen, not the four A14 payloads. Ambiguous text must refuse/YIELD;
consider a fifth pair only if required to exercise the actual joined contract.
No claim of general held-out or load robustness from this finite set.

## H / T / D / C / U

H: current independent task reconciliation prevents image-only false completion,
while a bounded changed-evidence rich-model recovery can restore a task without
wrong-recipient input. This may fail on actual model recovery, fresh admission,
endpoint effects or liveness; retain those failures, not merely safety PASS.

T: freshly frozen paired live apps, same first model answer/images per pair,
actual XTest input/received event traces, later local observations, independent
exclusive task-file endpoint, maximum one first call + one conditional semantic
recovery call per pair, no transport retries. Fixed schedule, all cells retained.
Use eligible pinned local WSLc container/private display; host cloud model
separate. Container/app must stay alive during real model latency.

D: independently reconstruct source/identity/image/prompt/process/clock joins,
each arm's actual post-answer inputs and saved file, every YIELD/refusal,
recovery model boundary, fresh sequence/ACK and final result. Report paired
actual task correctness, false completion, wrong-target count and recovery
cost. Do not call the integrated hypothesis PASS on safety-only refusals:
predefine required actual successful endpoints and explicitly distinguish
safe unfinished task from completed task. Missing custody is STOP/UNQUALIFIED.

C: cooperative instrumented private apps, shared first answer across arms
(not independent sampling), controlled partial input/drift, fixed fonts/order,
application-owned text/focus oracle, no general public sensor or hardware proof.
Shared-answer costs must be counted once, extra recovery separately. No causal
model-speed/price/population/human-tempo or effective-resource-enforcement claim.

U: actionable admission/effect/recovery boundary for integration, not another
evidence-only default. Consume only after scope-compatible independent review;
do not change main runtime defaults without current shared-entry revalidation.
Preserve all prior PASS/FAIL/STOP and keep the full #57/#59 roadmap open.
