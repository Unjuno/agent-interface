# Live MAP01 action during a pending model call

A fresh two-arm exploratory pair follows the development-selected route in `wslc_freedoom_map01_threat_route_20261031/e07.zip` through the first turn, where a Zombieman is visibly labelled by the game. Each allocation uses the same pinned image and current-main runtime at `822c9ef811cedd65fe89d03cfa5306586497f034`, Freedoom2 MAP01 skill 1, seed 991031, private Xvfb, one CPU and no container network. A Windows host prestarts a `gpt-6.1-sol` low model session; it receives only the synthetic screenshot and a request to locate the visible enemy and image center. The returned points are recorded but do not select or aim the action. Game-state telemetry is recorded for evaluation and is not passed to the model or policy.

In f02 the first game-sampled kill appeared at tic 198 while the caller was still polling for the model-done marker. The fire operation began after the caller observed the start marker and finished before it observed the done marker; its key-up and final owner-close release were verified, and final checked keys were neutral. Model output was not applied to the game. The endpoint timing is established by container-side observations of host-written files: the started marker is written immediately before calling the model adapter and the done marker immediately after it returns. It is not a synchronized provider-side timing trace, and filesystem notification delay is not bounded by this test.

This is one fixed-order sample per arm on a route selected using previous exploratory data. Kill count and visible labels come from the same game engine, not an external physical sensor; the pair does not prove which actor caused the scored kill or a statistical/causal benefit. Both arms lost no health, so no reduction in damage is demonstrated. The local fire was a fixed open-loop pulse, not the v39 threat policy, not model-authored, not conditioned on the model response, and not a test of stale-policy cancellation, ammo depletion, recovery, broad reliability or MAP01 completion. No claim is made that the model's returned coordinates are correct.

Each archive retains frozen conditions, scripts, game telemetry, input receipts, synthetic screenshots, model request/response and per-call usage. Nested private model protocol journals remain local and are represented by SHA-256 and size. `python audit.py` verifies both attempts, source/image/call/usage associations, game-tic advancement, observed marker ordering, action release, health and kill records. Model cached-input and reasoning-output counts are subsets of input and output totals and are not added twice.
