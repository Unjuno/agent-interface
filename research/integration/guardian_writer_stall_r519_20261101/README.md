# Guardian custody with a stalled receipt writer: r519

One preregistered fixed-order three-arm synthetic trial passed its scoped checks. A disposable parent transferred a sleeping child's pidfd to a separate guardian, and an independent observer pinned both target and guardian before allowing parent `os._exit(0)`. In the committed arm, the guardian reported sending a signal and observing the target exit; the observer's pidfd also became readable. In the uncommitted control, the guardian reported sending no signal and the target remained alive at observation. A separate sentinel was alive in all three arms.

In the third, committed arm the guardian was deliberately paused for 30 seconds immediately before writing its receipt. The parent exited; the independent target pidfd became readable; 200 ms later the guardian was still alive and no receipt existed. The absent guardian receipt remains UNKNOWN: the observer's target-exit observation is not a persisted guardian result and does not independently prove which actor caused exit. Startup-through-parent-exit was about 59–60 ms in these individual fixture samples, not a benchmark or hard deadline guarantee. The fixture then observed exit on every acquired target and guardian pidfd and the sentinel after cleanup; the test container was removed.

The archive contains preregistration, fixture scripts, hashes, parent logs, guardian receipts where present, observer results, cleanup observations, test stdout and exit. The image was `agent-interface-xvfb-mcp:late-input-r19`, `sha256:bd191d30ea94871a1d3ca717252cd07a276e8ef7d1bcb4a130b63935ce075425`, network disabled, one CPU, 1 GiB, no pull. Unlike r518, the committed PASS predicate explicitly requires `signal_sent=true`, parent readiness has a local timeout, and acquired guardian and target pidfds are checked for exit during cleanup. A partial parent output line could still block after readiness until the outer timeout. If failure happens before registration, the disposable container remains the containment boundary. Pidfd readability does not establish orphan reaping or enumerate all container processes.

This is a prototype with sleeping children and an injected sleep before writing, not an actual blocked filesystem operation, MCP or repository owner/supervisor integration. It does not prove input release, queue drainage, adversarial peer authentication, guardian crash recovery, durable evidence, hard deadlines or general reliability. The writer-stalled guardian was terminated during fixture cleanup; no eventual receipt is claimed. This does not resolve the blocking regression in PR #10131.
