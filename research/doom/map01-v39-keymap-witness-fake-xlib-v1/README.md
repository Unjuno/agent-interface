# v39 per-key witness source-compatibility construction

This package tests the observation interface against the exact v39 `InputOwner` v10 source and the current PR #7376 v3 transition wrapper. Two repeated `W` occurrences pass through the actual owner queue. The fixture records caller-assigned occurrence IDs and full 32-byte keymap-shaped snapshots before down, after the admission response, and after the explicit up receipt. Both sequences are `false → true → false`, and both explicit release receipts are ordinary and owner-history-complete.

The result is **fake-Xlib construction evidence only**. Fake XTest changes an in-memory key set directly; fake `sync()` performs no server work. This validates source and wrapper call compatibility, not Xvfb, a real X server, physical input, application feedback, task effect, recovery, or timing. The `occurrence_id` is generated by the test fixture because v10's admission record does not carry a unique per-occurrence identifier.

The frozen run produced two distinct occurrences, each with 32-byte witness bits `false → true → false`, valid `input-release-transition-v3` receipts, and a verified-empty owner close. The separate saved-result auditor passed 12/12 checks; both commands exited 0. The Windows host had neither Python Xlib nor Xvfb installed, so the fake server was the only available local construction route.

The existing T3 Xvfb witness remains the real-X-server construction precedent, but it uses a different upstream owner lineage. This package narrows source lineage to v10 and keeps the evidence boundary explicit. The next physical/server witness still needs the correct owner and a fresh named resource/allocation assignment; it must be accompanied by separate application-useful-feedback and bounded-recovery endpoints.

See `PLAN.md` for H/T/D/C/U, `FREEZE.json` for source pins, `result.json` for raw construction output, and `audit_fake_v39_witness.py` for saved-result checks.
