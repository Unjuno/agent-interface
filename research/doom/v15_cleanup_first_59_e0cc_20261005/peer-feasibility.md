# Cancellation UP measurement feasibility from retained V39 full runs

## Finding

The retained full-05 and full-06 raw Session event streams **do contain identity-matched per-key DOWN and cancellation-UP keymap brackets** for the invalidated `cover-1` hold of key `a`. The owner event and `input_release_transition` preserve the exact same owner ID, intent token, key, and minted actuation ID. The UP also has its own ordered shared-batch snapshot interval. This is enough to audit a cancellation cleanup UP from the raw event pair, separately from the ordinary three-key primary-plan release pairs.

The normal `report.json` projector does not publish that cancellation pair as a completed `input_edge_receipt`: it emits `adapter_edge_receipt_incomplete` for `a` with its timestamp fields null. This is a conservative classification, not evidence that the raw UP was missing. The V39 projector's batch completeness gate requires `ordinary_release_candidate=true`; cancellation transitions set that false (and `owner_transition_verified=false`), even though `owner_thread_keyup_verified_after_batch=true` and the raw measurement is `CONFIRMED_PHYSICAL_UP`. Thus downstream consumers restricted to the ordinary report projection cannot recover a cancellation UP measurement without a distinct cancellation-receipt view.

## Source basis and boundary

The retained loaded V39 source is SHA-256 `69c691d8c4413839d0673605215064efa3091174c390c8ef8494c19bdf0523a9`. `input_owner_v12.py` (SHA `51b41a1d35542ca32a1140047629650814b2a4c9e11ce6995fe3ddaf19a565a4`) uses `KeyEdgeMeasurements.edge()` on its per-key down and batched up calls; `key_edge_measurement_v1.py` (SHA `977ba9218ec1dca0db0296de52c1bbd7d08c6d8fc41688340e91569ecb180bc0`) mints an owner-generation actuation ID at DOWN and retires the same ID only on a matching UP. V4 copies the nested owner measurement into the transition. The batch backend then attaches batch identity and post-batch verification fields. V39's `input_edge_receipts()` deliberately gates publication of its standard paired receipt on ordinary-release eligibility, which cancellation does not meet.

This finding applies to these retained synthetic full-run raw artifacts and their pinned source bytes. It does not say the current main branch has been independently refreshed or tested, and it is not live-control evidence. The precise remaining gap is **summary/projection scope**: raw records can be joined for cancellation cleanup, while the standard report's ordinary-pair summary suppresses them. If a public report needs cancellation telemetry, add a separate explicitly non-ordinary cleanup-UP record rather than weakening `ordinary_release_candidate` or upgrading cancellation to an ordinary release pair.
