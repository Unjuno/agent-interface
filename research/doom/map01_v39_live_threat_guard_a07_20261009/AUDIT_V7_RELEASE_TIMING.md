# A07 v7 release-call timing reconciliation

A synthetic current-v6 counterexample uses one valid identity: admission at 90, cancellation at 100, and a claimed verified release call starting at 80 and returning at 85. V6 returns scoped PASS despite release preceding admission. This does not assert that the retained A07 data contains such a row; no historical allocation was read or rerun.

The additive v7 keeps v6 identity, token ownership and strict admission/cancellation checks, and additionally requires each matching admission's integer admitted_ns to be strictly before the integer release_call_started_ns, with release_call_returned_ns at or after start. It uses timestamps, not row order, because publication can be delayed. The current transition producer exposes these call-bracket fields, but their presence and a common truthful monotonic clock in historical A07 evidence have not been established. Missing, malformed or contradictory times fail the scoped check; missing evidence is not proof of an actual unsafe input. The bounds only describe caller-side timing; they do not prove physical release or application behavior, and admission before call start alone does not establish input acknowledgement order.

Use only an explicitly copied evidence directory: python audit_live_v7.py --root <copy>. It writes AUDIT_V7.json exclusively, refuses an existing result and preserves previous audits. No older files are replaced. Synthetic tests compare v6 and v7 on the counterexample, valid and reordered records, missing/malformed/equal/reversed times, identity errors and existing-result preservation. Ten discovered tests, including four inherited v6 tests, passed normally and under Python -O. This does not establish the original A07 result, task success, live recovery or MAP01 completion; terminal-cleanup-only custody remains outside this explicit-transition contract.
