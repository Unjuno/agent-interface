# A07 v8 admission acknowledgement timing

A synthetic v7 example has admission at 90, a release call starting at 110, and input_ack_ns at 115. V7 returns scoped PASS although the recorded acknowledgement is later than release start. This is a synthetic evidence-quality counterexample, not a finding about the historical A07 run.

V8 retains v7's identity, token, admission/cancel and release-call checks and requires integer timestamps satisfying admitted_ns <= input_ack_ns < release_call_started_ns <= release_call_returned_ns. Current input_transition_owner_v3 uses the same acknowledgement-before-release relation when validating its release admission receipt. V8 checks the matched identity's recorded fields; it cannot establish that the fields are truthful, share a clock, or prove application-level delivery or physical release. Missing or inconsistent timestamps fail the scoped check and mean insufficient/contradictory evidence, not proof that an unsafe action happened. Historical A07 field availability is not established, and terminal-cleanup-only custody remains outside this explicit-transition contract.

Run only on an explicitly copied evidence directory: python audit_live_v8.py --root <copy>. The new AUDIT_V8.json is created exclusively; historical inputs and older audit outputs are not replaced. They cover the v7 counterexample, valid and reordered records, missing/malformed/contradictory acknowledgements and existing-output preservation.
