# A07 strict-timestamp reconciliation v5

The retained v2 is a historical counterexample and v4 permits append-only row-order fallback when both timestamps are absent. V5 is an additive copy of v4 with one ordering change: every matched input admission must have integer `admitted_ns` strictly earlier than its cancellation's integer `requested_ns`. Missing, malformed, equal or reversed timestamps fail the scoped custody check. A failure caused by missing timing means the evidence is insufficient; it is not proof that unsafe input actually occurred. Cases with no admissions need no admission-time comparison. Time values still need an independently justified common monotonic clock and truthful provenance.

Run `python audit_live_v5.py --root <explicit-copied-evidence-directory>` only on an authorized copy. The script has no implicit historical allocation path, writes a new `AUDIT_V5.json` exclusively, and refuses an existing result. Original raw and older audit files are not modified. No historical A07 candidate or original auditor was rerun for this addition.

Synthetic tests cover valid pre-cancel timestamps, late rows with earlier timestamps, missing/equal/late/malformed times, no admission, v4-derived identity and malformed-ID cases, and existing-output refusal. The 29 discovered tests (including imported prior-version fixtures) passed normally and under optimized Python. V5 is a scoped reconciliation; `formal_pass` remains false and no native release, live MAP01, complete event provenance or task success is established.
