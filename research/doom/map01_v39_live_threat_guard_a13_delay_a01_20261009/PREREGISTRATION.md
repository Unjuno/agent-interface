## H/T/D/C/U

**H — Hypothesis.** A09 (seed `990620`, 10 model turns) exposed a hard-health guard during a model turn but no useful scorer event during that turn. Its only useful scorer event was recorded 820.537 ms after the end of the tenth model-turn interval. A13 tests whether a fixed host relay hold after the tenth model completion can keep the controller awaiting that response long enough for an independently useful scorer event to occur before the controller consumes the completion. This is an event-timing and relay-boundary test, not a test of inference latency and not a claim that the model used the event.

**T — Treatment.** Run exactly one episode on the same fixed threat-contact fixture with `gpt-5.6-luna` at low effort, seed `990623`, at most 10 planner decisions, and the existing 600-second episode timeout. After forwarding the tenth `turn/start`, the host relay will hold exactly one matching `turn/completed` response for 1.0 seconds before making that already-produced response available to the guest controller. It will not reissue a request or alter controller code, model, effort, schema, inputs, or game controls. Use the dedicated Issue #59 VM only after live checks show no game/controller/Xvfb process and at least 2 GiB available memory and `/tmp` disk. A13 has its own source checkout and unique output directory. No retry, manual gameplay, prewarming, or in-place repair.

**D — Decision and measurements.** Retain requests/responses and usage, controller events, invalidation and release receipts, typed health/ammo observations and paired RGB artifacts, independent scorer samples/events, score and terminal, host/guest output, one-shot relay-delay receipt, and hashes. Report separately (1) model completion time, (2) host hold interval, (3) guest controller completion-consumption time, and (4) useful scorer-event timing relative to the controller's still-pending turn. A delay receipt must show exactly one 1.0-second hold for turn 10 and no reissued model request. PASS for the treatment-integrity subgate requires the exact one-shot hold and a useful independent scorer event before the guest consumes the response; it does not imply better control or task success. FAIL is a wrong/multiple delay, request reissue, broken release custody, stale admission after invalidation, or unverified final release. HOLD means the episode completes without the treatment-integrity subgate. STOP records death, MAP01 exit, timeout, runtime/model failure, or failure to reach the target turn, without retry. These labels apply only to A13; a local STOP does not stop unrelated authorized work.

**C — Controls.** A13 uses the next sequential fixture seed `990623` after A11's `990622`, retains a 10-turn cap, controller, model, effort, fixture, source closure, and runtime, and adds the host delivery hold on turn 10. A09 at seed `990620` is an immutable historical timing reference, not a matched control; seed and model nondeterminism prevent a causal efficacy claim. The hypothesized 179 ms overlap is arithmetic from A09's observed 820.537 ms gap and the planned 1.0 second hold, not a guaranteed outcome. Freeze exact current-main SHA, complete runtime closure, harness and treatment test, fixture/WAD, CLI binary/version, VM mount mapping, package versions, output path, and stop rule before starting app-server or game.

**U — Uncertainty and scope.** One episode cannot establish an event rate, survival benefit, causal advantage, or MAP01 completion. A scorer event during a held response is controller-visible timing evidence only if the existing frozen controller independently consumes it; the injected relay does not expose scorer state to the model or controller. X11 release receipts establish server-side event processing and observed server state, not hardware key state or game consumption.
