# A03 frozen plan — generated source binding

## H / T / D / C / U

**H.** A generated freeze can bind the retained V12 per-key down/up sample
brackets to a strict consumer without hand-transcribed digests or relabeling
the measurement row as the authority-bearing batch transition.

**T.** Resolve the exact input bytes from the current Git commit, compute its
SHA-256 and Git blob OID programmatically, copy those bytes, and generate the
freeze plus executable-source digests from the files on disk. Preflight all
source/hash joins before one candidate invocation. Run one offline candidate,
then independently reconstruct raw events and execute ten malformed-evidence
and output-corruption controls.

**D.** PASS only if the generated input SHA and Git blob match the exact source,
all frozen code/input hashes validate before the output path is claimed, the
candidate reconstructs one identity-matched confirmed pair with ordered
sample brackets, authority/effect flags stay false, and a distinct raw-only
audit matches it and rejects changed output. Any source mismatch is STOP;
semantic mismatch is FAIL.

**C.** The input comes from a prior fake-display construction. The replay
validates data integration only, not live input, game use, task effect, useful
feedback, threat response or recovery.

**U.** One F8 pair. No distribution, exact physical occupancy, live allocation,
causal effect, latency benefit or MAP01 progress result.

## Frozen commands

- Generate freeze: python3 generate_freeze.py
- Preflight: python3 -m py_compile candidate.py audit.py run.py test_consumer.py generate_freeze.py
- Candidate: exactly once, python3 run.py
- Independent audit: python3 audit.py
- Tests: python3 -B -m unittest -v test_consumer.py, normal and -O
- Output: results/a03/
- No OS input, GUI, game, model/provider or container operation.
