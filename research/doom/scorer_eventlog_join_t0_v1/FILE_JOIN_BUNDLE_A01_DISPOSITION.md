# A01 freeze correction

A01's raw-only result auditor passed its ten synthetic labels, but the frozen provenance gate was not satisfied. At the time of the run, the checkout was based on PR #7664 head `c0d7f484e2223e3e6bcae7963b21a682e6efbcc1`; `research/live_control/input_transition_owner_v3.py` had Git blob `0ea631abcf6272f0538a9ef9198ad8069b47b464`. Frozen main `8e807cd4c4ecd07f53c98f4d1629fbbe3528ac2b` had blob `99dfc7c9907b018e7473bc2ba8a7393a5b221f51`. The report's statement that all seven dependencies matched across those refs was wrong.

The A01 candidate cases were built using the stack-parent checkout's source bytes; its frozen `source_sha256` records that set, but the raw-only auditor compared those values only to the freeze file. It did not query either Git tree. In addition, the frozen D section says “all seven decisions” although the freeze and run contain ten cases. Therefore A01 is **HOLD_INVALID_FREEZE**, not a PASS, and must not be used as source-bound evidence. The original freeze, raw, audit output, and test source are retained unchanged; this note corrects their interpretation. The additive A01 artifact digest list records the retained files as they stand now; the shared consumer source received two small defensive checks during A02 and that digest list is not A01 candidate-source provenance.

A02 is a new, versioned construction check against current main `52d2c7a7b6f4854d9d9de43d001a1d8ebfbfaacf` and the then-current #7664 stack head `cf8200378e4e895da2c6b492a4b6f307b56aee56`. Its freeze records both Git blob maps and the exact content SHA-256 values, and its independent auditor checks them against those Git objects before accepting the raw result.
