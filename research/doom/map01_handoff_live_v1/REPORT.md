## New observation: pulse count is not precise angle control

Across the nine admitted six-pulse programs, absolute yaw change has median **89.6484 degrees**, range **77.3437..138.8672 degrees**. Requested total key-down time was always1140 ms. The observed sums of owner key-down acknowledgement to key-up request start have median1140.8075 ms, range1140.6777..1142.5915 ms. Those intervals are not exact physical occupancy or game-consumed key-up timestamps.

Thus fixed pulse count plus verified release did not produce a fixed angular displacement in this block. This does not establish that fencing improves angle precision; the gate deliberately tests effect presence/absence, not angle accuracy. Do not change the successful authority gate or retroactively turn these diagnostic values into an angle benchmark.

The next question for #480 is whether the game observes the short released intervals between pulses, or whether another engine/input timing mechanism explains this dispersion. A bounded observation-based termination rule should be compared only after that cause is isolated; no new macro DSL is justified by this result.
