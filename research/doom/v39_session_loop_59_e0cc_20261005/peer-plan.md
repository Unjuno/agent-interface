# Proposed synthetic full-session composition test

## Boundary and current coverage

Reuse `research/doom/test_map01_overlap_controller_v39.py::_exercise_invalidation_handoff` for its pending planner, hard/unknown health, terminal-before-frame, wrong-binding/stale-capture rejection, verified-neutral-release, no-replan, and fresh-frame assertions. It exercises the real V39 `main()` and real `ObservableSignalPolicyMonitor` in its health cases, but currently patches `subprocess.Popen`, feeds a `TraceQueue` of hand-authored child rows, patches `session_command`, and fakes model/planner transport. It does not execute V15/V12 child startup, real Executor/backend/owner, or their event serialization.

The `#8094` controller already has the pending-future/no-active-cover path (`wait_without_active_cover` and the `current_cover is None` branch around the V39 planner wait). It does **not** include the #8031 observation-identity producer fix or its frame-barrier helper. Its `ObservableSignalPolicyMonitor.observe` event needs `capture_ns`, a copied `pointer_binding`, and `frame_rgb_sha256` when available; after cancel/release, V39 must wait for an observation matching that identity before the next planner turn. Compose those identity/barrier changes with #8094 for this test; otherwise it can prove interrupt ordering but cannot prove the required replan frame is the invalidation's paired frame.

## Smallest harness change

Keep V39 `main()`, its wait/reader thread, `ObservableSignalPolicyMonitor`, `cancel_invalidated_cover`, frame barrier, action compiler/admission, and real V15/V12 child code. Replace the existing fake `Popen` with a deterministic in-process process shim: its `stdin` is a blocking line queue and its `stdout` is the child thread's JSON-lines pipe; launch the real `session_map01_v15.main()` in that thread with V39's generated session arguments. This lets the existing V39 reader thread consume rows produced by V12's actual `emit()` path rather than fixture rows. Keep a scripted planner future/adapter as the model seam, and inject only external facilities at V12's module boundary: fake `vizdoom.DoomGame`, fake `session_v8.Session`/Xlib, Pillow `ImageGrab`, clock if needed, and deterministic rendered frames/HUD reader. Supply a valid fixture/save manifest or narrowly stub fixture validation while retaining the remainder of V12 main. Do not stub V15's wrapper, V12's command loop, real V13 Executor, typed backend, V4/V3/V12 owner, per-key bridge, or batch release backend.

Use two child-owned observations with a stable fake binding and real PNG bytes/hashes. Start a valid cover through the real command channel while planner turn 1 is held pending. The fake game/Xlib seam should record actual key transitions and expose query results to the owner; it must not synthesize accepted/release/terminal rows. Then drive an actual full observation causing a hard health drop (and a separate unknown-health case) through the child's normal observation producer. Have the monitor invalidate the admitted cover, let V39 send `cancel`, and require the real executor/backend/owner to publish a verified empty release and terminal before any next plan is submitted. Arrange child event order so terminal arrives before the paired observation, then provide wrong-binding and stale-capture observations followed by the matching fresh frame. Assert that the planner is interrupted while still pending; no post-invalidation answer/action is admitted; no second model turn begins before both empty release and identity barrier; and the next turn's image is exactly the matching frame. A negative release (query error, key/button still down, or unverifiable sample) must stop with no barrier-driven replan and no further submit.

## Falsification controls and limits

Include normal-completion control, hard and unknown invalidation, one failed release control, wrong binding, stale capture, and missing identity metadata. Assert actual child source pins and selected owner/backend paths in startup receipts; the #8094 source-guard path must fail closed if the requested per-key owner is not the instantiated class. Capture raw child stdout/events, parent command writes, key-transition/query trace, planner timeline, and source hashes. This is a synthetic seam-composition test only: it establishes Python protocol/thread ordering and exercised owner logic under fake Xlib/game/capture/model services. It does not establish X11 delivery, Doom behavior, HUD accuracy, model latency, or live-control effectiveness.
