# Main-compatible evidence-storage startup guard

This promotes only the evidence-capacity guard from candidate PR #5639 onto main base `a7648fb47f16b15ac2fdb63075186aad1189859c`. Source `75e57e50199597669f96f4b6b60b1b45206fb317`. Main's relay client matched the pre-fix candidate exactly. Its instrumented host remains unchanged; pointer motion, reference lifetime, primary caller policy, acknowledgment and capture candidates are not part of this intake.

Previously a relay could start on a known-full evidence filesystem, then lose its request journal as in spine09. Both factories now check the existing parent's reported capacity before allocation, then the fresh directory and an exclusive startup receipt write before spawn. Default floor32MiB; the caller may choose another positive safe-integer floor. Known shortage throws `EVIDENCE_CAPACITY`; unavailable measurement throws `EVIDENCE_CAPACITY_UNKNOWN`. No fallback, evidence deletion or input replay is introduced. The receipt is not capacity reservation, WSL backing-space proof or a future-write guarantee. Existing post-start fail-and-reconcile behavior remains required.
