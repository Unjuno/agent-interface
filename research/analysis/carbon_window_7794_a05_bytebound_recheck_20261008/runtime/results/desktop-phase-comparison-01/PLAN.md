## Six phases per arm / planned finite workload

Same task every positive phase: from an empty XLSX, enter A1=317/A2=529, save in
XLSX, review actual format modal and separately confirm if evidence qualifies.
No other cells may persist. Development-known task; not held-out or blind cold.
Each arm has: acquisition, warm1, warm2, changed_dependency, bounded_repair,
subsequent_reuse. Reuse horizon is these six phases only; no extrapolated break-even.

Acquisition: fresh app/session/profile and grounding; include construction,
validation, dictionary/schema delivery actually measured, shared preparation
separately. The model has already seen this workflow: cannot claim cold model
knowledge. Warm rows reuse method code only; session-scoped authority is freshly
grounded and cannot be transported to another app/window. Fresh XLSX/profile per
positive row avoids hidden accumulation of previous saves.

Changed_dependency: capture/ground original sheet, retain it, then the independent
harness moves the owned main window +40,+30 screen pixels before method entry.
The caller receives no replacement pixels before using its old grounded context.
Require fail-closed refusal before consequential input from that stale context.
Keep actual mutation, full captures, input prefix/release and empty persisted file.
A mutation that does not change the chosen crop is not an accepted negative:
retain inconclusive result, no favourable rerun. New window geometry is verified
by harness metadata only, never supplied as executable targets to the controller.

Bounded_repair: same changed session (not reset), one new actual observation,
primary re-grounding, one new method invocation and at most one explicit modal
review/confirmation. Independent workbook scoring occurs only after owner close
and all children wait. Changed and repair are two phase records in one owner:
report their joint terminal score, never claim a pre-repair saved-file oracle or
separate independent terminal score for changed while that owner is live.
Subsequent_reuse: fresh session at the changed geometry, same repaired method,
new scope and actual grounding, no authority reuse across owners.

Schedule proposed before results: acquisition A,B,C; warm1 B,C,A; warm2 C,A,B;
then changed_dependency+bounded_repair paired per owner A,B,C; reuse C,B,A.
Pairs cannot be interleaved/restarted merely to counterbalance. Fifteen owners,
eighteen phase records; all refusals/infrastructure/unfinished rows retained.
Seeds and order in schedule.json are reserved proposals, not consumed allocation.
If protocol or implementation changes before freeze, version the construction
record. After freeze do not edit or retry based on a result.

## Bounds and stopping

Per owner: 900s wall lifetime, one initial method call; only paired changed owner
may receive its one separately labelled repair method. Each local method requested
10s, each dispatch lease2s, existing cooperative I/O limits disclosed. No hard
real-time promise. At most 8 commands normal owner / 12 paired owner, including
close. At most 3 input programs positive / 3 after valid stale refusal+repair;
any unexpected completed input in changed phase is a correctness failure, not
an invitation to repair automatically. Stop consequential input on uncertain
input/release, unqualified/withheld feedback or changed identity; close original
owner, wait original children, retain all outcomes. Stop whole block on a shared
correctness defect or resource/OOM failure; remaining rows are censored/unattempted
with reason. No reset/restart to turn a failed row into PASS.

## Measurements / disposition frozen before allocation

Host monotonic timestamps: command request publication, owner acceptance, method
entry, native capture interval, public projection ready, primary tool output,
separate confirmation and independent terminal scorer. Cross-host timestamps use
UTC and are not subtracted as if a shared monotonic clock. First image delivery is
not automatically first useful feedback; primary record identifies what was useful
and when known, otherwise null. Stale modal pixels do not establish redraw or
semantic completion. Persisted scorer completion is independent task completion;
primary awareness needs its actual corresponding received result.

Count separately: unique model responses/generations, tool calls, input programs,
incremental emissions (not cumulative sums), local captures, local OCR crops,
actual primary input_image blocks, reviews and recovery. Scope actual whole-context
provider counters by exact call/source boundaries including failures; cached input
and reasoning are subsets. Shared construction is not assigned solely to C/A to
manufacture savings. Joint and per-phase views overlap, do not add. Unknown cost,
provider snapshot, concurrency/peak memory and timing remain null. Record both
Windows available memory and Ubuntu MemAvailable before each owner. No human-speed
claim without a human comparator. No serialized-byte→token conversion.

Meaningful exploratory threshold proposed before results: at least20% reduction
in cumulative actual uncached input+output and at least20% shorter independently
completed workload time over the full declared reuse horizon, with no additional
wrong/stale-target/collateral/release failure and all intended positive completions.
Report input/output/time separately even if combined threshold met. One sample per
phase and growing shared context do not establish generality or causal superiority.
Provider-priced net economic RETAIN additionally requires actual billing and fair
acquisition/safety comparability; missing billing/context confounds imply HOLD.
REJECT on correctness regression; HOLD on insufficient evidence or nonmatching
capabilities; retained negative/inconclusive report is valid milestone completion.
