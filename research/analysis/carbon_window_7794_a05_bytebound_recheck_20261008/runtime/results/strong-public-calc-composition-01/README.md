# Strong ordinary public Calc composition

Concrete #57/#56 capability blocker, following #6323/#6336. The ordinary public
Python API can be locally composed with trusted read-only application callbacks.
A model turn per input operation is not its strongest supported baseline. The
prior form comparison already demonstrated this for its fixed fixture; form's
fixed click/CTRL+A/text/submit helper is not the same two-cell Calc workflow.

public_method.run implements the Calc continuation with the genuine existing
observe_in_session / dispatch_in_session / inspect_after_dispatch / present_result
functions and no graph or guarded alias substitution. The caller supplies the
same read_cells function used by compiled Calc and primary-grounded context RGB /
two cell regions. Fresh capture/context/focus precede entry; one ordinary batch
enters317/529, an exact retained image is read, and Save follows only if both
values match. Initial reading follows the compiled perception convention but
unknown initial cells do not prohibit entry into a grounded sheet. No intermediate
model resumption is required by either branch of this application-authored method.
Save always yields for separate primary modal review/confirmation. Independent
saved-workbook success is never inferred from input completion or pixels.

Every input request/returned raw result is retained before later inspection.
Completed prefix is appended only after completed input plus verified neutral
release. Input failure, uncertain delivery, changed context, unknown readings or
withheld image stops without another input. Prior capture state clears before
input, so an exception cannot expose a pre-input image as post-input feedback.
Runtime exceptions remain typed RUNTIME_FAILED with their confirmed prefix;
empty confirmed prefix does not imply no emissions. No replay, automatic rebind,
repair or confirmation occurs. Ten-second method/two-second input lease bounds
are cooperative checks, not hard deadlines on blocking backend/callback I/O.

The additive keeper exposes one `public_method` command after primary grounding.
The primary supplies only the context box and two pixel regions; context bytes
come from its exact previously delivered artifact, never application state. The
same existing read_cells is passed directly. The command returns the method
receipt and final Save inspection image when available; primary modal review and
confirmation remain separate commands. Source sequence follows only accepted
captures. The keeper/reader imports are checked before any live allocation.

## Qualification and limits

Three construction test methods exercise seven plain/compact/control subcases
with test-double capture/input/focus and actual public presentation/image selection.
They verify unchanged ordinary Enter/Save programs, conditional local continuation,
unknown/changed stops, neutral release failure, uncertain input and withheld image.
PASS normally and under -O. The first direct test invocation failed before imports
because repository PYTHONPATH was absent; the test entry point now supplies it.
This is construction qualification, not a fresh live allocation or provider usage
measurement. No archive/live plan was frozen or comparative row launched here.
The caller-supplied real read_cells must be exercised on a new pinned live
allocation before treating this composition as live qualified.

Per-key guarded target/reference semantics remain stronger in compiled.run than
in ordinary dispatch. Public focus/context checks do not erase the residual race,
renew symbolic references or establish equivalent safety. Do not claim a fair
speedup until that non-matching capability is handled/disclosed in the evaluation.
Ordinary batching is preserved rather than deliberately weakened. Public local
presentation encoding cost remains visible; no optimized baseline cost is assumed.
