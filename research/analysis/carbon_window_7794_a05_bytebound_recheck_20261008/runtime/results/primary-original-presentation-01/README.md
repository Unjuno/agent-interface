# Explicit original presentation through the primary caller

Disposition: ADOPT_EXPLICIT_WRAPPER / HOLD_EMPIRICAL_BENEFIT.

The motivating primary frame-review error remains unchanged in draft #6114.
Research Issue #6118 is independently studying same-image interpretation versus
new acquisition; this change does not execute its T0/T1, implement a critique
policy, or claim a correction-rate/cost benefit.

The existing host already permits explicit `present(attempt, sinks,
{forceImage:true})`. The new `primary.presentOriginal(attempt)` exposes that
same local mechanism with one positive integer attempt, copied sink callbacks,
and no caller-selected force/reference options. It emits the original retained
response through the sinks, not a new response or source epoch. It neither sends
a relay/public tool request nor captures or dispatches input. STOP remains sticky.
The host's ordinary identity, busy, evidence-failure and closed-state restrictions
still apply; presentation failure stops the primary and preserves its exception.

An existing instrumented host with an inert subprocess relay tests one initial
observation, original review and primary STOP, then explicit re-presentation.
The original reply/review files remain byte-identical, the two completed
presentations name the same reply hash, full image bytes are delivered despite
reviewed-image reuse, and relay attempts/send events remain exactly one.
Unknown attempt and modified retained bytes are rejected before delivery and
block later calls. Callback mutation, getter failure, missing sinks and invalid
arguments are tested. These are protocol fixtures using inert bytes labelled as
an image, not rendered screenshots, valid-image decoding or native app evidence.

Original RED (missing helper), initial GREEN, added controls and final focused
logs are retained. The committed-source selection passed 160 Node host/relay
tests; nine portable-distribution tests verify committed source export and
checksums. Six guide snippets parse. Source identity is in source.json.
No Python runtime execution policy, wait default, image encoding, source time,
authority, or automatic action selection changed.

Original review receipts stay exclusive and are not overwritten. This helper
does not automatically attribute a later interpretation or permit a second
ordinary review at an existing receipt path. Presentation events record source
identity; correction notes must preserve the first interpretation separately.
Re-presenting old evidence cannot establish current state or safely renew input.

Closed #6101's fresh-observation/historical-server-read helpers remain absent.
This candidate uses only retained local presentation, not those tool requests.
No fresh model/GUI allocation, actual token saving, latency benefit, task effect
improvement or human-tempo result is claimed. Existing frozen studies are not
rerun or changed. All log files are original subprocess output; this README and
source.json are authored summaries of those runs, not an independent GUI oracle.
