# Native exact-request retrieval without image redelivery

A read-only attachment to the previously completed native-node-relay-02 trial retrieved its stage-2 action receipt twice through the reusable Node client and actual WSL MCP server: first with default image delivery, then include_image=false. One MCP image block became zero; receipt, outcome, image status/reference, continuation and window inventory were identical. Both responses retained resumed_read_only=true. The original request bytes and mtime were checked unchanged; the relay exited 0.

This uses the public MCP content presenter rather than a new compression mechanism. The default remains image delivery. Image omission does not skip image validation: real-stdio regression checks invalid flags, a wrong request digest and corrupted image bytes. Corruption remains needs_review and is not relabeled omitted_by_request. No new GUI allocation, input, capture or task scoring occurred in this paired retrieval. It is not a token, cost, latency or human-tempo comparison, and does not prove the model no longer needs an image when selecting a new action.

Run `python verify.py` with the four files in this directory. The stdlib verifier checks nine retained files, exact requested digest, response identities, block counts, unchanged outcome fields and the full response image hash. The mtime check is a retained observation from the original check, not something an archive can independently reproduce. Base revision and candidate file hashes are in PROVENANCE.json. The earlier real task and its failures are retained separately in ../native-node-relay-01.

Validation: local shared native integration suites PASS (211 protocol / 97 harness). The new real-stdio assertion failed before the implementation because two content blocks were still returned, then passed after using the shared presenter. Original request bytes and modification time remain checked in the composed regression. Full local logs: results-local/native-resume-image-check-01.
