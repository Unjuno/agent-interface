# Live observation crosses a real model call and becomes stale

A fresh private Linux/Xvfb Mindustry process used unchanged socket v1 and interactive v2. live_focus_boundary_v1 acquired an observation-only terminal, built focus-decision-view_v2, and measured capture age with a clock response from the same runtime. The prompt then went to the existing Windows model_text_runner_v1 requesting Luna/low. The orchestrator ran preparation, model invocation and revalidation consecutively without a human/assistant decision pause between these stages. This is a guided text-only live proposal, not visual gameplay.

At prompt preparation the actual observation age was115.655ms. The model correctly reported the target binding, proposed a new target action, prohibited automatic replay/old lease reuse, and required runtime revalidation. At post-model revalidation, the same observation was12603.096ms old. The experimental maximum age was1000ms, so the driver recorded observe_only and issued a fresh observation-only program. It did not execute any target input from the model proposal. Source capture to reobservation acceptance was12655.427ms; to new image-ready12753.084ms.

The Windows CLI runner took11374.012ms locally, including startup/process overhead. Usage was12048 input,1792 cached input,73 output tokens (30 reported reasoning output tokens). Actual served identity, model receipt timestamp and cost remain unverified. All image-age and capture-to-reobserve deltas use the Linux runtime clock; Windows runner duration is computed separately. Never subtract Windows and Linux monotonic timestamps. This measures a chain that contains a real model invocation, not a model-internal receipt boundary.

The1000ms cutoff is an explicit experimental parameter, not an empirically established Mindustry safety requirement. The game stayed paused, so temporal age alone does not establish semantic invalidity. The pass proves the configured stale veto and observe-only followup on this one case. It is not a general freshness guard, target-action admission mechanism or liveness solution. If every fresh observation is sent through another slow model call with the same strict age budget, the system could repeatedly observe without acting. This remains a product-relevant architecture problem, not a completed recovery loop.

Audit: audit_live_focus_boundary_v1.py checks pinned sources/prompt bytes, model raw-event arrival hashes, a single no-tool model reply, exact socket cursor slices, the runtime-clock age transition, only two observe programs and no input admissions, three exact frame reconstructions, false independent empty-route score and cleanup. There are22 events and7 exchanges; runtime/bridge/orchestrator exit0 and canonical save unchanged. Result files reside in results/live-focus-boundary-01. The helper does not yet implement a general model-error recovery policy; it is a bounded probe and remains experimental.

This is negative evidence against relying on prompt compression alone for subsecond freshness under the measured CLI path. Next evaluate a bounded model-authored intent whose fixed target conditions can be revalidated locally against a new observation without asking the model to reinterpret the same static state. Preserve refusal to replay uncertain input, separate current target validation from historical observation, and measure both successful progress and refusal/timeout cases. Do not loosen the one-second parameter silently or claim human-like tempo from this observe-only success.
