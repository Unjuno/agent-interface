## H / T / D / C / U

- **H:** Knowing the intended action and receiving a dispatch acknowledgement does not reveal whether an effect persisted: in the authored save/modal pair, one new independent persistence receipt is required before either safe completion claim or recovery action. If a fresh local typed effect receipt is already in the decision-maker's current transcript, the same pair is already separated and no additional screenshot or model/tool exchange is necessary for the declared decision.
- **T:** Standard-library finite enumeration of two worlds and the exact current transcript in each of two controls. First run seven construction tests; then one candidate process in a pinned offline `linux/arm64` OrbStack container, followed only on candidate exit 0 by one independent raw-only auditor process in a second container. Mount sources/cases read-only, use separate new output directories, disable networking, bound CPU/memory/PIDs, and never touch an existing worker container. No GUI, model, GPU, game, OS input, or real task effect.
- **D:** `PASS_METHOD_SCOPED` requires exactly one additional `independent_persistence_receipt` in `known-save-intent-effect-unknown`, zero additional exchanges in `fresh-local-receipt-no-extra-tool`, an independent audit with no errors, all seven construction tests passing, and rejection of stale-receipt, false-zero, oracle-mismatch, and undeclared-channel controls. Any unexpected count is `FAIL_METHOD`; source/image/capture/resource ambiguity before candidate is `STOP_PREFORMAL`; audit disagreement is `FAIL_RAW_AUDIT` and remains terminal for this allocation. No retries.
- **C:** Both worlds, channel semantics, truth/freshness of the local receipt and safe-action oracle are hand-authored. Dispatch acknowledgement is deliberately not treated as effect evidence. This does not show that a real application's receipt is independent or truthful.
- **U:** This is a finite method/control result only. It does not establish any general model-call lower bound, live GUI necessity, actual persistence, task completion, latency, token/cost savings, safety, or roadmap completion.

Prior #5927 allocations 01–03 and PR #6393 remain unchanged; this is a distinct successor testing the newly added epistemic-necessity comparator controls.
