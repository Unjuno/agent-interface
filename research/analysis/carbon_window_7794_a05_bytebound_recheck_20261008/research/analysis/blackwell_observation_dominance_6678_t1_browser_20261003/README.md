# Blackwell observation-channel T1: browser fixture sampling

Successor to Issue #6678's completed synthetic T0. This allocation samples actual browser-rendered outputs from a disposable, authored static fixture; it does not test the Agent Interface runtime, a real application, or an agent.

## H / T / D / C / U

- **H:** On the frozen three-state fixture, screenshot-derived `full`, `left_roi`, and `right_roi` channels yield reproducible finite empirical kernels whose Blackwell relation and task-conditioned Bayes risks are independently recovered from retained raw captures. `left_roi` and `right_roi` encode different one-vs-rest state partitions and should be incomparable with opposing task-conditioned preferences; `full_png` and `accessibility_snapshot` should distinguish all three authored states, while `mutation_delta` should be state-uninformative after render quiescence.
- **T:** Render three explicit one-hot states in local Playwright Chromium; capture full-page PNG, two fixed PNG crops, accessibility snapshot, and a post-render DOM mutation delta. Freeze a deterministic 24-capture schedule per state (72 total) with one fixed viewport, scale, theme, and no animation. Retain every original screenshot, crop, accessibility text, and event JSON; the candidate tabulates empirical conditional kernels and applies the exact T0 garbling/risk method to frozen losses. A separately authored auditor reads raw evidence only, independently decodes PNG pixels, reconstructs labels/kernels and risks, and checks the candidate receipt. Construction and mutation tests precede an immutable input/source freeze; candidate and auditor are each invoked at most once, retries 0.
- **D:** `PASS_EMPIRICAL_CHANNELS_SCOPED` only if all 72 scheduled captures have complete raw artifacts, pixel-level independent labels match fixture ground truth, all kernels sum to one, the independent auditor reconstructs each kernel and all decision risks exactly, the accessibility positive control distinguishes all states, mutation delta has identical outputs across states, and all hash/corruption controls are rejected. Any missing/mislabelled capture is `FAIL_METHOD`; inaccessible raw evidence or uncertain browser labeling is `HOLD_AUDIT`; source, browser, fixture, or schedule drift before formal capture is `STOP_SOURCE_DRIFT`. A T1 pass would be browser-fixture evidence only.
- **C:** Repeated captures from one browser build are not independent draws from a population of browsers; deterministic rendering may produce degenerate kernels. Accessibility snapshot semantics are browser/tool-specific. The one-hot fixture makes state labeling easy and does not model naturally occurring GUI ambiguity. This tests capture/transformation, not inference by an LLM.
- **U:** No live app, native GUI, user data, Agent Interface component, model, action/effect, timing benefit, safety or cross-browser claim. Pixel hashes/pixels do not assess semantic usefulness beyond the preregistered hidden-state code. No sampling uncertainty generalizes beyond this exact browser/OS/configuration.

## Frozen protocol

The immutable freeze is `FREEZE.json`. The fixture presents one of three equally likely hidden states as a colored target card in a fixed 960x640 viewport: left-only active, neither active, or right-only active. Each output is collected 24 times per state in the order defined by `schedule.json`; output files are append-only under `formal/raw/`. Chromium is launched by the locally installed Playwright package with a fresh isolated browser context, headless mode, no extensions and no network access from the page. No existing browser tab is used. The initial construction candidate/audit mismatch is preserved, and the revised design has not been formally invoked.

The channel family is `full_png`, `left_roi_png`, `right_roi_png`, `accessibility_snapshot`, and `mutation_delta`. PNG-derived outputs are labeled from exact color/geometry rules frozen in the fixture. The auditor independently decodes the original PNG scanlines and samples the frozen card-center pixels/RGB palette, not candidate labels. Accessibility output is mapped from the two exact accessible names. The mutation delta is collected only after the initial render and a fixed quiescence interval; expected output is the empty mutation list.

The scoring state prior is uniform. Loss tables, channel definitions, schedules, capture script, candidate, independent pixel/kernel auditor, tests, and browser executable/package identities are included in the freeze. Empirical kernels use integer counts divided by 24; no smoothing or post-hoc binning is permitted. Relations require exact rational garbling, tolerance zero. Unobserved outcomes are omitted (zero probability) and reported as such. Left/right ROI kernels are expected to form the two different deterministic partitions from T0; exact-rational garbling and all four frozen Bayes risks are recomputed from observed kernels. A finite decision-family risk witness is not, by itself, a proof of non-dominance over every possible decision problem; the exact LP result is the dominance test.

## Construction failure retained

The initial construction design's `fail-01` rendered all 72 scheduled cases in about 90 seconds. Candidate and auditor ran once each against these construction bytes. Independent reconstruction detected an output-label schema disagreement (`s0` versus `rgb:230,57,70`) for the two pixel channels and returned `FAIL_AUDIT`; the raw captures, candidate, and audit are retained unmodified under `construction/fail-01/`. This is not a formal allocation and is not relabeled as a pass. The reporting code was revised to use the same canonical RGB label string while keeping the independent decoders separately authored. Review also showed the initial fixture could not test ROI incomparability, so the protocol was improved to the three-state left/right target design described above. The construction candidate/auditor will not be rerun on these same captures.
