# Journal-owned clock, reobservation and distinct action after rejection

`durable_submit_v3.py` extends the frozen v2 candidate with exact `{op: clock}` commands. Clock requests receive generated transport identities and are durably marked pending before transport, under the same cooperating-process flock. While either a clock or submit is unresolved, all new commands are refused. Clock recovery uses command-free reads without action scope and resolves only after its exact command echo and valid clock record. The received continuation independently correlates and validates that clock. The record cursor and retained observation advance together in the journal; the observation is still historical, never a new lease.

## Clock uncertainty controls

`probe_durable_clock_v1.py`, results/durable-clock-01, injects five replies into the real journal API. An orphan old clock before the requested echo does not resolve pending. Two attempted new commands are refused before transport. Echo alone and an empty timeout remain pending. A malformed negative clock fails received validation without changing the persisted checkpoint. A subsequent valid own-clock reply resolves; the image evidence remains exactly the old observation. One clock command total, no resending, zero real network calls in this control. These controls complement the actual integrated GUI path; they are not an additional live split-clock experiment or multi-process durability proof.

Material boundaries remain: trusted local checkpoint/session ownership, cooperating callers, Linux flock/fsync on WSL-mounted Windows storage,4096-record continuation cap, no power-loss/runtime-crash claim, and no reset based on elapsed time. Reconciliation does not prove task correctness; task evidence stays independent. The lock is held through bounded transport and persistence, whose contribution to end-to-end latency has not been isolated.

Next measure this caller's extra persistence/continuation cost against the earlier received caller on a fixed task, then use it in an actual model-facing decision loop. Retain successful recovery behavior while measuring model input, waiting and action/observation round trips. Do not extend the journal with more failure variants without evidence they improve real caller use or expose a necessary missing behavior.
