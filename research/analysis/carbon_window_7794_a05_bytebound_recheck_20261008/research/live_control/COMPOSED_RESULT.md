# Known-field result composition candidate

composed_result_v1 removes three fixed duplicates only after exact canonical JSON equality: root image matching receipt image; lifecycle terminal matching receipt terminal record zero; and binding terminal matching that same record. A short omission-name list describes these known locations. It can also omit the four input-state fields of the lifecycle observation when a unique matching sequence in the existing state table reconstructs every value exactly. All other observation fields, unknown data, full attention entries, source references and task-success uncertainty remain literal. Decoder restores omitted values and checks the canonical reconstructed SHA-256. The hash is consistency evidence, not authenticity or permission.

Unlike the generic sharing candidate, the state table can supply structurally encoded state values that are not repeated whole JSON objects. This is a format-specific self-contained representation; a reader must understand the fixed omissions and state table. It is not a human-readable summary, a readiness classifier or a new authority mechanism. Empty/irrelevant inputs can grow due to envelope overhead. No default client or frozen result was edited.

Ten archived browser/Calc results round-trip exactly as JSON values. Their canonical sizes total 95814 bytes before and 79496 after, a 17.03% reduction. Individual savings range from 939 to 1876 bytes, including two pending early results. This is an offline archival corpus, not a novel live comparison. No model-token, decision-accuracy, cost or speed benefit is established.

Five changed-evidence controls pass: mismatched image, terminal and held-button state remain literal; an unknown future error remains intact; duplicate state sequences disable state omission. Four corrupt encodings are rejected: mutated source image, repeated omission, overwrite of retained image and wrong state-row index. The tested hash detects corruption relative to its recorded value, not an attacker replacing both content and hash. Full schema validation for arbitrary hostile envelopes is outside this prototype.

Results and source pins are in results/composed-result-01. Next use a preregistered decision task that requires the retained negative state, not only an obvious screenshot, before any model-facing promotion. Do not interpret this 17% byte change as a 17% token change or compare it directly to the earlier ~0.87% actual-token result. The new format has not been tested with a model. Overall live control and human-tempo criteria remain unresolved.
