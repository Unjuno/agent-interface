# Post-recovery focus change refuses stale model input

A fresh Inkscape seed239 run repeats the intermediate scripted X88/save with response abandonment and one bounded recovery read. The model sees the recovered view and proposes a new X104 edit. After the model returns, before fresh admission, the fixture locates only the running bridge's descendant Xvfb and moves focus to a private override-redirect window. This is a deliberate focus fault in the observation-to-execution gap, not an organic race or an injection during model inference.

The existing fresh-observation gate detects changed pointer binding and refuses the proposal before submit. The trace contains no X104 input program. The fixture restores focus only for cleanup and does not replay or replan the proposal. Independent saved SVG remains X88,Y50,W40,H30 with the same hash as the intermediate result. Final goal X104 is explicitly not achieved. The result's success flag denotes the expected-refusal experiment; the runtime's broad independent score is supplemented by exact SVG assertions and final_goal_achieved=false.

Audit replays57 events,10 exact decoded frame/PNG pairs and13 journal records, verifies source/image/model hashes and exact prompted recovery view, matches the refused proposal to raw model output, checks changed binding and observation-only final submit, and confirms only three admitted programs: selection, intermediate edit, fresh observation. Save occurs once; original request is not replayed. All terminals have verified released inputs, driver exits0 and private sockets are removed. Evidence is results/recovery-focus-ink-01; audit_recovery_focus_ink_v1.py runs under Linux without new model or GUI calls.

The model call uses10545 input tokens,274 output and12.015s runner time. Recovery takes1.109s. There is no latency improvement or matched performance comparison. The purpose is input correctness under a controlled focus change. The initial edit/fault are scripted; the new edit proposal is an actual constrained-responder model output.

Limitations: this covers changed focus/binding, not same-window semantic target movement, a target change after the final fresh check, or atomic target identity. The source plan retains a inherited continuation scope string; refusal artifacts and this report distinguish the fault run. The harness stops after refusal and does not demonstrate autonomous replanning. Recovery/read/cleanup limitations remain unchanged.

Decision: the previous post-recovery continuation is protected against this observed focus-change case. Next address same-focus semantic changes with the existing sampled-target contract and expose refusal as a new observation for replanning, rather than treating this successful stop as task completion. Human-tempo, robust live continuation and broad domain coverage remain open.
