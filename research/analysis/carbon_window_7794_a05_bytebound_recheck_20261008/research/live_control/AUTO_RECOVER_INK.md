# One bounded caller read removes a model decision from uncertainty recovery

recover_once_v1 is an opt-in command-free read adapter over the existing durable_submit_v4 journal. It takes no input command. While run holds the exclusive journal lock, its transport callback verifies a pending command exists and the read action identity matches a pending submit. It calls transport once. The existing durable reconciliation rules determine whether pending clears; timeout/conflict are returned with pending retained and transport errors propagate. No automatic retry loop, submit resend, input continuation or task-success inference is added. Clock boundaries are selected by existing run behavior; this new study exercises submit recovery only.

Six offline injected-transport cases cover timeout, closed channel, read ConnectionError, conflicting command echo, matched original reply and no pending command. Each eligible case invokes one fake read transport; no-pending invokes none. Error/no-pending leave journal bytes unchanged. Timeout/closed/error/conflict retain pending; a follow-up new clock command is refused before transport. Matched original reply clears pending. Closed channel remains recorded as closed, not inferred to be runtime death. These are offline controls, not six live outages. Results are in results/recover-once-controls-01.

A fresh actual Inkscape seed239 episode uses the same initial scripted X88/save and deliberate AF_UNIX close-after-sendall as live-responder-ink-01. After pending persistence and pre-transport new-command refusal, the driver invokes the single recovery read directly. It receives the original echo/admission/completed terminal and current image. Only then is the constrained Luna-low responder called to inspect the geometry and request independent SVG verification. The verification succeeds: x88,y50,width40,height30, no transform. The model prompt for verification retains the preceding experiment's evidence/schema text; IDs and timing naturally differ between sessions.

The improvement removes a model call from a choice already constrained by pending state. The new remaining verification runner takes6.948s. These are two separate single episodes, not a randomized latency estimate or proof of general speedup. The omitted prior read-choice runner alone took8.747s; scheduling, completion timing, request evidence and generation differ, so do not attribute every millisecond or token difference solely to the adapter. No provider cost/serving identity is available. Model inference is still seconds and full human-like interaction remains unproven.

Actual audit replays49 events,9 exact transported frames and9 append records; source/model/image/raw-output hashes, pending state and exact reply attribution match. There are two admitted programs and one Save chord; no edit resend. Both terminals have verified empty held inputs. The saved SVG hash matches the earlier episode. Driver exits0, sockets removed and no error artifact; runtime liveness was explicitly checked. Run audit_auto_recover_ink_v1.py under Linux to replay results/auto-recover-ink-01 without invoking model or GUI. The initial edit is scripted and the model verifies only; neither version is full autonomous editing.

The adapter does not catch and classify every upstream failure automatically. A caller explicitly selects recovery when uncertainty is known. If the one read remains pending, the current driver stops; it does not invent success or reset state. Existing journal size, channel/identity limitations and research-driver failure cleanup remain. No production-wide default changes were made.

Decision: use this opt-in single read in subsequent uncertainty experiments instead of asking the model to choose a mechanically required read. Keep unresolved state visible and require a new explicit decision for further reads or input. Next consolidate this recovery status into the shared caller's model-facing response so a real agent can distinguish resolved, still pending and closed-channel cases without inspecting several files. Validate that presentation against failure evidence and preserve the separate observation/semantic-completion boundary. Avoid more identical successful Inkscape reruns as a substitute for improving the caller experience and broader domain coverage.
