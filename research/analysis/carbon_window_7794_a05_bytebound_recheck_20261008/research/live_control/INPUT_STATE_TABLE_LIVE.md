# State companion used during a fresh changed-value field task

The assistant used the full decision receipt plus the nonempty input-state table
through a fresh Inkscape task, without requesting an extra raw-state expansion.
The new target X=73.25 passed independent saved-SVG geometry scoring with Y=50,
width40, height30 and absolute tolerance0.01. This is a single familiar-layout,
changed-value trial, not a changed-layout or injected-fault trial.

`field_table_live_v1.py` uses the existing cause/servo socket entry, seed222 and
unchanged runtime defaults. It selects the rectangle, edits the visible X field
with ordinary click/Ctrl+A/text/Return, then saves. Each program returns the full
receipt, its final image and the state companion only when nonempty. The table
replaces the previous extra manual state dump; it is not a substitute for the
receipt, image or unknown-event review. Receipt attention remains unchanged.

The assistant viewed the initial, selected, edited and saved images. Common owner,
focus, pointer and released-input values were read once per table, with revision
and timestamp differences kept for every sample. No state classification or new
input authority is inferred by the codec. This normal trial alone does not show
that changed focus, held inputs or unknown state will be correctly interpreted
during a live fault; the earlier offline preservation controls remain narrower
evidence that those values are not discarded.

Before finish, the assistant recorded a GUI-only decision: X73.250/Y50.000/W40.000/
H30.000 satisfies the declared task. Its source image hash and decision hash were
bound to a runtime clock echo before the independent evaluation. Saved SVG was
not inspected before that decision. The runner's declared target supersedes the
old randomized ready-event goal field for this precision task. The final runtime
evaluation is coarse, so `audit_field_table_live_v1.py` independently recomputes
the stricter predeclared geometry score from the saved single direct rectangle.

## Research decision

Keep the companion opt-in as a demonstrated normal-case review aid. Do not claim
token savings, general fault usability, speedup or Research Freeze. No additional
table-format variants are justified merely to shave more bytes from this fixture.
The larger remaining cost is repeated captures and per-step feedback during a
bounded field edit: the edit alone produces eight observations. Inspect existing
observation policies before adding another mechanism; preserve focus/lease/error
visibility and useful application feedback when evaluating fewer captures. Include
another desktop domain or layout before promotion to avoid single-app tuning.
