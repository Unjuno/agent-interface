## Concrete measurement decision

Under the exact-clock, same-key/server, single DOWN-to-UP transition and no
re-press assumptions, the tight feasible logical-release interval has an OPEN
lower endpoint at the last DOWN query START and a closed upper endpoint at the
first subsequent UP query END. The full proof, variables, units, necessity,
sufficiency, deadline logic and limitations are in [original/PROOF.md](original/PROOF.md).

A DOWN response cannot replace the lower endpoint; an UP request cannot replace
the upper endpoint. The internal snapshot can occur anywhere inside its query.
An empty interval cannot certify a deadline. The unchanged local prototype
omitted this nonempty guard; a separate pure wrapper rejects it. This is not an
upstream X11Backend defect or a production patch. Do not deploy the preserved
prototype as an authority or task-success oracle.

This supports #2789's release/recovery measurement boundary: preserve query
brackets and UNKNOWN rather than invent an exact release timestamp, interpret
missing recipient events as held input, or replay task input after uncertainty.
It does not close #3066's real runtime dependency/fault matrix or #4345's scope.
