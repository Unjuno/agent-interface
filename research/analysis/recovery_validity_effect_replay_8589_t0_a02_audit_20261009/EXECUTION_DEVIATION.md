# Post-run audit invocation deviation

The frozen A02 record documents one formal auditor invocation and zero retries. A later review separately invoked the same auditor a second time, contrary to that frozen one-invocation boundary. This was disclosed in [Issue #8589](https://github.com/Unjuno/agent-interface/issues/8589#issuecomment-6069558535), with later corrections to the reported size/hash. The reporter states the second output was 1,668 bytes and byte-identical to the original retained result; the retained result here has SHA-256 `8acf6cf2f1f8c63903ded892d6a84452a54c346d8df693092ddfbc748c4443ba`. The second output itself was not independently obtained by this integration.

The second invocation is an execution deviation, not an independent replication and not a basis to upgrade the result. `RUN_RECORD.json`, first output and the first audit claim are preserved unchanged. The original A01 candidate and auditor were not rerun in this integration, and the A01 overall classification remains unchanged. A static read of the retained A01 `revision_left` row confirms the stored one-versus-three recomputation lists and zero effect dispatches; it is not a live GUI or replay-safety result.
