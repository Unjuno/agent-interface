# A06 preregistration — optimizer sensitivity after A05 numerical mismatch

## H / T / D / C / U

- **H:** The A05 base-fit discrepancy is at least partly consistent with optimizer instability near a finite-sample GPD likelihood boundary: on fresh stationary exponential fixtures, changing `ismev::gpd.fit` starts and optimizer method will produce materially different converged fits or objective values on at least one fixture. The competing outcome is that the R fits remain stable while the frozen Python port differs, which would direct follow-up toward the Python implementation/termination behavior instead.
- **T:** Generate six fresh `n=400` exponential samples with R 4.4.3 and seeds 65769931–65769936. For each, use the same type-7 0.90 threshold and remove the two largest observations, matching the A05 base-fit construction. In one R candidate invocation, run the pinned `ismev` default Nelder–Mead fit plus five predeclared start/method variants. In one Python candidate invocation, run the repository's frozen pre-A06 TailID-equivalent Nelder–Mead port once per fixture. A separate Python auditor reads only frozen samples, preregistration and candidate raw outputs. Candidate invocations: one per language; independent audit: one; retries: zero.
- **D:** A converged R-fit set is classified `R_OPTIMIZER_SENSITIVE` if any fixture has scale range / median scale >0.001, shape range >0.001, or negative-log-likelihood range >1e-6 across the predeclared starts/methods. Otherwise it is `R_FITS_STABLE_AT_GATE`. Separately compare the default R fit with the Python port using A05 limits (relative scale 0.001, absolute shape 0.001, CI endpoint 0.002). Any cross-implementation failure is retained; convergence status alone does not imply a global optimum. Audit must recompute each raw likelihood and threshold/candidate mask from the frozen sample.
- **C:** Six seeded stationary synthetic samples and optimizer variants test numerical sensitivity of this narrowly specified implementation. They do not estimate population tail risk, compare statistical quality, validate the eligibility gate, or establish an operational endpoint.
- **U:** No formal six-case #6576 T0, real input-release timing, physical key-up, GUI, safety, worst-case, production, or general package-equivalence claim. A stable six-fixture result cannot rule out optimizer pathologies outside this sample.
