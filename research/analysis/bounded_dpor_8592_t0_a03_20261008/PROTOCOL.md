# Frozen protocol — Issue #8592 T0 A03

## H / T / D / C / U

**H — hypothesis.** For the finite deterministic event fixture in `input.json`, a conservative sleep-set dynamic partial-order reduction (DPOR) explorer will return exactly the same reachable final typed states, per-event outputs, and safety-violation set as exhaustive schedule enumeration. On the preregistered commuting-heavy diagnostic control it will enumerate at least 20% fewer complete schedules. This is a schedule-count method claim, not a wall-time or production-performance claim.

**T — finite method test.** Candidate events are immutable, one-shot occurrences; every event attempt is enabled at each prefix, with its lifecycle guard deciding whether its typed transition takes effect or records a blocked/unknown result. There are two frozen reset cases:

1. `lifecycle_order_faults`: seven events, namely observation-generation update, lease revoke, task cancellation, dispatch, physical release, effect receipt, and caller acknowledgement. The bound is all 7! = 5,040 schedules. The state includes task/observation generations, lease and authority epoch, cancellation, dispatch/release/effect/ack receipts, and retained safety violations.
2. `commuting_heavy_diagnostics`: eight disjoint per-window diagnostic markers, all 8! = 40,320 schedules. This is a reduction-positive control, not a claim that diagnostic markers represent live interface traffic.

The candidate computes independence only when all frozen read/write, guard, enabling, effect/release, and authority-epoch resource sets are present and disjoint. Missing/unknown dependency metadata is dependent. The raw candidate records its independence relation, every representative schedule, typed event receipts, final state, and the concrete order for any invariant violation. It also emits a #6206-style exhaustive feasible ordered-pair baseline (all n(n−1) length-two ordered pairs, with replay receipts) as a separate descriptive comparator.

The auditor is separately implemented and imports no candidate code. It exhaustively enumerates every full schedule, reconstructs the reachable typed outcome and violation sets, checks each declared-independent pair's state-and-output diamond over every reachable prefix state where both events remain, and independently replays all representative and ordered-pair traces. `truth.json` is mounted only in the auditor container; the candidate receives only its frozen input and candidate-visible integrity manifest.

**D — decision rule.** `PASS_DPOR_METHOD_SCOPED` requires exact equality between candidate and exhaustive outcome/violation sets; complete replayable witnesses for every violation; exact frozen counts and legal complete schedules; a sound independence declaration with unknown pairs never omitted; exact complete ordered-pair baseline coverage; rejection of every frozen corruption/dependency-underdeclaration control; and at least 20% schedule-count reduction on the commuting-heavy control. Any missed typed outcome or safety counterexample is `FAIL_INCOMPLETE_DEPENDENCY`. A sound but ineffective reduction is `FAIL_NO_PRACTICAL_REDUCTION`. Oracle disagreement or a violated assumption is `HOLD_ORACLE_OR_BOUND`. Source, freeze, runtime, output-custody, or execution-integrity failure is `STOP`; retain it without retry.

**C — competing hypotheses.** Exhaustive exploration may be cheaper and easier to trust for small lifecycles. A #6206-style ordered-pair suite may cover practical order faults at lower cost without claiming equivalence-class completeness. The resource footprint may be insufficient to establish semantic independence; in that case the safe result is no reduction, not optimistic pruning.

**U — uncertainty and limits.** This proves nothing about unmodeled events, repeated event identities, liveness/fairness, real time, scheduling, external actors, UI state, application effects, user actions, network/provider behavior, or a live agent. Independence is valid only for this finite transition system and its enumerated reachable prefixes. Eight independent diagnostic actions were selected to exercise the reduction mechanism; their count savings are not a runtime speedup. No GUI, model, user data, external effect, GPU, or shared service is used.

No memory-ceiling claim is permitted. The finite suite is small and CPU-bound.
