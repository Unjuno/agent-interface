# Issue #5749 action-only label-blind successor A02

This is a distinct, additive method-validation rung prompted by the A01 report's explicit limitation: its candidate emitted post-decision `wrong_proposal` values from target labels available in the same fixture/process, and its auditor did not demonstrate policy/scorer process separation. A02 does not alter or rerun A01, source-routing A01, or the original #5749 T0/A02 outcomes.

## H / T / D / C / U

- **H:** Separating policy-visible action/consent/context events from a frozen preference-scoring key, then running the candidate, scorer, and raw-only auditor as distinct processes, will preserve the finite action-only state-machine outcomes while making scorer labels absent from candidate inputs and candidate outputs. Exact independent reconstruction and mutation rejection will expose any label/authority channel accidentally included in the raw output.
- **T:** Use six newly authored synthetic episodes (21 turns) and three fixed policies (`static_default`, `clarify_each_turn`, `action_only_adaptive`) for 63 policy-turn rows. Candidate receives only `fixtures/policy_input.json`, whose strict schema contains action observations, consent, scope, and turn-scoped clarification answers; it has no target/preference field. It persists proposals/state and `authority_granted=false` in `candidate.raw.json`. Only afterward, a separate scorer process reads that raw file plus `fixtures/scoring_key.json`, producing target-linked score rows and summaries. A third process, implemented in `audit_core.py` without importing either candidate or scorer, reconstructs all 63 proposals and scores from the two frozen inputs and checks their SHA-256 identities. The audit exercises five corruptions: injected authority, altered proposal, omitted row, injected target in raw, and altered score key/outcome. No model, GUI, network, human, native input, or real effect is involved.
- **D:** `PASS_LABEL_BLIND_METHOD_SCOPED` requires exact pinned input/code identities; a target-free policy input and raw output; rejection of a target field at the candidate boundary; all 63 candidate rows and separate score rows reconstructed by the independent auditor; all five mutations rejected; no authority grant; and exit 0 for candidate, scorer, and auditor. Any label leakage, reconstruction mismatch, false authority, or escaped mutation is FAIL. Identity/exit or infrastructure failure is STOP/HOLD, not a scientific verdict.
- **C:** A separate candidate/scorer data path may be sufficient for this deterministic method question; process separation is not a security boundary when both processes share one host account and filesystem. The scorer could remain integrated if its labels are never exposed to candidate decisions; a more complex isolation mechanism may add no value for this scope.
- **U:** Authored action streams and target labels do not model endogenous behavior under different policies. This validates only dataflow and finite state-machine reconstruction, not causal adaptation, stable user preferences, consent UX, human interruption burden, privacy, GUI/effect correctness, safety, transfer, or product benefit. The policy receives explicit answer fields for the clarification comparator; the adaptive policy is required not to use them. Host execution carries no container-isolation claim.
