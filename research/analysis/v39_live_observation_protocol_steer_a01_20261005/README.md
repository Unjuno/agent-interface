# V39 live-observation protocol: same-turn steering A01

## H / T / D / C / U

- **H:** On the workstation's installed `codex-cli 0.146.1`, App Server `turn/steer` may accept a text-plus-image observation for the active turn and cause the next Responses request before the preceding mock Responses request completes.
- **T:** Freeze the probe, tests, exact local protocol schema, CLI version, and retained seq=200 PNG. Start one App Server regular turn against a `127.0.0.1`-only mock Responses endpoint; hold its first response open. Once the server has received request 1 and returned the active turn ID, send exactly one `turn/steer` with that `expectedTurnId`, fixed observation text, and the retained PNG. Observe for exactly 2.0 seconds after the steer acknowledgement, release the first mock response, then wait up to 20 seconds for the follow-up and terminal turn event. Run the candidate once; no candidate retries or alternate payloads.
- **D:** `PASS_PREEMPTIVE_STEER` only if the active turn accepts the steer, returns the same turn ID, the second mock request arrives before response 1 completes (or before the fixed release gate if the client cancels request 1), and request 2 contains the exact observation text and exact PNG data URL. If it arrives only after completion, classify `FAIL_STEER_QUEUED`. Record method rejection, missing/mismatched turn identity, missing image/text, no follow-up, malformed timestamps, incomplete turn, and transport/mock errors as distinct failure/STOP outcomes. Integrity failures are separate from hypothesis failures. Unit/audit tooling may be rerun; the candidate itself may not.
- **C:** This is a local CLI/App Server protocol probe, not inference: a temporary `CODEX_HOME`, temporary `HOME`, empty API credential variables, disabled analytics, removed HTTP proxies, and a mock Responses endpoint bound to `127.0.0.1`. The fixture is a previously retained, publicly committed V39 seq=200 image and is used only to test byte delivery.
- **U:** One CLI version and one serialized image/text payload only. It does not establish model comprehension, plan change, interrupt/stop behavior, X11/device/game receipt, useful feedback, recovery, threat survival, ammo/progress, terminal outcome, or MAP01 completion. A positive result would justify a prospective live test only after the private lane is actually assigned; it does not grant that lane.

## Why this is distinct

PR #7969 measured `ExternalMessage`/`turn/start` tool output on CLI 0.160.0 and found its follow-up Responses request after the held response completed. V39 sequence audits also found pending frames 200/204 with no steer message. This A01 tests the separate `turn/steer` RPC and its direct `UserInput` image type on the installed CLI 0.146.1. The current local CLI generated schema is retained at `protocol/turn_steer_user_input_schema.json`. The official App Server protocol describes `turn/steer` as appending user input to an active turn and requires `expectedTurnId`: [App Server README](https://github.com/openai/codex/blob/main/codex-rs/app-server/README.md), [turn protocol types](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/src/protocol/v2/turn.rs).
