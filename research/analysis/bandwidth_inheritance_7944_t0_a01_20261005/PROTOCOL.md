# Issue #7944 T0 A01 — frozen finite scheduler method test

## H / T / D / C / U

**H.** In the authored finite model, when a current, authenticated, complete, preemptible resource edge blocks a verifier, its owner has exhausted its home reservation, and the remaining critical section fits inside the verifier's available reservation, BWI-style service attribution will meet the verifier freshness deadline where bounded PI charged to the holder's home server does not. BWI will not help the no-contention control, exceed any reservation, create or refund service, or admit a stale result.

**T.** Run every fixture case under all three frozen policies: `NONE`, `PI_HOME_CHARGED`, and `BWI`. One CPU is divided into preemptive unit ticks. Each server has fixed `(Q,P)`, an explicit remaining budget and absolute deadline. When a server exhausts its budget, it becomes ineligible until that absolute deadline; at that tick it receives `Q` and advances the deadline by `P`. This is a deliberately small CBS-like replenishment model, not the full CBS algorithm and not a host scheduler. EDF uses server absolute deadline, then frozen `tie_rank`, then job ID. Resource ownership and wait edges are frozen inputs. A verified waiter may donate only through its current, complete, authenticated, acyclic chain over a modeled preemptible resource. Under PI the owner runs at the waiter's tie priority but consumes its own server; under BWI it consumes only the selected waiter's available server budget. At unlock, cancellation, or expiry, the association ceases and consumed service is not refunded. The trace is deterministic and exhaustively replayed tick-by-tick for every declared case and policy; no random sampling is used.

The fixture includes a budget-inversion discriminator, no-contention control, exhausted waiter budget, unlock exactly at replenishment, two waiters, a nested acyclic chain, a cycle, cancellation, and a best-effort job. Construction-only mutations additionally cover unauthenticated/forged, stale, incomplete, expired, and non-preemptible/remote edges, altered budget deltas, duplicate service, stale-result admission, and omitted policy rows. A separately implemented raw-only auditor reconstructs the schedules without importing candidate code.

**D.** `PASS_METHOD_SCOPED` requires exact independent reconstruction of all rows; exact-once debit to the declared server; per-period budget and total admitted bandwidth conservation; fail-closed handling of unsupported, unauthenticated, stale, incomplete, expired, ambiguous, or cyclic dependencies; cancellation/unlock boundary correctness; no stale freshness admission; and policy invariance without contention. The hypothesis additionally passes only if BWI meets the budget-inversion verifier deadline while home-charged PI misses, and BWI is equivalent to other arms on the no-contention verifier endpoint. Any audit mismatch, duplicated/created/refunded service, unauthorized inheritance, or stale admission is `FAIL_METHOD`. A correctly reconstructed null or reversed benefit is `H_FAIL_SCOPED`.

**C.** Ordinary bounded PI may suffice when the holder has home budget; #7722-style control reservations or a nonblocking design may remove inversion more simply. BWI can consume the waiter's budget and cause that waiter's own job to miss when critical work does not fit. Non-CPU resource waits cannot benefit from a CPU reservation transfer.

**U.** This is a tiny authored finite schedule family using integer ticks and an intentionally simplified CBS-like replenishment contract. It does not prove the CBS theorem, general schedulability, a runtime policy, real verifier latency, CPU isolation, GUI safety, or physical key release. It does not establish that Agent Interface has an actual CPU-backed lock with these `(Q,P)` semantics. Candidate and auditor are separate implementations by the same author; independent human review remains useful.
