# Issue #5811 — relational session non-interference T0

## H / T / D / C / U

- **H:** Per-run PASS and final application state can both look correct while adding session B changes A's source/receipt/release projection; a relational check using independently reconstructed, source-bound resource events catches those leaks, ignores an explicitly allowed verifier-queue timing shift, and abstains when completeness or independence is unknown.
- **T:** Model-free deterministic pair enumeration over 10 A-alone vs A+B histories: clean disjoint, shared verifier capacity, B observation misbound to A, undeclared global focus, delayed B receipt delivered to A, B cleanup releasing A's input, intentionally shared document, truncated dependency trace, stale source generation, and missing effect evidence. Compare single-run status, final-state equality, and relational source/effect/release projection. Per-session `expected` counts source-bound resource events in the paired trace; `ledger_expected` counts inventory rows and `alone_expected` counts A-alone source-bound rows. Counts, session IDs, generations, and completeness are audited before scoring. In capacity-only mode only the explicitly allowed queue-use row is projected out; it remains in the dependency audit. Independence is never taken from the declared-disjoint label.
- **D:** `PASS_METHOD_SCOPED` only if all 10 labels reconstruct; two complete independent contamination controls (foreign receipt and foreign cleanup/release) are confirmed despite each run passing and final states matching; clean disjoint and shared-capacity controls hold; hidden-global, misbound observation, shared-document, truncated, stale-generation, and missing-effect cases remain UNKNOWN when footprint/effect coverage cannot be independently completed; and five mutations (session relabel, source-generation substitution, effect-row omission, hidden-resource omission, trace truncation) are rejected. Shared but fully audited resources are `SHARED_BY_CONTRACT`/`NOT_INDEPENDENT`; incomplete shared footprints are UNKNOWN, not asserted shared.
- **C:** Existing per-client binding and resource-footprint completeness may already prevent these cases; a new relational checker may add audit cost. Some apparent interference should simply be declared shared rather than solved by a new mechanism.
- **U:** Hand-authored finite resource/effect events do not prove real instrumentation completeness or live multi-session isolation. Timing equality is not required; no confidentiality theorem, backend safety, GUI effect, throughput, human-tempo, or production claim follows.

## Scope

This is distinct from #2774/#2733/#2293: it does not measure live dependency discovery or actuator overlap. It tests whether paired trace projections detect session contamination **given independently auditable source-bound dependency evidence**. No live GUI, model, participants, shared app, or external effect is used. Unknown coverage is never evidence of independence.
