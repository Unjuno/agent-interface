Two fresh Linux/Xvfb Mindustry cases use the same fixed model-proposed menu intent and new menu_intent_guard_v2. A test-only X11 thread changes the actual display one second after the source observation. Patch case maps a red47x52 override window over the known menu patch without changing input focus. Focus case maps a private sink and transfers input focus. Both changes occur after the recorded prompt-preparation clock and before the fresh revalidation capture. Windows model-internal timestamps are unavailable, so do not claim a precise injection point inside inference.

The new frame captures the changed state; only afterward does the fixture remove its overlay/restore focus to allow independent game evaluation. Refusal is based on that captured changed state, even though the fixture has restored the game before guard dispatch. No agent recovery or unstable-state liveness claim follows from fixture restoration. Both model calls are actual Luna/low invocations but the requested intent is fixed, testing the interface rather than autonomous planning.
