# Requested Fast mode in an actual Calc loop

Four fresh isolated Calc sessions used the predeclared default/fast/fast/default order, seed238, requested Luna-low, the same typed schema, full immediately previous outcome, supervisor and append-journal runtime. First prompt bytes match across all sessions. The runner differs only in Fast configuration flags; current-image paths necessarily differ between episodes. Each model proposal was passed automatically and unchanged through fresh observation/focus checks. No manual intervention, model retry, selected rerun, or global configuration change occurred.

All four independently saved A1=480 and A2=192 in the actual XLSX. Mean capture-to-evaluation is35.625s default and25.677s fast-requested. Total runner durations per episode are36.180,25.399,19.897,27.928s. The raw proposal arrival intervals are retained separately in results/tier-abba-01/audit.json. These are local CLI intervals, not provider-only inference time. Windows supervisor and Linux runtime clock domains are not subtracted from each other.

This is descriptive evidence, not a causal or population speed estimate. There are only two episodes per mode; action choices, generated output, cache state and service conditions vary. One Fast episode also saves a complete model turn, whereas the other repeats Save just like both default episodes. Requesting Fast did not reliably eliminate redundant actions. Actual honored tier, serving identity, receipt time and monetary cost remain unavailable. Default remains unchanged. The earlier fixed-image screen and this live experiment are separate scopes and their samples must not be pooled as equivalent tasks.

The per-episode audit replays full continuation, journal and runtime records, validates source and image hashes, raw model output and typed proposal correspondence, exact prompted previous outcome, clock/deadline/sequence, unique request IDs, released terminal states and independent workbook contents. It decodes every transported frame and matches exact PNG pixels. The aggregate audit checks the planned order, first-prompt equality, argument differences and arrival timing order. Totals are312 events,59 exact frames,92 append records,52 socket exchanges. All supervisors/drivers exited0 and private sockets were removed; no abort/error artifacts were present. These checks cover the completed episodes; they do not expand the bounded supervisor's previously documented failure-cleanup guarantees.

Reproduction of evidence (no new model calls): run `audit_tier_calc_v1.py LABEL` under Linux for each label in results/tier-abba-01/plan.json, then `audit_tier_abba_v1.py`. A new execution needs new explicit result labels; the frozen runner refuses preexisting result directories. Original measured source and raw records remain unchanged.

Decision: keep Fast as an optional experimental call setting and report it separately from shared-interface improvements. The interface still spends seconds on each image decision and sometimes repeats a completed save. Do not continue adding nearly identical tier trials merely to find a favorable ratio. The next generalizable investigation is the approximately13k input tokens per image invocation: inspect supported caller/context configuration and identify which input is necessary for this constrained screenshot responder. Test any reduced-context caller under the same action schema, runtime and independent scoring; retain task instructions, uncertainty/recovery handling and model/tool restrictions. No context reduction or speed benefit is established yet. Previously tested tiny terminal-field removal and all-history variants remain unpromoted. Full domain coverage and human-like live operation are still open.
