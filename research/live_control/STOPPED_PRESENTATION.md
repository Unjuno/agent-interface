# Presentation failure while a real socket action is pending

probe_stopped_presentation_v1 extends the existing stopped-transport fixture with presentation_choice_v1. The private AF_UNIX transport, bridge subprocess, executor v8 and PendingAction client are real. The backend deliberately raises a focus-change interruption and blocks capture on a controlled file gate; it is synthetic, not X11 or an actual application.

After receiving input_stopped, the probe forces the optional composer to raise. The emitted fallback retains lifecycle input_stopped_capture_pending, terminal=null, the exact received reply and an explicit RuntimeError presentation diagnostic. A command-free read times out without inventing a terminal. Cancellation is acknowledged on the cancel lane while capture remains blocked. Releasing the gate yields one passive capture and a needs_decision terminal retaining focus_changed and zero completed steps. A second forced formatting error retains that terminal exactly. Finish returns process exit 0.

There is exactly one submit command, one accepted action and only step zero started; the tail never starts. Each presentation invocation leaves the recorded socket call count unchanged. No automatic resubmit is present. The injected exception is a formatting failure, not a fabricated runtime error. Both original received results remain intact.

The independent audit reconstructs the tracker from six real socket replies, checks all eleven event slices and cursor coverage, verifies both fallback payloads against corresponding live states/replies, checks hashes and local emission receipts, and confirms the observed exit record. Probe source pins and complete raw evidence are in results/stopped-presentation-01. Output was captured in BytesIO; it proves local fallback contents, not downstream model receipt or delivery through the actual GUI client.

This is a bounded integration test of the same-action tracking and fallback boundary. It does not demonstrate semantic GUI recovery, hard capture preemption, nonempty physical held-input release or a speed/token improvement. The explicit Inkscape v2 client still needs live fallback validation; do not call it fully tested on the basis of this fixture. Earlier receipt construction and filesystem failures remain outside this helper. No defaults changed.
