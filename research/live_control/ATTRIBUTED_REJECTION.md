New candidates: rejection_identity_v1, cause_servo_interactive_v5/socket_v6, durable_submit_v2, then stopped_scope_v2/cursor_v2/socket_v2 and cause_servo_socket_v7. Previously measured files remain unchanged. The runtime catches its existing admission errors and emits diagnostic reason plus valid command op/action ID/transport request ID. A submit rejection is marked not_admitted only if it has both identities and the executor has never added that action ID to used_ids. The existing executor adds IDs before emitting accepted or starting execution. Already used, malformed or identity-free commands remain admission unknown. Per-line command state is cleared before JSON parsing to avoid attributing malformed input to a previous command.

The journal requires an exact prior command echo, no conflicting command, no observed acceptance, exact request/action identity, submit op and explicit not_admitted. It then records the rejection as historical resolution and clears pending. It never retries, and resolution grants no new input authority. Diagnostic reason text is not parsed to infer execution. Terminal/release reconciliation is preserved.
