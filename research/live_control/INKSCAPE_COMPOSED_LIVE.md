# Composed output used during actual Inkscape correction

inkscape_composed_live_v1 is an explicit candidate client on unchanged cause_servo_socket_v5, interactive v4 and executor v8. It saves the full result, composes known duplicate fields, verifies exact JSON-value reconstruction, then emits only the composed payload through presentation_emission_v1. Its initial plan pins candidate sources. Existing clients and defaults are unchanged.

One private Linux/X11 episode with seed 228 intentionally supplied not-a-number to the selected rectangle X field. The assistant viewed each decision screenshot: initial object, selected X50/Y50/W40/H30, invalid-entry X0/Y50/W40/H30, corrected X86/Y50/W40/H30, then the saved document without a modification asterisk. The invalid five-step program completed normally, yet the object moved left. The assistant recorded that semantic mismatch and issued a separate valid correction, then saved. The original task contract is a rightward move preserving size and Y, not an exact screen-pixel gain. Evaluator source was inspected after the correction value had been chosen; saved SVG contents were not inspected until independent scoring.

The final GUI prediction hash was embedded in a clock command before finish. Independent evaluation and retained shape.svg confirm X86/Y50/W40/H30 with no transform, success true. Intermediate X0 is evidenced by screenshot 012 and the assistant's decision note; an intermediate SVG was not saved or independently scored. This is deliberate application-input fault recovery, not a spontaneously discovered model error, runtime focus interruption or nonempty held-input test. Those latter cases remain separate coverage gaps.

All four action programs completed, each with verified receipt binding and no optional followup. The composed output retained unknown-field attention and task-success uncertainty; matching image/terminal/state values were restored by the audit. The assistant used the shown composed output and actual images to proceed, not a separate model sidecar. Initial and finish envelopes contain no omitted fields and therefore add overhead, a remaining presentation drawback.

Audit passes 111 events in 11 socket exchanges, 26 exact PNG/AIT frames, all source hashes, command echoes, regenerated receipts/state tables, six composed payload reconstructions and local emission hashes. Bridge/runtime exit 0 was observed. Correction alone used a five-step program and two socket exchanges; invalid entry adds its own five-step program and two exchanges. There is no matched no-fault baseline or model-time attribution. Initial capture to final GUI commitment was 132.843s including orchestration; it does not establish human-like tempo or a speedup. Actual model tokens and billed cost for this live parent turn were not captured.

Results: results/inkscape-composed-live-01. Decision: the candidate is usable in one real correction episode, but not default-ready from this evidence. Next address no-omission envelope overhead and failure-safe presentation delivery, then use a consequential runtime-negative case instead of more familiar successful numeric edits. Composition must not block recovery if presentation formatting fails after a command has already executed; current client raises on formatting failures and has no fallback, so that path needs explicit validation.
