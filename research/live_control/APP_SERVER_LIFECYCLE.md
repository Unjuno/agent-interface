# Owned client startup and sequential retirement

This candidate connects the UTF8, pending-response ownership, binary-stderr and factory-journal changes with two-reader startup access cancellation and sequential Popen pipe closure. It is a proposed complete lifecycle composition; unchanged PR7186 and peer7062/6965 retain their independent source and review scope. No old approvals transfer.

The stdout and stderr loops block independently, so each has its own mutex covering its complete synchronous resource-access interval. Stderr state is initialized before either reader starts. Both Thread construction/start operations are guarded. On failure, attempt direct process cleanup and both access cancellations independently. Only successful exclusion of both resource intervals permits independent pipe and journal closure. A pending native bootstrap can still run but skips its read action. A running reader that does not finish retains all resources. Cancellation is not a claim that the native thread has already retired.

For sequential normal close, the existing process stop and both reader joins must finish first. Then independently attempt journal lock/close/release and stdin/stdout/stderr closure. Keep the first cleanup exception as primary; annotate later error types. Failure of one component does not skip the others, and remains incomplete. A journal mutex timeout keeps that journal but permits owned pipe closure after both readers retire. Repeated successful close returns normally.

Custom process factories must supply exclusively owned standard Popen-like streams with close capabilities. Concurrent calls/writers, foreign or shared streams, hostile close implementations, descendants and total-startup/close hard bounds are not qualified. Process-stop or reader-join early errors retain the prior handling. State/gate allocation before guarded reader construction still has no total failure-retirement certificate. Typed reply matching, UTF8 decoding and diagnostic tail custody do not authenticate the peer or prove task effect or physical input release.

Eight selected app-server regression modules exercise 50 ordinary methods. The new reader-startup8/pipe-close9 definitions import the public module and do not require private evidence paths. The native catalogue appends those two modules once, retaining all prior ordered bytes.
