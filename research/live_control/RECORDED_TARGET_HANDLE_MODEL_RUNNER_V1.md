# All-attempt recording for the integrated target-handle runner

Status: opt-in instrumentation, locally tested with an inert CLI fixture. No live provider or formal comparison was run with this wrapper.

`schema_preflight_v1.py` and `integrated_efficiency_model_v1.py` both resolve `AGENT_INTERFACE_MODEL_RUNNER` when imported. Pointing that variable at `recorded_target_handle_model_runner_v1.py` sends both preflight misses and comparison calls through the same recorder while leaving the existing target runner and its frozen experiment inputs unchanged. Set the variable before starting the Python process; each model output path must be new, as required by the underlying runner.

For every invocation, the wrapper fsyncs a start row and a self-contained request record before calling the existing runner. The request includes exact prompt, schema and instruction bytes, optional image bytes, mode, paths, requested model/effort and source hashes. The terminal record preserves the raw event stream and every output file with per-file SHA-256, plus wrapper stdout/stderr and terminal status. The output directory gets `attempt-ledger-ref.json`, which points to the sibling ledger and hashes its journal. `journal_complete` means that the ledger has a terminal row; it does not mean the model call succeeded. A completed call status requires a zero exit and exactly one `turn.completed` event; missing or duplicate terminal events are malformed, not successes.

A runner timeout is recorded as one terminal timeout with partial response evidence and no retry. If the outer caller kills this Python wrapper at its own timeout, the durable start can remain unresolved; reconciliation must report it as unresolved rather than infer zero tokens or a completed outcome. Do not reuse an output/ledger directory for a second invocation.

The wrapper records the local CLI response. It cannot reveal provider-internal retries, billing adjustments, or usage not present in the CLI event stream, and it does not verify that the requested model/effort was actually served. A report must keep those quantities unknown. The request/artifact bundle duplicates input and output bytes in base64, so use a dedicated output location with sufficient capacity and preserve the ledger with the run.

Focused coverage includes handle-mode/preflight-shaped requests, image-mode requests, both caller override paths, timeout retention, malformed terminal streams, and actual schema-preflight plus comparison-caller execution through the wrapper using only a local inert Node script. These tests prove the recording seam, not a model result, task effect, release property, efficiency advantage or live-control qualification. Frozen comparison files (`integrated_efficiency_model_v1.py`, `schema_preflight_v1.py`, and `target_handle_model_runner_v2.py`) are not modified by this change.
