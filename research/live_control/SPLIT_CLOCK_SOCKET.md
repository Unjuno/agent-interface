# Received continuation across a real split-clock socket response

The received-continuation candidate previously passed archive/injected-reply tests. This experiment uses the unchanged stopped_socket_v1 bridge, a real subprocess and real private AF_UNIX connections. A synthetic runtime emits an image-reference observation plus an old clock, then holds its current clock response behind an explicit file gate after echoing the new request. No GUI is launched and no actual image or input is produced.

probe_split_clock_socket_v1 calls the existing received_exchange_v2.request_once five times: read initial observation; send one new clock request; read with50ms timeout while its response is gated; release the test gate and read the same pending clock; send one finish. The first clock reply contains the old clock only, so matched_clock for the new request remains None. The timeout reply contains the new command echo but no clock and leaves it pending. The process handle was checked live at this point; the timeout was not treated as termination. The next command-free read matches the original request. No clock request is resent.

The actual runtime stream contains7 events. The latest received cursor reaches7 while the retained observation remains sequence1 at event1. Two followups are read-only. The fixture/bridge exits0, stderr is empty, and both owned socket paths are gone after shutdown. Exact reply slices, continuation transitions, clock echo/event positions, one forwarded new clock and source hashes are independently checked by audit_split_clock_socket_v1.py. Results: results/split-clock-socket-01.

This is real transport validation with a synthetic clock gate and an image-reference record, not actual GUI observation or model performance. The old clock timestamp1 is deliberately synthetic. The positive probe verifies successful handling of a protocol timeout response; it does not exercise a client-side socket exception, dropped response after forwarding or malformed runtime stdout. Its emergency failure cleanup terminates the bridge, so it is a test harness rather than a production supervisor.
