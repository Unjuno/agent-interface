# Short terminal presentation saves little input and does not improve loop time here

terminal_context_v1 is an optional lossy presentation of the immediately previous proposal/resolution. It preserves the proposal, terminal status/error/steps_completed/decision_reason/semantic-completion scope, release reason/verified/held inputs, interruption reason/release state, and post-release observation counts/sequences/errors/stop/scope. It omits historical absolute timestamps, release deadlines, elapsed post-release time and opaque request/action/intent identifiers. The original complete history remains in supervisor evidence. Unknown field sets or selected invalid types return the full record. This is not a complete malformed-runtime validator; opaque ID types and every retained field type are not validated. It must not replace runtime admission validation. It is not lossless compression and the model has no automatic evidence-fetch tool: the shared prompt tells it to stop if omitted evidence is needed.

A predeclared full/view/view/full test used one supervisor/runtime/schema/task seed238/requested Luna-low, last outcome only, and the same explanatory prompt for both arms. First prompt bytes are identical across all four episodes. Only the presentation branch differs. All four complete independent saved XLSX480/192 without reruns, with four model calls and two save chords each. The redundant second save persists in both modes. This study is separately fixed from the previous history ABBA; the extra presentation explanation changes its prompt, so cross-study turn-count differences cannot be attributed to compression.

Offline controls preserve both actual archived proposal/outcomes without input mutation, retain error/failed-release/held-button state, and fall back full for unknown top-level,terminal,release,post-release fields and a boolean timestamp. The live per-episode audit checks exact prompted view against the function output, original full history retained, source/prompt/image/raw-output hashes, typed model proposals mapped unchanged to GUI steps, clock/deadline/sequence, full continuation/append replay, unique request IDs, released terminals, independent workbook and cleanup. Decision: do not promote this lossy view for a0.66% descriptive input reduction without a latency/turn benefit. Retain the full prior outcome as the current default. No claim that omitted timing/identity is unnecessary in every task, especially long-horizon/recovery cases. Binding/focus checks, bounded supervisor and append-log limitations remain as previously documented.

Next address the dominant seconds spent on each model decision as a separate experimental axis. Compare available lower-latency model/call settings only under fixed screenshot, schema, task and environment, keeping task accuracy/extra actions/independent evidence. A model-setting improvement must be reported separately from interface improvement. Validate capability availability before launching a live comparison; do not repeat tiny metadata-removal variants merely to obtain another passing benchmark. General desktop/dynamic-domain coverage and human-tempo remain unproven.
