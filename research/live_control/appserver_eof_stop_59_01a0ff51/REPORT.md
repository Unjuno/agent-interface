# Result: stop after stdout EOF without draining stderr

**RETAIN_REPAIR_SCOPED; proposal awaits independent content and current-main integration gates.** When stdout closes, both public wait methods currently execute `stderr.read()` under their condition lock. An independent stderr writer can hold that read beyond the already configured wait deadline; invalid stderr bytes can instead replace the intended AppServerError with UnicodeDecodeError. The repair reports stdout closure immediately and explicitly says `stderr not drained`. It changes only those two diagnostic branches. Matching responses, notifications, journal events and the actual command are preserved; no request is resent.
