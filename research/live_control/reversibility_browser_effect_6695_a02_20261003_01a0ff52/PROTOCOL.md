# #6695 A02: transfer of the conditional frontier to a disposable browser application

H: In this exact authored form, delayed visible information and reversible preparation permit a cheap-edit staging advantage, while a sufficiently costly edit reverses that advantage against WAIT using the same delayed information. The A01 analytical result and original T0 remain immutable. The browser/HTTP execution and independent server effect ledger are the changed factor; this is not a replay of their synthetic matrix.

T: Eight predetermined cases, two policies, 16 sequential fresh browser contexts. Alternating policy order by case parity. Application preparation service delay p=400ms and signal eligibility s=300ms; edit delay e=0 or800ms and deadline d=600/1000/2000ms as fixed in fixtures.json. The controller sees the signal only in the live form, not in future fixtures or truth. UNKNOWN selects proposal A in both arms. Server does not read scorer truth.json. Server preparation/edit completion changes a reversible draft only. The irreversible fixture effect is the append to the per-trial server in-memory ledger, which has no undo operation. This is an application-session effect, not durable filesystem or physical input proof.

D: PASS_METHOD_SCOPED requires all16 unique controller/server records, exact observed-event reconstruction, preparation/edit lower bounds, current signal, policy-specific target/order, single atomic effect admission at or before the server deadline, matching ledger/readback, no controller errors or external page requests and all seven effective auditor mutations rejected. H_PASS_SCOPED additionally requires c00 STAGE correct/WAIT deadline and c01 STAGE deadline/WAIT correct. Directional failure is retained as H_FAIL_SCOPED with no threshold adjustment; missing/contradictory evidence is HOLD_METHOD. No retries, exclusions, post-result retuning, or formal replacements. Candidate launcher once, independent raw auditor once. Source is fixed before these invocations.

C: Authored asynchronous service delays are the dominant intervention. Selector waits, HTTP overhead, scheduler/timer noise and policy order can perturb outcomes; all attempted trials are retained, no natural rate or causal production speedup estimate is permitted. The server's deadline guard could explain safety even if the controller is late; it does not prove client-side timely control. UNKNOWN/B can produce wrong commits in both policies, intentionally exposing the absence of sufficient information rather than asserting safety.

U: macOS native owned headless Chrome for Testing/Playwright; one process/context at a time, no user browser or physical display/input, model, GPU workload, shared Docker/VM or production runtime changes. Native execution is chosen for the actual installed browser boundary; no container or enforceable CPU/RAM limit is claimed. Browser-context request interception admits only the fresh loopback origin and blocks service workers; background OS/process network is not a network namespace. Browser background networking and GPU rendering are disabled through launch flags, not host-wide enforcement. Independent scorer reads retained server evidence and truth after the candidate exits. Same host filesystem is accessible to trusted processes; this is an observed no-truth-input path, not a hostile-code secrecy proof. Browser executable plus Node/package versions/hashes are recorded, not every transitive library or OS binary. Real websites, model grounding, reversibility beyond this fixture, human tempo, physical release and general optimality remain untested.
