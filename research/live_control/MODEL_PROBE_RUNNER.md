# Explicit model probe runner and local event arrival capture

model_probe_runner_v1 runs the installed Codex Node entry directly with a fixed request for gpt-5.6-luna, low reasoning, ephemeral read-only mode and ignore-user-config. Per-invocation feature switches disable plugins, remote_plugin, shell_snapshot and shell_tool. These are experiment arguments; no global user settings were modified. The runner records arguments, its own hash, image hash, exact UTF-8 stdin prompt, raw stdout lines, their hashes and local perf_counter_ns arrival timestamps, stderr and process exit. It does not use shell-built command strings. This first runner has no built-in wall-time cancellation; callers must monitor its live process handle rather than restart on observation timeouts.

The installed CLI was 0.153.4. Local help confirmed the flags and feature listing confirmed these feature names. Official [configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference) and [non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode) were checked on 2026-09-13. These sources describe configuration and JSONL usage; actual experiment output remains the evidence for this installation.

results/model-boundary-probe-02 contains the actual known unsaved screenshot probe. It emitted four events, a correct saved=false answer with confirmation-then-Save action, and usage: 12567 input, 1792 cached input, 43 output tokens. The input count includes the cached portion; do not add cached tokens again. The raw stderr contains only the stdin notice, with no MCP or snapshot warning. Exit 0 and the event/arrival hash audit pass. Local process duration was 5.563 s and completed agent-message arrival 4.905 s from process launch; neither is an authoritative model processing/receipt timestamp.

Compared with probe-01, model selection, features, launch path, prompt encoding and possibly cache behavior differ. No causal latency/token reduction claim is justified. The requested model is recorded; the served model identity is still absent from JSONL. No-MCP diagnostics is weaker than proof of no hidden tools or instruction context. Ordinary skills/global instruction discovery is not yet fixed or hashed. This is feasibility, not complete experimental isolation, an API billing measurement or an end-to-end GUI result.

Decision: use this explicit runner as a candidate starting point, but before paired presentation runs inspect a model-visible prompt inventory with private text omitted from published evidence, fix or account for instruction/tool configuration, and preregister task/presentation/order and cache accounting. Keep the two existing probes separate. Do not run repeated screenshot trials solely to produce lower elapsed times.
