# Returned execute receipt custody

An execute adapter can return a receipt before the caller's end-clock or stage-completion journal fails. Previously the outer error handler discarded that receipt. A callback could also mutate the original return value before decision validation, changing uncertain progress into apparent no-input or promoting an invalid receipt into success.

The caller now detaches the return before auxiliary callbacks and retains a validated receipt for operational failures. Delivery/progress and historical consumed-execute bookkeeping survive those failures. Stage chronology remains what was actually recorded: an end-clock failure can leave execute started. Explicit no-input refusal still reports not_attempted with no input authority. A typed upstream exception after an execute receipt becomes CALLER_FAILED; pre-execute model deferral is unchanged. A completed receipt followed by verifier failure preserves confirmed reported delivery with unknown task effect.

This is an adapter-reported plain-value boundary, not authentication of physical dispatch, release or task success. No resend authority is granted. Terminal journal failures, arbitrary deepcopy/non-JSON object failures and dispatch ambiguity when execute throws without returning remain outside this repair.
