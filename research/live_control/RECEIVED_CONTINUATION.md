# Separate image evidence from received-event continuation

The actual Inkscape guarded-click failure used a saved image reply at an older cursor after a later clock had already been received. A subsequent read selected the first historical clock and built an expired lease. received_continuation_v1 stores session identity, latest received cursor, per-record hashes, latest observation with its own event cursor, pending clock echo and clocks indexed by transport request ID. An observation is retained when later records contain only clock/terminal/diagnostic information. None of these records is input authority.

advance accepts contiguous or matching overlapping event slices, rejects conflicting replay, session mismatch, unavailable cursor ranges and non-increasing image sequences, and returns a copy so a rejected slice leaves the previous checkpoint unchanged. A clock is indexed only after its command echo; another command clears the pending clock association. clock_for returns None until that request's own clock appears. Channel closure is recorded separately and does not assert that the runtime process exited. Checkpoints are trusted local artifacts, not authenticated untrusted-input capsules; the hash list does not provide cryptographic provenance.

The actual failure replay starts at cursor23. The old clock advances the continuation to25 while image sequence4 remains at event21. The requested new clock is absent, so no input is proposed. A synthesized command-free read of actual events25–27 obtains the clock for the original request. Old clock68815411336ns is not substituted for the matching106455132483ns. Full session replay reaches cursor79/image12, survives JSON serialization and accepts identical overlap. Six controls reject wrong session, modified overlap, gaps, invalid cursor, duplicate observation and reads after channel closure.

received_exchange_v2 wraps one explicit exchange and persists request/raw reply/checkpoint. The caller supplies events/timeout and, only for a new request, command/request_id. It uses the continuation cursor automatically. A later read can name clock_request_id to recover the existing clock without resending a command. Raw evidence is persisted before checkpoint validation; transport exceptions record that the command may have been forwarded and no automatic retry occurs. V2 verifies session identity before any transport call. The initial v1 wrapper only checked it when ingesting the response, a discovered pre-send validation gap; v1 remains unpromoted and preserved.

probe_received_exchange_v2 injects recorded replies into the actual caller function: one clock command, one command-free followup, matching current clock, retained image sequence4, and zero calls on a cross-session attempt. This is not a new socket round trip or live GUI experiment. The continuation probe uses actual events and a synthesized read slice; the wrapper probe uses an injected transport callable. Results: results/received-continuation-01 and results/received-exchange-02; initial wrapper replay retained in received-exchange-01.

CLI candidate: received_exchange_v2.py SOCKET CHECKPOINT_OR_DASH SPEC_JSON OUT_DIRECTORY. Dash creates an empty checkpoint for that socket. SPEC_JSON has events and timeout, optionally command/request_id/action_id or clock_request_id for observation-only recovery. Continue using OUT_DIRECTORY/continuation.json. Source image references are available within the checkpoint; callers still need an independently declared target contract and current owner admission before input. No implicit lease extension, tail replay or loop is implemented.
