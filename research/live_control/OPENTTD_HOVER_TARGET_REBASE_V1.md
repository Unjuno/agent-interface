# OpenTTD hover evidence and persistent target rebase v1

## Result

A bounded active-observation path repairs the retained OpenTTD semantic-point
failure for one development-known toolbar task. Three fixed candidates are
hovered for 800ms and observed once more. Exact readable tooltip templates bind
the points to `Display subsidies`, `Display list of company's trains`, and
`Build roads`. Luna-low selects the Road Construction candidate at `[820,51]`
in all three hover-enabled calls across the two studies.

The first study is a retained failure. It minted the target patch while the
Road Construction button was still hovered. The 35 hover-highlight pixels
became part of target identity. After an actual X11 surface move of `[21,28]`,
the pointer remained at its old screen location, the highlight disappeared,
and exact target revalidation returned `MISSING`. No target click was admitted,
the terminal requested a decision with verified release, and the independent
engine score remained false. The paired candidate-association fault was refused
before any model call. Its 48 exact frames audit on Windows and WSL.

The corrected preregistered pair moves the pointer to a fixed neutral location,
waits 800ms, and requires the original pre-hover 24x14 patch to be restored
exactly before minting. This separates transient meaning evidence from the
persistent target identity.

| Case | Model selection | Target behavior | Independent result | Time from decision start |
|---|---|---|---|---:|
| Rehover negative | roads `[820,51]` | rehover changes the patch; `MISSING`; zero target clicks | false, expected | 15.867s |
| Stable | roads `[820,51]` | rebase, move `[21,28]`, revalidate at `[841,79]` | all four engine checks true | 17.677s |

The stable program completes all eight steps. Its local barrier measures 160
changed target pixels and zero guard pixels before continuing, and the final
engine scorer verifies target ownership, ordered connections, clear forbidden
tiles, and unchanged surrounding ownership. The negative and stable cases use
14 and 16 durable calls. All 81 exact frames, preregistered source hashes,
tooltip associations, model contracts, target patches, releases, cleanup, and
scores reconstruct on Windows and WSL.

The study sources used to allocate input are covered by the preregistration
manifests. The audit programs were written after the allocations and are not
themselves hashed by those manifests. They recompute the claims from immutable
raw artifacts, but their procedure does not have preregistered authorship.

## Efficiency evidence

The direct full-frame OpenTTD baseline grounded the semantic target 0/2 and
reported 9,296 input tokens for its stable call. The three hover-enabled calls
ground it 3/3 and report 9,932, 9,936, and 9,935 input tokens with no cached
input. The bounded hover program itself takes about 3.6 seconds. This is an
accuracy and recoverability gain with roughly 636--640 additional reported
input tokens and added observation latency. It is not a speedup.

The corrected stable run's 17.677s cannot be treated as faster than the direct
baseline's failed 18.629s because their outcomes differ. The first hover study's
13.207s ends in a safe stop rather than task success. Observed model identity
and monetary cost are unavailable.

## Scope and next allocation

The candidates, tooltip templates, neutral point, patch size, guarded L, and
seed991004 save were known during development. The result does not establish
automatic candidate discovery, an unseen target, layout transfer, causal
latency, broad token compression, or human-tempo control.

Retain persistent target rebase as a candidate. The next study should invoke
active hover evidence only when the passive view is uncertain, then test a
held-out toolbar target or a changed candidate layout in a matched comparison.
That comparison must keep independent scoring, freshness, ordinary input
admission, exact failure preservation, and recovery behavior fixed.
