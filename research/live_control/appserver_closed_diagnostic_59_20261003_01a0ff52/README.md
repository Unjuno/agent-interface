# Closed stdout diagnostics can outlive a configured client timeout

The unchanged research CodexAppServerClient closes its stdout reader at EOF, then calls stderr.read() in the request and notification closed-transport error paths. An owned child can close stdout while retaining stderr and stdin. These directed native macOS constructions show both callers still blocked at the actual read after their configured wait deadline. This is a recovery counterexample for the research client, not actual Codex/model operation or a deployed repair.
