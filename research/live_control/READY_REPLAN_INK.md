# Bounded passive readiness removes extra patch refusal, exposes program expiry

passive_pair_v1 collects at most three additional captures in this experiment (API permits1..4). It uses the unchanged sampled target contract between successive samples. A changed patch can trigger another sample; other invalid context ends the attempt. Matching samples return stable evidence with no authority and no semantic-readiness claim. Callback errors propagate. This is a bound on capture count, not a hard wall-clock guarantee; callbacks retain their existing per-request deadlines.

Offline controls use the archived selection transition to reach a matching pair after two new samples, synthetic alternating real image bytes to exhaust three samples, invalid bound refusal before callback, and the actual disabled-target refusal as a regression. A stable new state does not reauthorize a proposal made from the old enabled state. The target contract is unchanged. Controls invoke neither GUI nor model.

A fresh actual replan episode inserts readiness after the model's single-click selection. Two additional observation-only programs produce a matching X-field pair in0.594s. Readiness evidence/current observation is sent to the model before the next edit. The initial deliberate same-focus deselection still refuses the old proposal, but no additional patch refusal occurs after reselection. Model calls drop from five in the prior episode to four here. Final saved SVG is104/50/40/30. This is one separate episode per version, with changed prompt/evidence, cache, model output and timing; no causal/general speedup estimate follows.

Crucially, this is NOT clean program completion. The final edit program expires with four completed steps. Ctrl+S is admitted just before the deadline, and independent SVG confirms its effect; the appended observe step is never started. All input admissions precede their deadlines and held inputs are released. The model requests verification from the latest received observation despite the expired outcome; saved success does not erase that interrupted status. The initial audit rejected the unexpected expired terminal. That failure is retained in audit-initial-failure.json; the revised diagnostic audit explicitly requires and examines the expiry instead of relabeling it completed. No runtime/model rerun was made to obtain a clean result.

Measurements: capture-to-evaluation40.960s versus prior47.110s; four runners12.029/8.730/7.922/6.777s; input45102 tokens (13312 cached),717 output, versus prior52456/889. Readiness increases observation/journal work and adds substantial prompt evidence, so token differences are not pure compression. One fewer model call is observed, but the expiry prevents promotion as a clean improvement. The initial read recovery takes0.911s.

Audit replays152 events,23 exact transported frame/PNG comparisons and47 journal records, checks actual readiness capture triples and matching verdicts, all prompted evidence/model proposals, fresh admission sequence/deadline, exact saved SVG and released inputs. There are two intended Save commands for distinct edits; no lost-command replay. Driver exits0, private sockets removed; its task-success field is supplemented by the diagnostic classification saved-task-success/program-expired. Evidence is results/ready-replan-ink-01; audit_ready_replan_ink_v1.py replays the observed mixed outcome under Linux. The expected single expired terminal assertion deliberately audits this artifact rather than acting as a general success validator.

Decision: keep readiness opt-in and do not weaken pixel matching. Before adoption, fix the mismatch between a first-click freshness contract and the lifetime of a multi-step edit program. The current1s capture-derived deadline can expire during keyboard/save steps, as demonstrated. Keep expiry visible and require post-release observation before further semantic decisions; do not simply call an expired program successful because a file happened to save. Investigate a correctly bounded separation of fresh target activation and subsequent input lifetime, with explicit interruption tests. Human-like live control and broad domain coverage remain unfinished.
