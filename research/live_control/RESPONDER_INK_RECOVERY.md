# Inkscape archived uncertainty screen preserves reconciliation choice

The same domain-neutral screenshot_responder_v1 instructions were tested outside Calc using two archived checkpoints from the actual ink-scape-lost-reply-01 experiment (directory spelling: inkscape-lost-reply-01). That original run sent a real edit/save program and deliberately abandoned its response before receiving bytes; a subsequent command-free read recovered the original execution. This new study makes model proposals only. It does not issue new GUI input, recreate a transport fault, or execute model-selected recovery.

The uncertain checkpoint supplies the pre-send image003 (X50), an explicit send-completed/no-response record, and unknown receipt. The resolved checkpoint supplies received image009 (X88,Y50,W40,H30), original-command echo/admission facts and the actual completed terminal with verified input release. No independent saved-SVG score is supplied to the model. The same task prompt/schema is used within each case for both instruction modes; the evidence changes between cases. The prompt explicitly explains reconciliation and the distinction between verification request and saved success. Thus this is an instruction-following decision screen, not discovery of recovery semantics from an unannotated image.

All four choose the expected distinction; neither mode proposes replay of the uncertain edit. The responder uses3390 fewer input tokens in both cases. There is one sample per case/mode, different cache/output and no latency improvement claim; the resolved responder call is slower. Actual served identity, full context and monetary cost remain unavailable. No general recovery or quality-equivalence claim follows, particularly for partial echoes, contradictory evidence, ring eviction, wrong request identity, stale targets or runtime loss.

The audit validates frozen source and instruction hashes, archival evidence hashes, image/prompt correspondence, raw event hashes/lengths/order labels, single model message/no tool events, successful exits and exact proposal schema/value expectations. It does not independently reconstruct all summarized evidence facts; those are inspectable in the original archived experiment and its separate runtime audit. The assistant viewed both original screenshots before constructing the cases. All outputs, including the slower responder call, are retained in results/responder-ink-recovery-01. Run audit_responder_ink_recovery_v1.py for read-only evidence replay.

Decision: retain the opt-in responder; this removes one narrow concern about losing explicit uncertainty guidance when shortening instructions. The missing integration remains real model-selected read-only reconciliation on a newly running Inkscape session, followed by a current observation and independent saved-artifact verification. Use the existing durable caller to enforce pending identity before allowing new commands. Do not count this archived screen as that live integration or repeat favorable archived cases instead of implementing it. Broader domain coverage and human-tempo are still unproven.
