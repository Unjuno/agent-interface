# Typed successful-servo review card

`servo_review_v1.py` presents a small card only for a narrowly checked successful
single pointer_servo report. It retains program/status, target and observed deltas,
correction count, tracking distance/method, verified release, result image and the
original report hash. Full details remain in the saved source. Independent task
success stays unknown until the saved-output oracle runs; state samples remain
historical and the card grants no input authority.

Checks include the existing command/terminal binding; terminal/release fields;
sampled owner, revision, button mask, focus and lease deadline; observation brackets;
yield/feedback identity and reply deadline; correction residual and acknowledged
continuation; and matching local-goal outcome. Unsupported fields at these checked
locations, negative evidence and non-normal outcomes return the full v4 receipt
with an explicit reason. This is not exhaustive schema validation or authenticity:
some inherited routine and nested context fields are not fully typed. No attention
is not permission or proof of task success.

Sixteen mutations preserve all duplicate report copies and valid underlying
program binding. Unknown top/observation/tracking/terminal fields, metric exception,
lost tracking, owner/revision/button/deadline mismatch, incorrect correction,
outcome status/identity mismatch, wrong goal delta, failed release and a cause on
a completed terminal all fall back to detailed review. A preserved actual keyboard
interruption also falls back. Evidence: `results/servo-review-01/`.

For the historical success, equivalent JSON serialization was 7323 bytes for v4
versus 1385 bytes for the card. These are lossy review summaries of the same saved
report, not lossless compression or model-token measurements. The card drops
event-index paths and detailed tracking/state payloads from immediate display;
they remain accessible through the full source identified by hash.
