# Live model-selected reconciliation succeeds, but spends seconds on a mechanical choice

A fresh Inkscape seed239 session runs the existing shared socket/executor and append-backed durable caller. The fixture scripts selection and one X88/save program. After a real AF_UNIX sendall, it deliberately closes the client connection before receiving bytes and raises a marked exception. This is intentional response abandonment, not an organic outage or a caller-process crash. The journal commits pending request identity before transport and retains the pre-send observation. A new clock attempt is refused before transport while pending; the journal state remains unchanged.

The constrained screenshot responder then receives that actual stale pre-send image and pending evidence. It chooses a command-free read for the exact generated action ID. The harness validates this proposal and performs one bounded read, which reconciles the original echo/admission/completed terminal and yields a current image. A second model call reads X88,Y50,W40,H30 and requests independent verification. Only then does finish invoke the independent saved-SVG evaluator. The result succeeds. Both calls use requested Luna-low, responder instructions and Fast disabled. No new user configuration, model retry, edit resend, automatic input replay or manual model correction occurs.

Scope limits: initial edit is scripted; the model chooses recovery read and verification only. The driver accepts only an exact read proposal while pending and stops on other proposals, so it is not a general recovery planner. Recovery has one read attempt and refuses to invent success if still pending. It does not handle arbitrary partial echoes, ring eviction, runtime death, process restart, wrong-session journals or general failure cleanup. Parent failure terminates the bridge; this is not a production process-tree cleanup guarantee. Typed numeric verification uses equality rather than a general numeric schema. Source files are frozen and this successful episode does not cover those absent cases.

Decision: the missing live connection from model proposal to durable read is now demonstrated on one real second-domain task. It also exposes avoidable waiting: the pending journal permits only reconciliation, yet a model call spends8.747s choosing that read. Next implement an opt-in caller step that performs one bounded command-free read after transport uncertainty, preserving pending state on timeout/conflict and never retrying submit. Compare actual failure-to-useful-feedback time with this measured path, keeping model interpretation of new visual state and independent scoring. This is mechanical uncertainty handling, not a policy to replay or continue GUI actions automatically. Do not add more model-selected-read successes merely to accumulate evidence. Shared domain coverage and human-like live interaction remain unfinished.
