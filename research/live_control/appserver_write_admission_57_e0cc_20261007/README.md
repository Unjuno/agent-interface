# App-server response ownership at write admission

Main could cache an unsolicited future response, return a response while its request was still waiting for the write slot, or replace the first reply with a duplicate. This current-main successor admits each numeric request ID only after acquiring the write slot and preparing serialization and its sent journal record. It accepts the first matching response, preserves equal Number IDs such as `1` and `1.0`, and retires the pending ID and response cache on every request exit. Blocking I/O does not hold the reader condition lock.

H: this software admission boundary rejects replies classified before admission without losing immediate, numeric, or concurrent replies. T: held-write-slot and gated sent-record counterexamples, fake synchronous replies/failures, and 14 actual default-Popen inert-peer cells on frozen baseline/candidate sources. D: candidate rejects pre-admission/future/duplicate poison, retains proper numeric results/errors, and retires requests/readers/children in the tested cells. C: replies buffered before admission but classified later, fake transport ordering, and EOF can confound a broader claim. U: these are ordinary construction regressions, not a preregistered formal allocation or an authentication/delivery guarantee.
