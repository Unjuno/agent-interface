# Sources and limits

- [Linux close(2)](https://man7.org/linux/man-pages/man2/close.2.html), consulted2026-10-03: on Linux, a blocked I/O call can retain its open file description after another thread closes the descriptor. FD reuse makes repeated close unsafe. This is established prior behavior, not a newly invented cancellation mechanism.
- [Python3.12 concurrent.futures](https://docs.python.org/3.12/library/concurrent.futures.html#concurrent.futures.Future.cancel): a running callable cannot be cancelled by Future.cancel; callable completion and executor shutdown are separate boundaries.
- [Python3.12 selectors](https://docs.python.org/3.12/library/selectors.html): DefaultSelector uses the available readiness backend; Unix pipe readiness is not a portable Windows pipe assumption.
- [Linux proc_pid_wchan(5)](https://man7.org/linux/man-pages/man5/proc_pid_wchan.5.html) and [proc_pid_syscall(5)](https://man7.org/linux/man-pages/man5/proc_pid_syscall.5.html): process kernel sleep location/current syscall observations depend on kernel support and permissions. We actually preflight the frozen guest and check the native TID/FD/state together, rather than infer blocking from a producer Event alone. Published formal observations omit buffer addresses/SP/PC.
- Repository prior art [#810](https://github.com/Unjuno/agent-interface/issues/810), [#4397](https://github.com/Unjuno/agent-interface/issues/4397), and [#4124](https://github.com/Unjuno/agent-interface/issues/4124) are separate retained pipe-write/control-channel, SQLite-release and ownership work. #6897 uses explicit event release to study callable exit/rejoin; this experiment supplies a distinct OS blocked-read/FD boundary.
