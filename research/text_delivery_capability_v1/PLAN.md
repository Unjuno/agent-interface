# Text delivery capability model v1 — H/T/D/C/U

**H:** Explicit route capability + side-effect negotiation prevents semantically successful but undeclared destructive text lowering from masquerading as generic text, while still selecting a stronger route when its side effects are allowed and exact semantics are established.

**T:** Pure offline reference selector, evidence-derived X11 profile, deterministic unit tests, and exhaustive enumeration of alternative capability states × every side-effect budget. No GUI/input/model/network. Freeze source before one retained run.

**D:** PASS only if retained evidence cases resolve correctly (transparent ASCII→direct keys; transparent Unicode→no route; declared clipboard-mutating Unicode→clipboard route; global-keymap-only budget→no route), unknown/permission-required/unproven routes never leak through, and exhaustive selection yields zero side-effect/state/exactness violations.

**C:** Preference/risk ordering may be premature; accessibility/native IME routes are hypothetical until platform evidence exists. Side-effect sets may need richer lifetime/reversibility semantics.

**U:** Candidate interface model only. It does not modify the portable contract, prove native OS support, or establish provider/model efficiency.
