# Proof-carrying action admission for untrusted planners — Issue #5311

Issue [#5311](https://github.com/Unjuno/agent-interface/issues/5311) proposes that an untrusted planner attach a compact, checkable certificate to an action plan so a trusted admission gate can validate selected policy claims. The certificate is about admissibility; it cannot establish the application effect or task success, and it cannot replace freshness checks, release obligations, or independent effect scoring.

The retained T0 A01 package is in [the frozen report](../../research/analysis/proof_carrying_action_5311_t0_a01_20261009/README.md) and is preserved in open, non-draft [PR #8836](https://github.com/Unjuno/agent-interface/pull/8836), which has not yet been integrated into current main. Its corrected disposition is `FAIL_COST_GATE_SCOPED`: on eight valid synthetic plans, full reconstruction uses 96 counted inspections and certificate admission uses 136 (41.7% more); both accept 8/8 with identical effect labels, and certificate admission rejects 7/7 directed invalid certificates. The post-run correction found both the candidate counter and saved auditor expectation omitted one strict release-boolean check per action. The frozen raw and code were not changed or rerun. The saved audit's 15-row reconstruction and seven negative controls remain useful; its cost PASS is superseded by the correction.

This is a finite, hand-authored method result, not an impossibility theorem or a security/safety guarantee. Hash binding proves which plan bytes were checked, not that a proof compresses the required policy work. The original hypothesis remains open; a successor would need a separately specified proof rule that soundly reduces trusted checks, with independent accounting and the same effect outcomes. Do not reuse the consumed allocation.
