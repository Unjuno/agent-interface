# Skill-conditioned terminal-event memory — #8886

- **Status:** Unverified robotics-to-GUI transfer proposal; no implementation or result is recorded.
- **Source:** Open [Issue #8886](https://github.com/Unjuno/agent-interface/issues/8886).
- **Idea:** Test whether selecting a small number of provenance-bound terminal events for the currently declared subtask helps continue correctly when different histories produce visually identical screens, at the same context budget as current-only, chronological-history, and generic-event-memory baselines.
- **Relation to prior work:** #7161 owns generic provenance-linked action/effect event records and state-only/chronological comparisons; #689 owns interaction-to-next-observation feedback; #5368 models action-conditioned hidden-state hypotheses; #28/#746/#751 cover history, temporal views, and skill retrieval. #8886's proposed residual is active-skill selection of prior terminal evidence under fixed context cost, not new memory authority.
- **Proposed minimum test:** First use a deterministic finite GUI-like state machine with aliased screens, verified/reverted/unknown effects, stale generations, and held-out histories. Freeze event schema, retrieval `K`, token accounting, and an independent state/effect oracle. Reject dispatch or prediction as verified completion. Any later model-facing fixture requires its own allocation and matched all-attempt comparison.
- **Decision boundary:** A method pass requires exact history reconstruction, source-bound eligible retrieval, and rejection of stale, unknown, reverted, or mutated evidence. Transfer requires equal-budget improvement on aliased-history cases without false completion/wrong-step effects, and no material harm on current-state-sufficient controls.
- **Limits:** Robotics results do not transfer by citation. T0 cannot establish model or live GUI benefit; no memory record can refresh target/freshness or grant input authority. If #7161/#689 owners adopt the same retrieval contrast, consolidate there.
