# Shared vocabulary and evaluation intake — provisional, 2026-09-13

This records the current mapping for Issues #11 and #12. It is not a frozen ABI or
a claim that proposed fields/state machines are implemented. Preserve frozen traces
and backend-independent meanings while deciding which contracts to stabilize.

| Concept | Meaning to preserve | Current evidence / gap |
|---|---|---|
| Observation | Historical evidence with source/provenance; never permission | Exact frames and historical owner samples exist; atomic freshness does not |
| Intent | Required/forbidden effect independent of route | Task meaning mostly in harnesses; no shared Intent object |
| Authority | Original runtime grant, revocable, never renewed by feedback | Owner/lease traces cover expiry, cancel, release, duplicate continuation |

| Evidence | Implementation, self-use, frozen data and qualification are independent | Many scripted/self-use snapshots; current servo is not qualified |

An accepted program is not a planner decision or model/tool boundary. Clock endpoints
must name what was measured. Python research timing does not specify native runtime
performance, and neither local speed nor a successful familiar task establishes
cross-domain usefulness.

For future task contracts, declare initial constraints, required/forbidden effects,
collateral scope, budgets, completion and scorer version before execution. Separate
setup and independent scoring from controller-visible information. An absent field
is a gap, not an implicitly passed requirement. Validate scorers with missing-effect,
wrong-target/owner, collateral and unsaved-state negatives where relevant.

Classify historical experiments honestly: reused traces and tuned layouts are
DEVELOPMENT_KNOWN; new concrete positions within a known family are FRESH_VARIANT.
HELD_OUT requires pre-frozen variants not used for tuning. Current distractor/overlay
regressions are development cases; one shifted placement is not a held-out suite.

Keep Desktop, Inkscape precision, DOOM continuous motor and OpenTTD placement as
orthogonal evaluation layers. Mindustry/Luanti remain subject to feasibility/oracle
gates. Capability-by-domain qualification must identify exercised axes; do not sum
these into a king-benchmark score. No existing pilot is retroactively promoted by
this document. Next formalize a small task/scorer contract and capability matrix
using the existing failure corpus before broad benchmark claims or ABI freeze.
