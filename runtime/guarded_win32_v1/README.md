# Caller-owned guarded Win32 move prototype

Input neutrality checks tracked keys, buttons and pending Unicode UP delivery. Unicode bookkeeping follows adopted main #7253: accepted DOWN remains pending until accepted UP, with one compensation attempt per pending unit per explicit release. Failed Unicode compensation retains the unit while ordinary release continues. Pending delivery refuses preparation and guarded movement; after a completed move it keeps semantic effect unknown and requires explicit recovery. Delivery acknowledgement does not establish physical neutrality or application success. Recovery never restores a consumed movement permission.

This opt-in module prepares a full-client image reference and dispatches one pointer move through ordinary core admission and Win32 session cleanup. It reuses the existing `runtime.guarded_x11_v1` image-history and reference modules; importing it does not load Xlib or open a native session. Pillow is required. It depends on the accompanying private Win32 backend/session changes and is not a default runtime route.

The caller supplies an exclusively owned backend, target and artifact directory to `FreshWin32Reference`. Observe the full client `[0,0,width,height]`, then mint an alias with a textured pixel box. Geometry, HWND, foreground focus, and a digest of the owner PID plus process creation time are pinned. Failure to query process identity fails observation closed; the HWND-to-PID mapping is sampled again after the process-time query. The generation digest is checked by the existing bound-execution guard before input. This narrows stale HWND reuse but is not an atomic identity-to-`SendInput` guarantee. Partial-client reference creation and window handoff are unsupported. Aliases currently expire after 1000ms; there is no automatic remint or renewal.

Construct `MoveBridge(observer, authorize, cancelled)`. `authorize(intent)` is an explicit trusted caller policy: it receives scope, target, operation, alias, offset and resolved point, and returns exactly `lease_id` and `expires_at_ns`, or declines. This callback is not an authentication boundary. `cancelled()` must return exactly `False` to permit movement. Reference eligibility supplies no input authority.

`prepare(alias, offset)` captures fresh pixels and obtains ordinary admission. `prepare_observed(alias, offset, source_sequence=...)` is the compiled-core adapter seam: it uses that caller's exact retained frame and sequence, checks current process/HWND/focus/geometry binding, and avoids silently changing the caller's source sequence. A composed `compiled_gui.run` test exercises this seam with inert Win32 API doubles, including generation change after admission; it is local adapter evidence, not a public MCP Win32 route or native-input result. `execute(authorization)` still consumes the token before live validation, recaptures pixels, rechecks the binding before input, and dispatches one move followed by verified release. New preparation invalidates earlier tokens. Refused and uncertain operations cannot reuse tokens. Focus changes are prohibited in bound execution; this module does not activate another window.

`recover_input()` uses the same operation lock, invalidates pending tokens and attempts input neutralization once through the existing session. Failed or unverified release retains quarantine. Verified recovery never reports task success or replays input. Direct access to the backend, observer or session bypasses the bridge lock and must not run concurrently.

The ordinary tests control native GDI, target, move and release. Their completed result proves the scoped inert execution and cleanup path, not an application effect. Physical held inputs outside the tracked ledger are not fully checked. Guard capture and release calls are not forcibly preemptible; state can change inside native emission after the last check. Metadata/artifacts grow with session length even though decoded images are bounded. Successful test flow currently captures four times; no latency, model-call or resource saving is established.

There is still no public MCP Win32 session route: `mcp_server.create_server()` only configures the existing X11 guarded caller. This `MoveBridge` is a separate private Python path. The additive `OperationOwner` is currently only a parent-side custody gate: it retains an injected producer handle, refuses stale identity/generation receipts, and gates recovery claims on confirmed exit. It does not start or terminate workers, perform recovery, emit input, or connect to the bridge/caller. Its inert spawned-child test is process-lifecycle evidence only, not bounded release evidence. Remaining qualification includes spawn-safe worker supervision, public standard-caller integration, bounded recovery under blocked I/O, independently checked task effect, and native platform behavior. No automatic input or default-route adoption is authorized by importing these prototypes.

Preflight checks binding, deadlines, cancellation and recovery without taking another image. Exact pixel comparison remains before ordinary dispatch and immediately before the pointer operation. Native capture-count reduction is not a measured latency/CPU improvement.
