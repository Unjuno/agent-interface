# Primary input helper: retained live self-use pair

The primary agent personally used the committed `primaryCaller.input(alias,
offset, interaction, tail)` helper on a private Linux/X11 six-task fixture.
Both guarded and direct routes recorded exactly one correct submission for each
of six tasks. This supports this helper's usability on this case; candidate
adoption remains **HOLD**. It does not establish human tempo, general product
completion, token savings or causal speedup.

Trial source: `e032ff186e784b7c5486dd9d48eac7b53390eb5a`; seed: `1001060`.
The twelve PLAN input hashes were frozen before launch and remain unchanged.
Guarded ran first; direct ran second on a separate allocation. The same model
handled both, without a context reset. These are known serial form tasks with
layouts A/A/A/B/B/B, not held-out tasks or a randomized crossover.

| Exact-once correct tasks | 6/6 | 6/6 |
| Returned public calls | 74 | 29 |
| Ordinary input programs | 24 | 12 |

Program granularity differs; guarded also performs minting, validation and three
frozen refusal controls. Per-program medians and overall elapsed spans are not
comparable causal performance estimates. Host gaps include orchestration and
caller activity, including a turn boundary in the direct arm. First useful
model feedback, semantic completion latency, isolated model wait, actual
provider tokens/cost and a human comparison remain unmeasured.

All original returned images have byte-identical saved PNGs and bound review
receipts; reviews precede the next ordinary input. Every ordinary input reports
verified neutral release, as does public close. The three expected controls
refuse without input, and the configured window review advances binding revision
0 to 1. Both transport exit records are zero and policy STOP is null.

Two guarded previews were unreadable to the primary agent. Call 38 was reviewed
through the exact retained PNG. For call 39, the default local image preview was
also unreadable; viewing the same PNG with original detail made it visible.
Three extra local image reads are therefore part of this trial's recovery cost.
`presentation-fallbacks.jsonl` and the original review reasons retain this
attribution. This does not prove why the previews were black, a capture defect,
or a complete presentation PASS.

Fixture child cleanup values are **[0, 1, 0]** in both arms, not all zero.
The fixture shutdown implementation explicitly terminates owned process groups;
the second process is Openbox. Its stderr was discarded by the existing fixture,
so the cause of exit 1 is not established. The auditor checks terminal cleanup
and preserves these values rather than reclassifying them as successful exits.

The initial post-run audit failed twice: first on an incorrect all-zero child
cleanup assumption, then because the committed host timing reader did not
recognize `text_acknowledgment_recorded`. The runtime reader is now extended to
bind text-only acknowledgment receipts to presented replies, without treating
them as image reviews or semantic comprehension. A positive test failed on the
old reader with `unknown event kind`; corrupt receipt, duplicate acknowledgment,
unpresented reply and image-content tests cover refusal. The reader included
here is this post-run correction, **not** the frozen trial executable. No live
trial was replayed after the correction.

Local native contract checks: protocol 340 tests and harness 149 tests pass.
The retained pair audits pass in ordinary Python and `python -O`. False six-task
score controls are rejected semantically in both modes; altered release replies
are rejected by reply identity. The latter is not a rehashed semantic control.
The archive manifest covers 866 files; all member hashes were reread from tar.
The archived CONTINUATION record is a historical mid-run checkpoint; terminal
records, final evaluations and PAIR-AUDIT are the final authority.
