# Current-capture RGB handoff for guarded observation

Integration decision: use the RGB image already produced by the existing X11 PNG writer for the same guarded observation, after verifying the stored PNG digest and raw-capture hash link. This removes the bridge's PNG decode/convert round trip. Fresh XGetImage, PNG compression/storage, binding checks, every guard stage, deadline checks and input release remain. The interface sends the same saved PNG format to the primary. No sensor, new model or older-frame reuse is added.

## Why this boundary

The preceding [primary six-task use](../atomic-primary-six-task-01/README.md) completed both routes but retained 70 backend observations on persistent versus 25 on direct. In that persistent allocation, recorded artifact-verified-to-decoded intervals summed to 405.817 ms, with the bridge reading and decoding every newly written PNG. This is a descriptive wrapper-stage sum, not CPU time or a causal task-latency estimate. Inspection identified a concrete duplicated representation: `CaptureArtifacts.write` already calls the supported X11 raw-to-RGB conversion to encode the PNG, and the bridge immediately decoded it back to RGB for its target history.

Existing [artifact replay research](../../../research/observation_tiles/IMAGE_ARTIFACT.md) and [#4401](https://github.com/Unjuno/agent-interface/issues/4401) describe exact pixel preservation and PNG preparation/delivery tradeoffs. #4401's first result is HOLD_NO_DELIVERY_RANKING_DISCRIMINATOR, so this increment does not change compression defaults or promote a latency claim from that study. [#4057](https://github.com/Unjuno/agent-interface/issues/4057) also warns that existence-only reuse is not validation of maintained artifacts. This implementation retains the current PNG byte-hash check and does not adopt that file cache. This is a tested adapter of the existing production conversion, not an unchanged promotion of a new research policy.

## Behavior and limits

`CaptureArtifacts(..., retain_rgb=True)` privately holds one completed artifact identity and the RGB image that produced it. Ordinary callers default to false. `take_rgb(artifact)` consumes the handoff once, comparing the full saved identity; mismatches refuse and clear it. Every new capture clears pending RGB before reading X11, and every writer invocation clears it before validation/encoding. Failed capture/packaging cannot authorize an older-image handoff. The bridge verifies the current PNG bytes and raw hash link before taking RGB; a file or raw-link mismatch never enters history. The producer's private image becomes the bridge's history image; no RGB object appears in a public JSON report.

Observation records add `image_source=exact_capture_rgb_handoff`. The existing `timing_ns.decoded` field remains for compatibility and now brackets the completed RGB handoff, not a new PNG decoder invocation. Do not compare differently implemented bracket names as isolated CPU/inference performance. Handoff storage is one pending reference; the existing bounded observation history continues unchanged.
