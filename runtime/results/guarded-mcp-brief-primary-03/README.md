## Failures and recovery retained

At attempt 7 the assistant incorrectly supplied `pointer:false`, an unknown argument ignored by the SDK. The default click executed on the browser profile icon before URL entry. The URL was visually correct, but the icon's changed pixels caused attempt 8 to refuse before dispatch. At attempt 9 the assistant grounded a new toolbar reference and used the correct `interaction:"keyboard"` thereafter. This is an unexpected recovery cost, not part of the planned layout-change control. Do not remove it from performance accounting.

At task 4 the planned old field alias was refused before dispatch (attempt 19), with full guard detail despite requested brief output. Two new references were grounded from that returned layout B image. All remaining tasks completed. The ignored-argument discovery led to a subsequent public transport fix rejecting unknown top-level arguments. That fix is NOT the runtime tested in this archive; its unit and actual stdio validation are separate evidence.

For the same 24 input reports, full JSON metadata totals 130,035 UTF-8 bytes, versus 108,586 bytes in the actual brief-request responses (16.49% less). Encoding uses Python json.dumps defaults, excludes image blocks and the transport envelope, includes the two full refusals and brief retrieval instructions. This is a representation comparison, not a matched second live baseline.

Host callbacks passed text and image blocks through unchanged in this trial. Prior trials used an additional text projection; model-side latency/token comparisons across them would be confounded. Actual model input tokens, cost, time to useful feedback, semantic completion time, and human-comparable speed are not measured. Host events retain transport and callback boundaries only. No performance or token-saving adoption claim follows from byte counts.
